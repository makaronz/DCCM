# 4.4 Converting to Standardized Color Spaces

## Theory: Gamut Mapping and Tone Mapping

### Gamut Mapping Fundamentals

**Purpose:** Convert colors from source gamut (potentially larger) to destination gamut (potentially smaller)

**Gamut Mapping Strategies:**

```
1. Hard Clipping:
   - Simple: clip to destination gamut boundary
   - Pros: Predictable, preserves in-gamut colors
   - Cons: Loses saturation/detail for out-of-gamut colors
   - Formula: C_out = clip(C_in, gamut_boundary)

2. Soft Clipping:
   - Gradual rolloff near gamut boundary
   - Pros: More graceful than hard clipping
   - Cons: Can shift hue near edges
   - Formula: C_out = C_in × (1 - (C_in / C_max)^n)

3. Gamut Mapping:
   - Preserve perceptual attributes (hue, saturation)
   - More complex than clipping
   - Multiple algorithms (CUSP, ITP, etc.)
```

**CUSP (Cusp Uniform Saturation Preservation):**

```
CUSP Algorithm Overview:

1. Convert to LCH (Lightness, Chroma, Hue):
   L* = perceived lightness
   C* = perceived chroma (saturation)
   h° = hue angle

2. Scale chroma to fit destination gamut:
   Find scaling factor α such that:
   LCH_in → α × LCH_in fits within destination gamut
   Preserve hue angle h°
   Adjust lightness L* if needed

3. Convert back to RGB:
   (L*, α×C*, h°) → RGB_dest

Result:
- Preserves hue relationships
- Maintains perceptual attributes
- Smooth roll-off at gamut boundary
```

### Tone Mapping for HDR to SDR

**Tone Mapping Purpose:** Compress high dynamic range scene to standard dynamic range display

**Tone Mapping Operators (TMOs):**

```
1. Reinhard Tone Mapping:

def reinhard_tmo(scene_linear, exposure):
    # Normalize by exposure
    color = scene_linear / exposure

    # Apply tone mapping
    mapped = color / (1 + color)

    # Scale to display range
    display = mapped × exposure / (1 + exposure) × display_peak

    return display

Properties:
- Global operator (same exposure for all pixels)
- Simple formula, computationally fast
- Can lose highlight detail
- May create "flat" appearance

2. Filmic Tone Mapping (Hable):

def filmic_tmo(scene_linear):
    # Separate luminance and chromaticity
    Y = luminance(scene_linear)
    chroma = scene_linear / Y  # Color ratios

    # Apply filmic curve to luminance
    # Linear shoulder + knee + toe
    Y_mapped = filmic_curve(Y)

    # Re-apply chromaticity
    mapped = Y_mapped × chroma

    return mapped

Properties:
- Mimics film response (toe, knee, shoulder)
- Better highlight detail preservation
- More complex computation
- Industry standard for HDR→SDR
```

### Chromatic Adaptation

**Purpose:** Adjust color appearance for different white points (D65 to DCI, etc.)

**Bradford Transform (Simplified):**

```
1. Convert source RGB to LMS cone responses:
[L]   [x_r x_g x_b]   [R_s]
[M] = [y_r y_g y_b] × [G_s]
[S]   [z_r z_g z_b]   [B_s]

2. Apply Bradford adaptation matrix D:
[D_L]         [     d      -d/√2   0]
[D_M] = D × [S] = [  d/√2   d       0]
[D_S]         [     0       0     1]

Where d = adaptation factor based on illuminant change

3. Convert adapted LMS back to destination RGB:
[R_d]   [x_r' y_r' z_r']^-1   [D_L]
[G_d] = [x_g' y_g' z_g'^-1] × [D_M]
[B_d]   [x_b' y_b' z_b'^-1]   [D_S]

Where x',y',z' are destination primary chromaticities
```

## Practice: Rec.709/2020 Conversions and HDR Mapping

### Rec.709 Conversion Workflow

**Typical Pipeline: Camera Log to Rec.709**

```
Step 1: Identify Source
- ARRI: LogC4 + AWG4
- Sony: S-Log3 + SGamut3.Cine
- RED: Log3G10 + RWG

Step 2: Choose Conversion Method

Method A: Manufacturer LUT (Fast, Accurate)
1. Download camera manufacturer Rec.709 LUT
2. Apply LUT in grading software
3. Verify with test chart

Method B: Color Space Transform Node (Flexible)
1. In DaVinci Resolve: Color Space Transform node
2. Input: Camera Log + Gamut
3. Output: Rec.709 Gamma 2.4
4. Gamma 2.4: Apply OETF

Method C: ACES Pipeline (Most Flexible)
1. Input: Camera Log → IDT → ACES2065-1
2. Grade in ACEScg scene-linear
3. Output: ACES2065-1 → RRT+ODT for Rec.709

Step 3: Validation
- Check 18% gray placement (40-45% in Rec.709)
- Verify skin tones look natural
- Test color chart for accuracy
- Check for clipping (waveform 0-100 IRE)
```

**P3 Mastering Workflow:**

```
Creating P3 Master from Camera Original:

1. Setup Timeline:
   - Project color space: P3-D65
   - Gamma: 2.6 (DCI) or 2.4 (P3-D65)
   - Bit depth: 12-bit

2. Grade in P3:
   - Grade directly in P3 space
   - Or grade in ACES, output to P3-D65

3. Validate P3 Output:
   - Check P3 coverage (wider than Rec.709)
   - Verify saturation in greens/cyans
   - Test with P3-specific test chart

4. Create Rec.709 Trim:
   - Use Color Space Transform node
   - Input: P3-D65 Gamma 2.6
   - Output: Rec.709 Gamma 2.4

5. Test Both Versions:
   - P3: Cinema projection quality
   - Rec.709: Broadcast/web quality
```

### HDR to SDR Mapping

**HDR10 (Rec.2020 + PQ) to Rec.709 Workflow:**

```
Input: HDR10 footage (Rec.2020 gamut, PQ transfer function)

Challenge 1: Gamut Reduction
- Rec.2020 significantly wider than Rec.709
- Must map while preserving intent

Strategy:
- Use CUSP or ITP (hybrid log-gamma)
- Maintain hue angles
- Scale chroma to fit Rec.709
- Apply soft clipping at boundary

Challenge 2: Tone Mapping
- HDR: 0-10,000 nits range
- SDR: 0-100 nits range

Strategy:
- Filmic tone mapping (not Reinhard)
- Preserve highlight detail
- Maintain contrast ratio
- Avoid "washed out" appearance

Implementation:
Method 1: Dolby Vision Tools
- Official Dolby Vision mapper
- Optimized for Netflix spec
- Good but requires license

Method 2: Open Source Tools
- RGB_Tonemap (GitHub)
- HDRTools plugin
- Custom tone curve in Resolve

Method 3: Manual Grade
- Create custom grade in Resolve
- Use power windows for selective adjustments
- More control but time-consuming

Validation:
- Compare HDR and SDR versions side-by-side
- Check for clipped highlights (should roll off)
- Verify shadow detail preserved
- Test on challenging scenes (fireworks, neon, etc.)
```

**HLG HDR Workflow:**

```
HLG Characteristics:
- Relative luminance (no absolute nit values)
- Backward compatible with SDR
- Lower dynamic range than PQ (0-1000 nits typical)

Workflow:
Camera (HLG) → Grade (HLG) → Display (HLG compatible)

No tone mapping required if:
- Target display supports HLG
- Same peak luminance capability
- Mastering and display use same format

For HLG → Rec.709:
1. Tone map 1000 nits → 100 nits
2. Gamut map Rec.2020 → Rec.709
3. Convert HLG to Rec.709 gamma 2.4

Key Consideration:
- HLG uses system gamma, not absolute
- Different approach than PQ mapping
- Often simpler than PQ workflow
```

### P3 Mastering for Cinema

**Digital Cinema Package (DCP) Creation:**

```
1. Color Space Selection:
   - DCI-P3 (x=0.314, y=0.351 white point)
   - Gamma 2.6 (DCI spec)
   - X'Y'Z' color encoding

2. Mastering Process:
   - Grade in P3-D65 or DCI-P3
   - Validate for cinema projection
   - Create DCP with proper metadata

3. Quality Control:
   - Check for out-of-gamut colors
   - Verify black level (DCI has specific black)
   - Test on cinema projector if possible

4. Trim Creation:
   - Create Rec.709 version from P3 master
   - Separate mastering pass
   - Test broadcast/web delivery

Common Issues:
- Cinema projectors vary in calibration
- Need on-site calibration
- Color timing adjustments may be needed
- Archive P3 master for future re-mastering
```

## Failure Modes: Gamut Clipping and Hue Shifts

### Gamut Clipping

**Problem:** Out-of-gamut colors lost in conversion

**Symptoms:**
- Saturated colors appear dull/gray
- Color detail lost in specific regions
- "Muddy" appearance

**Example:**

```
Scenario: Rec.2020 → Rec.709 conversion

Rec.2020 gamut includes:
- Extremely saturated greens (cyans, neon colors)
- Deep reds/oranges not in Rec.709
- Some purples outside Rec.709 triangle

Hard Clipping (Bad):
- All out-of-gamut colors → closest Rec.709 edge
- Severe saturation loss
- Hue may shift at boundary
- Example: Neon green becomes dull green

Soft Clipping (Better):
- Gradual rolloff approaching boundary
- Preserve more saturation
- Smoother transitions
- Example: Neon green becomes saturated green

CUSP Gamut Mapping (Best):
- Preserves hue angles
- Maximizes saturation within constraints
- Perceptually uniform
- Example: Neon green becomes slightly less green but still vivid
```

**Detection:**

```
Visual Check:
1. Look for unusually dull colors
2. Check saturated regions (signs, neon, costumes)
3. Compare to original if available

Quantitative Check:
1. Measure chroma (C*) in CIELAB
2. Identify colors with C* > 60 (very saturated)
3. Check if these regions look desaturated

Software Tools:
- DaVinci vectorscope (6x vectorscope)
- Resolve: Scopes > Gamut check
- Nuke: ColorSpace node analysis

Fix:
1. Use proper gamut mapping (CUSP, ITP)
2. Avoid hard clipping
3. Test with extreme colors before delivery
```

### Hue Shifts

**Problem:** Colors rotate around hue circle during conversion

**Symptoms:**
- Skin tones wrong color (magenta, green)
- Blue sky becomes purple
- Red traffic lights appear orange

**Causes:**

```
1. Wrong Chromatic Adaptation Transform:
   Source: D65 illuminant (Rec.709)
   Dest: DCI white (DCI-P3)
   Wrong CAT: Color shift

2. Primary Chromaticity Errors:
   Using wrong source primaries in matrix transform
   Result: Hue shift for all colors

3. Non-Linear Color Space Issues:
   Applying transforms in wrong order
   Example: Gamma before gamut conversion

Example Math:

Wrong:
Rec.709 → Apply Gamma 2.4 → Convert to P3 primaries

Correct:
Rec.709 → Convert to linear → Convert to P3 primaries → Apply gamma
```

**Quantification:**

```
Hue Shift Measurement:

Δh° = arctan2(b', a') - arctan2(b, a)

Where (a, b) and (a', b') are CIELAB a*, b* coordinates

Thresholds:
- Δh < 2°: Imperceptible
- Δh 2-5°: Noticeable by trained eye
- Δh > 5°: Obvious to anyone
- Δh > 10°: Severe error (skin tones critical)

Detection:
1. Measure hue angle of known color
2. Compare before/after conversion
3. Check if unexpected shift occurred

Fix:
1. Verify primary chromaticities matrix
2. Use correct chromatic adaptation
3. Test with skin tone patches
4. Validate with manufacturer LUTs as reference
```

### Saturation Errors

**Problem:** Overall color too muted or oversaturated

**Causes:**

```
1. Wrong Gamma Curve:
   Applying wrong OETF for target display
   Result: Incorrect saturation

2. Color Space Mismatch:
   Interpreting Rec.709 as Rec.2020
   Result: Colors appear dull (Rec.709 smaller gamut)

3. Show LUT Interference:
   Creative LUT designed for different color space
   Result: Unintended saturation changes
```

**Measurement:**

```
Saturation Metrics:

CIELAB Chroma (C*):
C* = sqrt(a*^2 + b*^2)

Saturation Difference:
ΔC* = C*_converted - C*_original

Thresholds:
- ΔC* < -5: Significant loss of saturation (washed out)
- ΔC* +5 to +10: Natural increase (acceptable artistic choice)
- ΔC* > +15: Oversaturation (colors appear artificial)

Detection:
1. Measure skin tone patches
2. Compare to reference
3. Check if overall saturation matches intent

Fix:
1. Verify gamma curve application
2. Check color space interpretation
3. Remove/show show LUT as needed
4. Use CUST or similar if saturation adjustment needed
```

### Dynamic Range Issues

**Problem:** HDR content not properly mapped to SDR

**Symptoms:**

```
Scenario 1: Highlights blown out
HDR: Sky detail visible at 1000 nits
SDR: Sky clipped at 100 nits
Cause: Insufficient tone mapping

Scenario 2: Crushed shadows
HDR: Shadow detail visible
SDR: Shadows black/crushed
Cause: Aggressive tone mapping curve

Scenario 3: Flat contrast
HDR: High contrast maintained
SDR: Low contrast, washed out
Cause: Wrong tone mapping operator
```

**Testing Strategy:**

```
1. Create test patterns:
   - High dynamic range (1000:1)
   - Skin tones at various exposures
   - Gradient test (black to clipped)

2. Compare HDR → SDR:
   - Check highlight rolloff
   - Verify shadow detail
   - Test skin tone reproduction

3. Measure quality:
   - PSNR, SSIM metrics
   - ΔE for color accuracy
   - Subjective evaluation by colorist

4. Iterate on tone mapping:
   - Adjust knee point
   - Modify shoulder rolloff
   - Test different operators
```

## Mini Glossary: Color Space Conversion Terms

**Gamut Mapping:** Process of converting colors from source gamut (potentially larger) to destination gamut (potentially smaller) while preserving perceptual attributes.

**Tone Mapping:** Dynamic range compression technique mapping scene-referred HDR to display-referred SDR or HDR output, preserving detail where possible.

**CUSP (Cusp Uniform Saturation Preservation):** Gamut mapping algorithm preserving hue angles while scaling chroma to fit destination gamut, widely used in professional applications.

**ITP (Image Temporal Mapping):** Hybrid gamut mapping combining multiple strategies (hue-linear and saturation-based), used in some HDR implementations.

**Rec.709:** ITU-R BT.709 standard HDTV color space with Rec.709 primaries and BT.1886 gamma 2.4, most common delivery format for broadcast and web.

**Rec.2020:** ITU-R BT.2020 Ultra-HD color space with very wide gamut, used for HDR and UHDTV delivery.

**DCI-P3:** Digital Cinema Initiatives P3 color space with wider gamut than Rec.709, used for theatrical projection.

**P3-D65:** Apple display color space based on DCI-P3 but with D65 white point instead of DCI white, used for Apple devices.

**Display P3:** Same as P3-D65, Apple's terminology for P3 with D65 white point.

**Gamut:** 3D volume or 2D area of reproducible colors within specific color space or display device.

**White Point:** Chromaticity coordinates of reference white (D65 for Rec.709, DCI for P3), defines color balance.

**D65:** Standard illuminant representing average daylight (6504K color temperature), white point for Rec.709 and sRGB.

**DCI White:** Digital Cinema Initiatives white point (x=0.314, y=0.351), slightly greener than D65.

**Primary Chromaticities:** CIE 1931 x,y coordinates defining red, green, and blue primary locations in 2D chromaticity diagram.

**Hue:** Attribute of color perception described as red, orange, yellow, green, blue, purple, magenta, corresponds to angle in CIELAB.

**Saturation:** Intensity of color, distance from neutral axis in color space, measured as chroma (C*) in CIELAB.

**Chroma:** Magnitude of color saturation in CIELAB space, distance from neutral axis in a*b* plane.

**Chromaticity:** Color quality independent of luminance, typically defined by CIE 1931 x,y coordinates.

**LMS Color Space:** Color space based on human cone responses (Long, Medium, Short wavelengths), used in chromatic adaptation transforms.

**CAT (Chromatic Adaptation Transform):** Mathematical model predicting appearance of colors under different illuminants (Bradford, CAT02, Von Kries).

**Bradford Transform:** Chromatic adaptation transform used in early color management systems, simpler but less accurate than CAT02.

**CAT02:** Chromatic adaptation transform used in CIECAM02 and ACES, more accurate than Bradford for most applications.

**Von Kries Adaptation:** Model of chromatic adaptation based on gain control in LMS cone responses, basis for many CAT transforms.

**CIECAM02:** Color appearance model predicting perceived color attributes (lightness, chroma, hue) under different viewing conditions, foundation for many appearance transforms.

**IPT Color Space:** Color space designed for perceptual uniformity, better correlates with human perception than CIELAB for wide gamut imagery.

**Jzazbz:** Perceptually uniform color space optimized for HDR and WCG (Wide Color Gamut) applications, developed by Dolby.

**ICtCp:** Constant luminance color representation used in HDR signal processing, separates luminance (I) from chrominance (Ct, Cp) components.

**YCbCr:** Color space separating luminance (Y) from chrominance (Cb, Cr color difference signals), basis for video compression.

**YUV:** Analog version of YCbCr used in analog video (PAL, NTSC), term often misused for digital YCbCr.

**YCoCg:** Alternative color space with Co (orange) and Cg (green) chrominance, used in some image compression algorithms.

**Subsampling:** Reducing chrominance resolution relative to luminance (4:2:0, 4:2:2, 4:4:4), exploits human eye's lower sensitivity to color detail.

**4:2:0:** Chroma subsampling with full luma resolution, half horizontal and vertical chroma resolution, used in Blu-ray and most streaming.

**4:2:2:** Chroma subsampling with full luma resolution, half horizontal chroma resolution only, used in professional production formats.

**4:4:4:** No chroma subsampling, full resolution for luma and chroma, required for VFX work and color grading.

**RGB:** Red, Green, Blue color components, additive color model for displays and digital imaging.

**CMYK:** Cyan, Magenta, Yellow, Black (Key) color components, subtractive color model for print.

**Color Depth:** Number of bits per color channel (8-bit, 10-bit, 12-bit, 16-bit float), determines number of possible colors.

**Bit Depth:** Total bits per pixel (24-bit for 8-bit RGB, 30-bit for 10-bit RGB), sum of all channel bit depths.

**Codec:** COder/DECoder compressing and decompressing video data (ProRes, DNxHD, H.264, HEVC, AV1).

**Container:** File format holding encoded video, audio, and metadata (MOV, MXF, MP4).

**Metadata:** Sidecar information describing clip properties (resolution, frame rate, color space, exposure).

**EXIF:** Exchangeable Image File format metadata from digital cameras (ISO, shutter, aperture, white balance).

**XMP:** Extensible Metadata Platform, XML-based metadata standard for embedded metadata in files.

**IPTC:** International Press Telecommunications Council metadata standard for news/photos (caption, keywords, copyright).

**ANCILLARY Data:** Metadata embedded in video signal (VANC, HANC) including timecode, closed captions, SCTE triggers.

**VITC (Vertical Interval Timecode):** Timecode embedded in vertical blanking interval of analog video signal.

**LTC (Linear Timecode):** Timecode recorded on linear audio track of tape, readable during high-speed shuttling.

**Burn-In:** Permanently applying text, timecode, or graphics to video, destructive (cannot be removed).

**Soft Subtitles:** Subtitles delivered as separate text/data track, renderable by player, can be turned on/off.

**Hard Subtitles:** Subtitles burned into video image, cannot be turned off or translated.

**Delivery Format:** Final encoded program meeting broadcaster or platform specifications (codec, color space, loudness, etc.).

**Master:** Highest quality version of program, typically camera originals or uncompressed mezzanine, used for creating deliveries.

**Mezzanine:** Intermediate codec quality near-original but more manageable than uncompressed (ProRes 4444, DNxHR 444, Apple ProRes 4444 XQ).

**Transcode:** Convert from one codec/format to another, typically introducing quality loss.

**Generation Loss:** Quality degradation from multiple encode/decode cycles or transcodes.

**Visually Lossless:** Compression introducing artifacts below threshold of human perception under normal viewing conditions.

**Quality Control (QC):** Systematic review of program for technical compliance and creative standards.

**Technical QC:** Review focusing on technical specifications (color space, levels, audio specs, errors).

**Compliance:** Meeting broadcaster or platform technical requirements (color space, closed captions, loudness).

**Loudness:** Perceived volume of audio, measured in LUFS (Loudness Units Full Scale), specifications vary by platform.

**LKFS:** Loudness K-weighted Full Scale, synonym for LUFS, unit of loudness normalized to full scale digital.

**True Peak:** Maximum absolute level of audio signal after reconstruction, important for preventing clipping.

**Integrated Loudness:** Average loudness over entire program, target -23 to -16 LUFS depending on platform.

**Short-term Loudness:** Average loudness over 3-second window, used for dynamic range measurement.

**Momentary Loudness:** Average loudness over 400ms window, used for monitoring peak loudness.

**LRA (Loudness Range):** Difference between loud and quiet portions, typical values 4-18 LU for broadcast.

**Dolby Vision:** Proprietary HDR format from Dolby with dynamic metadata for optimized HDR→SDR conversion, used by Netflix and other streaming platforms.

**HDR10:** Open HDR format using Rec.2020 gamut and PQ transfer function, no dynamic metadata.

**HLG:** Hybrid Log-Gamma HDR format using relative luminance scaling, backward compatible with SDR, simpler than PQ.

**SDR:** Standard Dynamic Range, traditional imagery with ~6 stops DR, Rec.709 gamut, 100 nits peak brightness.

**UHD (Ultra High Definition):** Umbrella term for 4K/8K delivery, often implies HDR and WCG (Wide Color Gamut).

**WCG (Wide Color Gamut):** Color gamut significantly larger than Rec.709, includes P3 and Rec.2020.

**Nit (cd/m²):** Candela per square meter, unit of luminance used for display brightness specifications.

**Tone Mapping Operator (TMO):** Algorithm or function mapping HDR scene-referred imagery to display-referred output (Reinhard, filmic, etc.).

**Knee Point:** Luminance value where highlight rolloff begins in tone curve.

**Shoulder:** Upper portion of tone curve with gradual rolloff, highlights roll off smoothly instead of hard clipping.

**Toe:** Lower portion of tone curve with gradual rolloff, shadows transition smoothly to black.

**Clip Point:** Maximum luminance or code value before signal saturation.

**Roll-off:** Gradual reduction in gain near clipping point, creates smooth transition instead of hard edge.

**Reinhard Tone Mapping:** Global tone mapping operator based on human visual response, simple but can lose detail.

**Filmic Tone Mapping:** Tone mapping mimicking film response with separate toe, knee, and shoulder sections, industry standard.

**Exposure:** Amount of light reaching sensor, controlled by aperture, shutter speed, ISO/EI.

**Middle Gray:** 18% reflectance standard used as exposure reference.

**Peak Luminance:** Maximum brightness display can produce (100 nits SDR, 1000 nits HDR10, up to 10,000 nits Dolby Vision).

**Target Luminance:** Desired peak brightness for mastering (e.g., 100 nits for Rec.709, 1000 nits for HDR10).

**Nominal Peak Luminance:** Reference peak brightness defined by HDR standard (e.g., 1000 nits for HDR1000).

**Minimum Luminance:** Black level luminance display can produce (typically 0.001-0.005 nits for modern displays).

**Contrast Ratio:** Ratio of peak luminance to black level (e.g., 1000:1 = 1000 nits peak / 1 nits black).

**Dynamic Range:** Ratio between maximum and minimum reproducible signals, expressed in stops (log2) or decibels (20×log10).

**Signal Range:** Portion of dynamic range actually used by imagery (often less than full DR).

**Viewing Environment:** Lighting conditions, display characteristics, and viewing distance affecting color perception.

**Ambient Light:** Environmental lighting affecting perceived contrast and color reproduction.

**Surround:** Ratio of ambient light to display peak luminance, affects perceived contrast.

**Bias:** Surround light affecting color reproduction, typically neutral gray required for critical grading.

**Calibration:** Process of adjusting display to match reference characteristics (color temperature, gamma, luminance).

**Probe:** Hardware device measuring display characteristics and output for calibration purposes.

**Profile:** File or data describing device color characteristics (ICC profile, EDID).

**EDID (Extended Display Identification Data):** Metadata provided by display to computer describing capabilities (supported resolutions, color spaces, etc.).

**ICC Profile:** International Color Consortium profile describing device color characteristics for color management.

**Validating:** Process of verifying display matches calibration targets over time.

**3D LUT:** Three-dimensional lookup table mapping RGB input triplets to RGB output triplets for color transformation.

**1D LUT:** Single-channel lookup table applied independently to R, G, and B channels, affects luminance and contrast.

**Matrix Transform:** 3×3 or 4×4 matrix multiplication for color space conversion.

**Color Difference Signal:** Chrominance signal in YCbCr or similar color spaces representing difference from luma.

**Chroma Subsampling:** Reducing color resolution relative to luma to exploit human visual system characteristics.

**Color Volume:** Maximum range of colors and brightness display can produce, combination of gamut and luminance range.

**Mastering Display:** Reference display used for color grading and quality control, typically calibrated to specific standards.

**Reference Display:** Standardized display type used throughout industry (e.g., Sony BVM-HX3100 for HDR mastering).

**Consumer Display:** Consumer-grade display with variable quality, often not calibrated to professional standards.

**Home Viewing:** Typical home viewing conditions with ambient light, uncalibrated displays, affecting perceived quality.

**Cinema Viewing:** Controlled dark environment with calibrated projector, optimal viewing experience for theatrical presentation.

**Mobile Viewing:** Viewing on mobile devices with variable ambient light, small screen size, automatic brightness.

**Target Platform:** Specific delivery platform (Netflix, Amazon Prime, Disney+, Hulu, theatrical, etc.) with specific requirements.

**Spec Sheet:** Technical specification document listing delivery requirements for platform or distributor.

**Technical Delivery Specification:** Detailed document specifying codec, color space, loudness, metadata requirements.

**Quality acceptance:** Criteria determining whether delivered program meets technical standards for distribution.

**Trim:** Edited version of program created from master for specific platform or territory.

**Version Control:** System for managing multiple versions of program (theatrical, extended, airline, etc.).

**Localization:** Adapting program for specific territory (language, cultural, technical requirements).

**Territory:** Geographic region for distribution with specific technical requirements.

**Region Code:** DVD/Blu-ray region restriction system limiting playback to specific geographic regions.

**DRM (Digital Rights Management):** Copy protection and access control system for digital content distribution.

**Encryption:** Scrambling content to prevent unauthorized access, requires key for decryption.

**Key:** Encryption/decryption key for encrypted content.

**License:** Agreement granting rights to distribute content in specific territory/window.

**Window:** Time period during which content has exclusive distribution rights in territory.

**Holdback:** Period after exclusive window before content can be distributed on other platforms.

**Pay Per View (PPV):** Distribution model where viewers pay fee for single viewing of program.

**Transaction VOD (TVOD):** Pay-per-view model where viewers purchase or rent individual programs.

**Subscription VOD (SVOD):** Subscription-based access to library of content (Netflix, Hulu+, Amazon Prime, Disney+).

**Free Ad-Supported TVOD:** Free streaming supported by advertising (Tubi, Pluto TV, free ad-supported tiers).

**Electronic Sell-Through (EST):** Purchase and download-to-own model for digital content (iTunes, Amazon Video).

**Premium VOD:** Higher-priced rental/purchase with earlier availability or better quality.

**Ultra-Violet:** Digital locker system for digital copy redemption across platforms.

**Movies Anywhere:** Digital locker system for digital copy redemption across platforms.

**Movies Anywhere:** Digital locker system similar to Ultra-Violet.

**Digital Copy:** Digital version of movie included with Blu-ray/DVD purchase.

**Cloud Storage:** Off-site storage for digital content, enables access from multiple devices.

**Digital Intermediate:**** Digital color grading and finishing process replacing photochemical color timing, offering greater creative control and precision.

**Color Timer:**** Traditional photochemical color grading role, replaced by digital colorist in DI workflow.

**Colorist:** Professional specializing in color grading and color correction, working in DI suite.

**Color Grading:** Creative adjustment of color, contrast, and appearance, performed after exposure and technical color management.

**Color Correction:** Technical adjustment compensating for scene issues or color reproduction errors, distinguished from creative grading.

**DI Suite:** Facility with color grading theater, calibrated display, and color grading tools.

**Grade Suite:** Alternative term for DI suite, facility with color grading capabilities.

**Online Editor:** Editor performing final assembly, conforming, and color correction of edited program before delivery.

**Offline Editor:** Editor creating rough cut using low-resolution proxies, not responsible for final assembly.

**Conform:** Process matching edited offline sequence to high-resolution camera originals for online and color grading.

**Render:** Generate final output from timeline through color grading and effects processing.

**Export:** Create mezzanine or delivery file from edited timeline.

**XML:** Extensible Markup Language, text-based format often used for metadata and edit lists.

**EDL (Edit Decision List):** List of edit points used to conform offline to online, now largely replaced by XML.

**AAF (Advanced Authoring Format:**** File format for interchange of edit data and metadata between editing systems.

**OTIO (Open Timeline I/O):** Open format for timeline interchange supported by Avid, Resolve, other systems.

**Timeline:** Sequence of edited clips with transitions, effects, and grades in editing software.

**Track:** Timeline element containing clips for specific media type (video, audio, subtitle).

**Clip:** Segment of media placed on timeline, can be trimmed with in/out points.

**In Point:** Starting frame of clip on timeline, determines first frame used.

**Out Point:** Ending frame of clip on timeline, determines last frame used.

**Mark In/Out:** Temporary edit points marking start/end of selection, may become in/out points.

**Source:** Camera-original media or other high-quality source material.

**Proxy:** Low-resolution version of footage for offline editing, created via transcode.

**Online:** High-resolution version of footage used for final assembly and color grading.
