# 5.1 ACES Fundamentals

## Theory: ACES Architecture and Color Science

### Core Architecture

ACES [Academy Color Encoding System] is a device-independent color management framework developed by the Academy of Motion Picture Arts and Sciences (AMPAS) for archiving, interchange, and creative mastering of motion picture imagery. The system provides unified color management across cameras, VFX, grading, and display devices.

**Primary Color Spaces:**

**ACES2065-1 (AP0)** - The archival and interchange color space with imaginary primaries outside the human visual gamut. AP0 encompasses all real-world visible colors using spectral locus-based primaries defined by CIE XYZ 1931. This ensures no color information is lost during archiving or interchange.

```
AP0 Primaries (xy coordinates):
- Red:   x=0.7347, y=0.2653
- Green: x=0.0000, y=1.0000
- Blue:  x=0.0001, y=-0.0770
- White: D65 (x=0.3127, y=0.3290)
```

**ACEScg (AP1)** - Working color space for computer graphics and VFX with smaller, more efficient gamut. AP1 primaries are optimized for rendering efficiency while maintaining wide gamut coverage.

```
AP1 Primaries (xy coordinates):
- Red:   x=0.7130, y=0.2930
- Green: x=0.1650, y=0.8300
- Blue:  x=0.1280, y=0.0440
- White: D65 (x=0.3127, y=0.3290)
```

**ACEScct/ACEScc** - Log-encoded color spaces designed for color grading with perceptual uniformity similar to traditional log curves. ACEScct (ACES color correction transformation) provides a toe in the shadows for better grading behavior.

### Scene-Referred vs Display-Referred

ACES maintains **scene-referred** [image data representing actual scene luminance and color as captured] workflow throughout the pipeline. Unlike display-referred workflows that encode for specific displays, ACES preserves the relationship between pixel values and scene luminance until the final output transform.

This scene-referred approach enables:
- Archival preservation without display technology dependencies
- Future-proof delivery to emerging display technologies
- Creative decisions independent of delivery constraints
- Accurate color reproduction across different mastering displays

### Reference Rendering Transform (RRT) and Output Device Transform (ODT)

**RRT** [Reference Rendering Transform] is a standardized rendering transform that converts scene-referred ACES2065-1 data to display-referred output. The RRT applies:
- Tone mapping for display adaptation
- Glow suppression for highlight rendering
- Color appearance modeling for surround adaptation
- Contrast adjustment for display rendering

**ODT** [Output Device Transform] maps RRT output to specific display characteristics including:
- Display peak luminance (e.g., 48 nits for Rec.709, 1000 nits for P3)
- Display color primaries (e.g., Rec.709, P3, Rec.2020)
- Display electro-optical transfer function (EOTF)
- Surround compensation for viewing environment

Transform chain: `Camera → IDT → ACES2065-1 → RRT → ODT → Display`

## Practice: ACES Workflow Setup

### Input Device Transform (IDT) Selection

IDTs convert camera-specific encodings to ACES2065-1. Correct IDT selection is critical for color accuracy.

**ARRI Cameras:**
- ALEXA 35/65: IDT based on ARRI's Wide Gamut 4 and LogC4
- Legacy ALEXA: IDT based on Wide Gamut and LogC3/4
- Always use manufacturer-provided IDTs for best results

**Sony Cameras:**
- VENICE: S-Log3/S-Gamut3.Cine IDT
- FX6/FX9/FX3: Same IDT with appropriate exposure index
- X-OCN: Use specific X-OCN IDT variant

**RED Cameras:**
- IPP2 workflow: IDT based on REDWideGamutRGB/Log3G10
- Legacy: Color Science v3/v4 specific IDTs

**Custom IDTs:**
- Use ACES IDT maker tool for unsupported cameras
- Requires shooting color chart under controlled lighting
- Generate per-camera or per-lens IDTs for maximum accuracy

### Output Device Transform (ODT) Selection

ODTs are selected based on target display and mastering requirements:

**SDR Displays:**
- Rec.709 100-nit ODT for broadcast and web delivery
- P3 D65 48-nit ODT for theatrical preview
- P3 D65 Theater (non-rec.709) for cinema simulation

**HDR Displays:**
- Rec.2020+P3 1000-nit ST.2084 ODT for HDR10 mastering
- Rec.2020+P3 2000-nit ST.2084 ODT for Dolby Vision
- Rec.2020+P3 4000-nit ST.2084 ODT for high-nit mastering

**Specialized ODTs:**
- P3 D60 (simulated) for theatrical color timing
- Rec.2020 100-nit for HDR broadcast down-conversion
- Custom ODTs for specific delivery requirements

### DaVinci Resolve ACES Setup

**Project Configuration:**
```
Project Settings → Color Management:
- Color Science: ACEScct (or ACEScc for linear grading)
- ACES Version: 1.3 (latest stable) or 2.0 (when available)
- Input Transform: "No Input Transform" (apply per-clip)
- Working Space: ACEScct (recommended) or ACEScg (for VFX)
- Output Transform: Target display ODT
```

**Per-Clip IDT Application:**
1. Select clips in Media Pool
2. Right-click → "ACES Input Transform"
3. Choose manufacturer → camera model → recording format
4. Verify with color chart reference if available

**Timeline Color Space:**
- Use ACEScct for most grading work
- Switch to ACEScg for VFX-heavy timelines
- Maintain consistent working space throughout project

### Baselight ACES Setup

**Configuration:**
1. Create new scene with ACES color management
2. Set base layer to ACES2065-1 (linear)
3. Configure view transforms for monitoring
4. Apply IDTs at media import stage

**Working Space:**
- Baselight recommends ACEScc for grading
- Use ACEScg only for texture and plate preparation
- Apply output transforms at final render stage

### VFX Pipeline Integration

**Maya/Houdini/Nuke:**
- Set project color space to ACEScg (linear)
- Configure render engines for ACES output
- Use ACES-compliant textures and lighting
- Apply ACES view transforms for monitoring

**Compositing:**
- Render elements in ACES2065-1 or ACEScg
- Composite in linear ACEScg space
- Apply RRT+ODT only for final output
- Maintain full dynamic range through compositing

## Failure Modes and Troubleshooting

### Wrong IDT Selection

**Symptoms:**
- Incorrect color balance (warm/cool shift)
- Skin tone inaccuracies
- Color saturation issues
- Shadow tint problems

**Diagnosis:**
1. Verify camera model and recording format
2. Check metadata for manufacturer IDT recommendation
3. Compare with color chart reference
4. Test multiple IDTs against known reference

**Prevention:**
- Document camera settings on set
- Use consistent recording formats across production
- Maintain IDT selection spreadsheet for multi-camera shoots
- Validate with color charts during production

### Scene-Display Referred Confusion

**Symptoms:**
- Grading feels "wrong" or counter-intuitive
- Poor highlight rolloff behavior
- Inconsistent results across different ODTs
- Difficulty achieving desired contrast

**Root Causes:**
- Grading with output transform baked into image
- Applying display transforms at wrong stage
- Confusing working space with output space
- Using display-referred LUTs in ACES pipeline

**Solutions:**
- Always grade in scene-referred ACEScct space
- Monitor through proper ODT but grade to scene values
- Test ODT switching during grading to verify scene-referred nature
- Avoid baking output transforms into renders unless final delivery

### Transform Errors and Version Conflicts

**Symptoms:**
- Color shifts between software applications
- Inconsistent results across different ACES versions
- Rendering artifacts or banding
- Incorrect display characteristics

**Diagnosis:**
1. Verify ACES version consistency across all tools
2. Check OCIO configuration files
3. Validate transform chain with test patterns
4. Compare output against reference renders

**Prevention:**
- Standardize on single ACES version across pipeline
- Use version control for OCIO configurations
- Document specific transform versions used
- Test cross-application compatibility before production

### Highlight and Shadow Issues

**Symptoms:**
- Harsh highlight clipping
- Colorful highlights (rainbow edges)
- Crushed shadows with no detail
- Banding in smooth gradients

**Solutions:**
- Verify correct IDT for camera exposure settings
- Use ACEScct instead of ACEScc for better shadow behavior
- Check for clipped source material (no transform can recover)
- Apply gentle highlight recovery before IDT if using RAW

## Mini Glossary

**ACES** [Academy Color Encoding System] - AMPAS-developed color management framework for motion picture imaging, providing device-independent color space and standardized transforms.

**AP0** [ACES Primaries Set 0] - The ACES2065-1 primary set with imaginary chromaticity coordinates outside the spectral locus, designed to encompass all visible colors for archival purposes.

**AP1** [ACES Primaries Set 1] - The ACEScg primary set optimized for computer graphics rendering, providing efficient computation while maintaining wide gamut coverage.

**IDT** [Input Device Transform] - Transform that converts camera-specific color encodings (Log, RAW, or video) to the ACES2065-1 scene-referred color space.

**ODT** [Output Device Transform] - Transform that converts RRT output to display-referred values for specific display characteristics (primaries, white point, EOTF, peak luminance).

**RRT** [Reference Rendering Transform] - Standardized rendering transform that maps scene-referred ACES data to display-referred output, applying tone mapping, appearance adjustment, and display adaptation.

**ACEScct** [ACES color correction transformation] - Log-encoded ACES color space designed for color grading with perceptual uniformity and shadow toe for intuitive grading behavior.

**ACEScc** [ACES color correction] - Alternative log encoding with different mathematical formulation, less commonly used but offers pure log characteristics.

**ACEScg** [ACES computer graphics] - Linear ACES color space with AP1 primaries, optimized for 3D rendering and compositing workflows.

**Scene-referred** - Image data where pixel values maintain linear relationship to scene luminance, independent of display characteristics.

**Display-referred** - Image data encoded for specific display characteristics, with pixel values mapped to display luminance and color.

**OCIO** [OpenColorIO] - Open-source color management configuration system used to implement ACES transforms in software applications.

**LMT** [Look Modification Transform] - Optional transform applied between IDT and ODT to implement creative looks or shot-specific color corrections within ACES pipeline.

**PQ** [Perceptual Quantizer] - HDR transfer function (ST-2084) used in ACES HDR ODTs for PQ-based displays.

**HLG** [Hybrid Log-Gamma] - HDR transfer function (BT.2100) used in ACES HDR ODTs for HLG-based displays.
