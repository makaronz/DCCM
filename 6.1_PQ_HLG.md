# 6.1 PQ and HLG Fundamentals

## Theory: Transfer Function Architecture and Signal Encoding

### PQ (Perceptual Quantizer) - ST-2084

**Mathematical Foundation:**

PQ, standardized as SMPTE ST-2084, is an **absolute** transfer function designed to match the contrast sensitivity of the human visual system. Each code value corresponds to a specific, absolute luminance level measured in nits [candelas per square meter], independent of display capabilities.

**PQ EOTF Equation (ST-2084):**

The PQ electro-optical transfer function (EOTF) converts encoded code values to display luminance:

```
L = ( (c1 + c2 * Y^m1) / (1 + c3 * Y^m1) ) ^ m2 * L_max
```

Where:
- `L` = output luminance in nits (0 to 10,000)
- `Y` = normalized code value (0 to 1)
- `L_max` = display peak luminance (e.g., 1000, 2000, 4000, 10000 nits)
- `m1` = 2610 / (2^19)
- `m2` = (2523 / 2^5) * (1/4)
- `c1` = 3424 / (2^12)
- `c2` = (2413 / 2^7) * (1/4)
- `c3` = (2392 / 2^7)

**Inverse PQ (OETF):**

For signal encoding (camera OETF), the inverse function converts scene luminance to code values:

```
Y = ( ( (L/L_max)^(1/m2) - c1 ) / (c2 - c3 * (L/L_max)^(1/m2)) )^(1/m1)
```

**Key Characteristics:**

**Absolute Encoding:** PQ code values represent fixed luminance levels. Code value 0.58 (on a 0-1 scale) always represents approximately 100 nits on a properly calibrated display, regardless of the display's maximum brightness capability.

**High Dynamic Range:** PQ supports up to 10,000 nits peak luminance, far exceeding current consumer display capabilities (typically 1000-4000 nits). This headroom ensures future compatibility.

**Perceptual Uniformity:** The PQ curve allocates more code values to luminance ranges where human vision is most sensitive, maximizing perceived image quality within the 10-bit or 12-bit encoding.

**No Backward Compatibility:** PQ signals require HDR displays for correct rendering. On SDR displays without proper tone mapping, PQ imagery appears dark and desaturated.

**Metadata Dependence:** PQ requires metadata (static or dynamic) to describe content mastering characteristics, enabling displays to tone-map content appropriately.

### HLG (Hybrid Log-Gamma) - BT.2100

**Mathematical Foundation:**

HLG, standardized as ITU-R BT.2100 and ARIB STD-B67, is a **relative** transfer function designed for backward compatibility with SDR displays. HLG uses different signal encoding above and below a transition point.

**HLG OETF Equation (BT.2100-3, 2025):**

The HLG opto-electrical transfer function converts scene linear light to encoded values:

```
For 0 ≤ L ≤ 1/12:
  E = sqrt(3 * L)  // System gamma curve

For 1/12 < L ≤ 1:
  E = a * ln(12 * L - b) + c  // Logarithmic curve
```

Where:
- `L` = normalized scene linear light (0 to 1, where 1 = 1000 nits)
- `E` = encoded signal (0 to 1)
- `a` = 0.17883277
- `b` = 0.28466892
- `c` = 0.55991073

**HLG EOTF (Display Side):**

At the display, HLG applies an electro-optical transfer function:

```
For 0 ≤ E ≤ 0.5:
  L = (E^2) / 3  // Inverse system gamma

For 0.5 < E ≤ 1:
  L = exp( (E - c) / a ) / 12 + b  // Inverse logarithmic
```

**Display Peak Normalization:**

The actual displayed luminance depends on the display's peak brightness capability:

```
L_display = L * α * L_peak
```

Where:
- `L_display` = actual display luminance in nits
- `L` = normalized luminance from EOTF
- `α` = system gamma (typically 1.2 for professional monitors, 1.0 for reference)
- `L_peak` = display peak luminance (e.g., 1000 nits)

**Key Characteristics:**

**Relative Encoding:** HLG code values represent relative scene brightness, not absolute luminance. The same code value produces different luminance levels on displays with different peak brightness capabilities.

**Backward Compatibility:** The lower portion of HLG (0-0.5 encoded) uses a gamma 2.4 curve similar to Rec.709 OETF, enabling SDR-compatible display on non-HLR displays.

**No Required Metadata:** HLG typically operates without metadata, simplifying broadcast workflows. The display's peak brightness determines the actual rendered luminance.

**System Gamma:** Professional HLG monitoring uses system gamma of 1.2 to achieve optimal contrast appearance on 1000-nit mastering displays.

**Scene-Referred:** HLG maintains scene-referred encoding, preserving the relationship between code values and scene luminance ratios rather than absolute display luminance.

### ITU-R BT.2100-3 Updates (February 2025)

**Current Standard Status:**

ITU-R BT.2100-3 represents the latest specification for HDR and SDR television signal interchange, incorporating several refinements from earlier versions:

**Clarified HLG System Gamma:**
- Professional mastering: α = 1.2 for 1000-nit displays
- Consumer reference: α = 1.0 for reference viewing conditions
- Documented measurement procedures for validation

**Enhanced OOTF (Opto-Optical Transfer Function):**
- Improved documentation of scene-to-display mapping
- Clarified handling of different display peak luminances
- Additional examples for 600-nit and 4000-nit displays

**Updated Reference Viewing Conditions:**
- Specified ambient illumination requirements
- Defined surround luminance ratios
- Documented display calibration procedures

**Improved Terminology:**
- Distinguished between scene-referred and display-referred workflows
- Clarified OETF vs OOTF vs EOTF terminology
- Enhanced examples and implementation guidance

### Scene-Referred vs Display-Referred

**PQ Display-Referred Architecture:**

PQ is fundamentally **display-referred** [encoding for specific display characteristics]:
- Code values map directly to display luminance
- Content mastered for specific peak brightness (e.g., 1000 nits)
- Requires metadata for proper rendering on different displays
- Tone mapping applied at display end

**HLG Scene-Referred Architecture:**

HLG maintains **scene-referred** [encoding preserving scene luminance ratios] characteristics:
- Code values represent scene brightness relationships
- Display capability determines absolute luminance output
- No metadata required for basic functionality
- System scales to display capabilities automatically

**Practical Implications:**

**For Content Creation:**
- PQ: Master for specific display peak brightness, use metadata to optimize for other displays
- HLG: Master with scene brightness ratios, let displays scale to their capabilities

**For Distribution:**
- PQ: Requires metadata-aware distribution (HDR10, Dolby Vision)
- HLG: Simplified distribution suitable for broadcast (single stream for SDR/HDR)

**For Monitoring:**
- PQ: Monitor must match or exceed mastering peak luminance
- HLG: Monitor scales content to its peak brightness capability

## Practice: Production and Post-Production Workflows

### PQ Grading Workflow

**Camera Setup for PQ:**

1. **Log/RAW Capture:** Record in camera Log or RAW format for maximum dynamic range
2. **Exposure:** Protect highlights while maintaining shadow detail
3. **Monitoring:** Use PQ-capable monitor with appropriate LUT or built-in PQ support

**Post-Production Setup:**

**DaVinci Resolve:**
```
Project Settings → Color Management:
- Color Science: DaVinci YRGB Color Managed or ACES
- Timeline Color Space: Rec.2020
- Gamma: ST.2084 (PQ)
- Color Space: Rec.2020 (or P3 for theatrical HDR)
```

**Grading Strategy:**
1. Convert camera Log to PQ/Rec.2020 working space
2. Grade with full HDR dynamic range in mind
3. Preserve highlight detail for HDR impact
4. Use waveform monitoring set to PQ scale
5. Test on reference HDR display (1000-nit minimum for HDR10)

**HDR10 Metadata Generation:**
- MaxCLL [Maximum Content Light Level]: Peak brightness in content
- MaxFALL [Maximum Frame-Average Light Level]: Average frame brightness
- Generated automatically from timeline analysis or set manually

**Output:**
- Codec: HEVC (H.265) 10-bit main profile
- Color Space: Rec.2020
- Transfer Function: ST.2084 (PQ)
- Metadata: SMPTE ST 2086 mastering display metadata

### HLG Broadcasting Workflow

**Camera Setup for HLG:**

1. **HLG Mode:** Many cameras offer built-in HLG recording (Sony HLG, Panasonic V-Log/V-Gamut with HLG assist, Canon HLG)
2. **Exposure:** Expose for HLG mid-tone (typically gray at 75% waveform)
3. **Monitoring:** Use HLG-capable field monitor or HLG LUT

**Live Production:**

1. **Camera Output:** HLG output from camera or switcher
2. **Monitoring:** HLG-capable monitors on set and in truck
3. **Recording:** HLG-encoded proxy for offline, HLG mezzanine for online
4. **Transmission:** Single HLG stream delivered to broadcasters

**Post-Production:**

**DaVinci Resolve:**
```
Project Settings → Color Management:
- Color Science: DaVinci YRGB Color Managed
- Timeline Color Space: Rec.2020
- Gamma: Hybrid Log-Gamma (HLG)
- Color Space: Rec.2020
```

**Grading Considerations:**
- Grade for 1000-nit mastering target (professional)
- Avoid hard clipping at high end
- Test on both 1000-nit mastering monitor and consumer displays
- Verify SDR compatibility by monitoring without HDR processing

**Output:**
- Codec: H.264 or H.265 10-bit
- Color Space: Rec.2020
- Transfer Function: ARIB STD-B67 (HLG)
- Metadata: Typically none required

### Camera-Specific HDR Setup

**Sony VENICE:**
1. Record X-OCN or S-Log3
2. Use S-Log3 to HLG or S-Log3 to PQ LUT in post
3. For HLG: Apply BT.2100 HLG OETF in color management
4. For PQ: Apply ST.2084 OETF with Rec.2020

**ARRI ALEXA 35:**
1. Record LogC4
2. Convert to ACES or directly to HDR color space
3. For HLG: Use ACES HLG ODT or custom LogC4 to HLG transform
4. For PQ: Use ACES PQ ODT or custom LogC4 to PQ transform

**RED V-Raptor:**
1. Record IPP2 Log3G10
2. Convert to Rec.2020 with appropriate gamma (HLG or PQ)
3. RED IPP2 provides good starting point for HDR grading
4. Apply highlight rolloff for pleasing HDR appearance

### Monitoring and Scopes

**HDR Waveform Monitoring:**

1. **PQ Scale:** Waveform displays 0 to 10,000 nits (or 0 to mastering target)
2. **HLG Scale:** Waveform displays 0 to 1000 nits (normalized to scene)
3. **False Color:** Use HDR-specific false color for exposure verification
4. **Target Exposure:**
   - PQ: Skin tones typically 100-200 nits
   - HLG: Skin tones typically 30-50% on waveform

**Reference Display Setup:**

**PQ Monitoring:**
- Display peak: Match or exceed content mastering peak
- Calibration: ST.2084 EOTF with proper black level
- Environment: Dim surround (5% of peak luminance)
- Verification: Calibrate with colorimeter regularly

**HLG Monitoring:**
- Display peak: 1000 nits for professional mastering
- System gamma: α = 1.2 for professional, 1.0 for reference
- Calibration: BT.2100 HLG OOTF with system gamma
- SDR Check: Verify backward compatibility by disabling HDR

## Failure Modes and Troubleshooting

### Wrong Transfer Function Selection

**Symptoms:**
- Incorrect overall brightness
- Wrong contrast appearance
- Color shifts in highlights or shadows
- Unnatural image appearance

**Diagnosis:**
1. Check project color management settings
2. Verify output codec and metadata
3. Test on reference HDR display
4. Compare with reference material

**Solutions:**
- Confirm transfer function matches delivery spec (PQ for HDR10, HLG for broadcast)
- Re-encode with correct transfer function
- Verify color space matches transfer function (Rec.2020)
- Test on target display types

### Metadata Errors (PQ)

**Symptoms:**
- Content looks wrong on consumer displays
- Tone mapping artifacts
- Incorrect brightness rendering
- Color appearance issues

**Root Causes:**
- Missing or incorrect MaxCLL/MaxFALL values
- Wrong mastering display metadata in ST 2086
- Incompatible metadata between encoder and decoder
- Incorrect mastering display target

**Solutions:**
1. Analyze content to determine actual peak brightness (MaxCLL)
2. Calculate average frame brightness (MaxFALL)
3. Set correct mastering display primaries (Rec.2020 or P3)
4. Set correct mastering display peak (1000, 2000, 4000 nits)
5. Verify metadata embedded in output file

**Best Practices:**
- MaxCLL should represent actual peak brightness in content
- MaxFALL should represent typical frame average (not peak)
- Mastering display metadata should match reference display used
- Test on multiple consumer HDR displays for verification

### Display Mismatch (HLG)

**Symptoms:**
- Different appearance on different displays
- Too bright or too dark on some displays
- Lost highlight or shadow detail
- Inconsistent color reproduction

**Root Causes:**
- HLG content appearing on non-HLG displays without proper handling
- Displays with different peak brightness rendering content differently
- System gamma variations between displays
- Missing or incorrect HLG identification in signal

**Solutions:**
1. Verify HLG signal properly identified in metadata
2. Test on variety of display types and brightness capabilities
3. Consider system gamma when grading for professional targets
4. Verify backward compatibility on SDR displays

**Testing Protocol:**
- Master on 1000-nit professional display with system gamma 1.2
- Test on 600-nit consumer display
- Test on 4000-nit high-end display
- Verify SDR compatibility by disabling HDR processing

### Confusing Scene-Referred and Display-Referred

**Symptoms:**
- Grading decisions don't translate between formats
- Difficulty achieving consistent appearance
- Unexpected behavior when switching display transforms
- Color relationships shift unexpectedly

**Root Causes:**
- Grading PQ content as if it's scene-referred
- Applying HLG corrections assuming absolute luminance
- Misunderstanding which operations are scene vs display referred
- Confusing working space with output encoding

**Clarification:**

**PQ (Display-Referred):**
- Grade to absolute luminance values
- Skin tones at specific nit levels (100-200 nits)
- Highlights controlled for specific display peak
- Tone mapping decisions baked into grade

**HLG (Scene-Referred):**
- Grade to scene brightness relationships
- Skin tones at relative percentages (30-50%)
- Highlights maintained as scene overexposure
- Display handles tone mapping

**Best Practices:**
- Understand which paradigm you're working in
- Use appropriate scopes for transfer function (PQ nits vs HLG percentages)
- Test on target display types during grading
- Document creative intent for transfer function

## Mini Glossary

**PQ** [Perceptual Quantizer] - HDR transfer function standardized as SMPTE ST-2084, providing absolute luminance encoding up to 10,000 nits with perceptual uniformity.

**HLG** [Hybrid Log-Gamma] - HDR transfer function standardized as ITU-R BT.2100, providing relative scene-referred encoding with backward compatibility to SDR.

**EOTF** [Electro-Optical Transfer Function] - Conversion from electrical signal (code values) to optical output (display luminance), applied at display device.

**OETF** [Opto-Electrical Transfer Function] - Conversion from scene light (camera capture) to electrical signal (code values), applied at camera or encoder.

**OOTF** [Opto-Optical Transfer Function] - Overall conversion from scene light to display luminance, combining camera OETF and display EOTF, used in HLG system gamma.

**Scene-referred** - Image encoding maintaining relationship between code values and scene luminance, characteristic of HLG and camera RAW/Log formats.

**Display-referred** - Image encoding optimized for specific display characteristics with code values mapped to display luminance, characteristic of PQ.

**MaxCLL** [Maximum Content Light Level] - HDR metadata value indicating peak brightness level in content, measured in nits, used for PQ tone mapping.

**MaxFALL** [Maximum Frame-Average Light Level] - HDR metadata value indicating average frame brightness across content, measured in nits, used for PQ tone mapping.

**System gamma** - Adjustment applied to HLG signal to achieve optimal contrast on target display, typically 1.2 for professional mastering, 1.0 for reference.

**Nit** - Unit of luminance equal to one candela per square meter (cd/m²), standard measurement for HDR display brightness.

**Absolute vs relative** - PQ uses absolute luminance encoding (code value = specific nit level), HLG uses relative encoding (code value = scene brightness ratio scaled by display).

**BT.2100** - ITU-R specification defining parameter values for high dynamic range television for production and international programme exchange, currently at revision 3 (February 2025).

**ST.2084** - SMPTE standard defining Perceptual Quantizer (PQ) transfer function for high dynamic range television.

**ARIB STD-B67** - Japanese standard (ARIB) defining Hybrid Log-Gamma (HLG) transfer function for HDR television, incorporated into ITU-R BT.2100.

**Backward compatibility** - HLG property allowing SDR displays to render HLG content with acceptable appearance by interpreting lower portion of signal using gamma curve.

**Tone mapping** - Process of adapting HDR content to display capabilities, particularly important for PQ on displays with lower peak brightness than content mastering target.

**Reference display** - Professionally calibrated HDR monitoring display meeting specific criteria for peak luminance, color gamut, and EOTF accuracy, typically 1000 nits minimum for HDR work.

**Mastering display** - Display characteristics (peak luminance, color primaries, white point) for which HDR content is graded, embedded in metadata for proper rendering on target displays.
