# 6.2 HDR Standards and Grading

## Theory: HDR System Architecture and Metadata

### HDR10 (Open Standard)

**Technical Specification:**

HDR10 is the baseline open HDR standard requiring no licensing fees. It combines several specifications:

- **Transfer Function:** SMPTE ST-2084 (PQ)
- **Color Gamut:** ITU-R BT.2020 (Rec.2020)
- **Bit Depth:** 10-bit minimum
- **Metadata:** SMPTE ST-2086 (static mastering display metadata)

**ST-2086 Static Metadata Structure:**

```
Mastering Display Color Volume:
- Primaries: RGB chromaticity coordinates (x, y for R, G, B)
- White Point: Chromaticity coordinates (x_w, y_w)
- Luminance:
  - Max: Mastering display peak luminance (nits)
  - Min: Black level (nits, typically 0.0005-0.001)

Content Light Level:
- MaxCLL: Maximum Content Light Level (peak frame brightness)
- MaxFALL: Maximum Frame-Average Light Level
```

**Practical Implementation:**

Typical HDR10 mastering configuration:
- Primaries: Rec.2020 (though content may not fill full gamut)
- White Point: D65 (x=0.3127, y=0.3290)
- Peak Luminance: 1000 nits (typical), up to 4000 nits for premium
- Black Level: 0.005 nits (dependent on display technology)
- MaxCLL: 1000-4000 nits (content-dependent)
- MaxFALL: 200-400 nits (typical for most content)

**Limitations:**
- Static metadata applies to entire content
- No scene-by-scene optimization
- Display tone mapping must handle all content uniformly
- No creative intent communication beyond global parameters

### HDR10+ (Enhanced Open Standard)

**Technical Advancement:**

HDR10+ adds dynamic metadata to HDR10, enabling scene-by-scene (or frame-by-frame) optimization:

- **Transfer Function:** ST-2084 (PQ) - same as HDR10
- **Color Gamut:** Rec.2020 - same as HDR10
- **Metadata:** SMPTE ST-2094-40 (dynamic metadata)
- **Backward Compatibility:** HDR10+ streams include HDR10 base layer

**ST-2094-40 Dynamic Metadata:**

```
Per-Scene/Frame Parameters:
- Targeted System Display Maximum Luminance
- Targeted System Display Peak Luminance
- Anchor Point Distribution
- Knee Point (x, y) coordinates
- Anchor Point Luminance values
- Color Saturation Mapping Parameters
- Tone Mapping Parameters
```

**Technical Implementation:**

1. **Analysis:** Content analyzed scene-by-scene for optimal tone mapping
2. **Metadata Generation:** Dynamic parameters calculated for each scene
3. **Encoding:** Metadata embedded in HEVC bitstream
4. **Display Processing:** Consumer displays apply metadata for rendering optimization

**Advantages over HDR10:**
- Scene-adaptive tone mapping preserves highlight detail
- Optimized contrast per scene rather than global settings
- Better shadow detail in dark scenes
- Improved highlight rendering in bright scenes
- Creative control over HDR appearance

**Adoption Status:**
- Developed by Samsung (2017)
- Supported by Samsung, Panasonic, Philips, 20th Century Fox
- Less adoption than HDR10 or Dolby Vision
- No licensing fees (open standard)

### Dolby Vision (Proprietary Premium HDR)

**System Architecture:**

Dolby Vision is a proprietary end-to-end HDR system with several key differentiators:

- **Transfer Function:** ST-2084 (PQ) with proprietary modifications
- **Color Gamut:** Rec.2020 with proprietary processing
- **Bit Depth:** 12-bit (though 10-bit delivery common)
- **Metadata:** SMPTE ST-2094-10 (dynamic, scene-by-scene)
- **Mastering:** Dolby-certified mastering workflow required
- **Display Processing:** Dolby Vision-certified displays required

**Dolby Vision Profiles:**

**Profile 5 (Single-Layer):**
- 12-bit HEVC encode
- No backward compatibility layer
- Used for streaming services (Disney+, Netflix)
- Requires DV-capable decoder

**Profile 8.1 (Dual-Layer, Blu-ray):**
- Base layer: HDR10 (10-bit HEVC)
- Enhancement layer: Dolby Vision metadata (10-bit HEVC)
- Backward compatible with HDR10 displays
- Used for Ultra HD Blu-ray

**Profile 8.4 (Dual-Layer, Streaming):**
- Base layer: HDR10 (10-bit HEVC)
- Enhancement layer: DV metadata (AVC codec)
- Optimized for streaming bandwidth
- Used by some streaming services

**Dynamic Metadata Structure:**

```
Dolby Vision ST-2094-10 Metadata:
- Scene Frame Brightness (SFB) distribution
- Targeted System Display characteristics
- Tone Mapping Function parameters
- Color Volume Transform parameters
- Desaturation mapping at high luminance
- Multi-scale luminance and color processing
```

**ICtCp Color Space:**

Dolby Vision uses ICtCp (Intensity, Chroma) color space for processing:
- I: Intensity (luminance)
- Ct: Chroma blue-orange
- Cp: Chroma red-yellow
- Provides better color separation for HDR processing
- Minimizes hue shifts during tone mapping

**Dolby Vision Mastering:**

1. **Certified Display:** Dolby PRM-4220 or approved reference monitor
2. **CMU Processing:** Content Mapping Unit analyzes and generates metadata
3. **Creative Suite:** Dolby Vision mastering tools for color grading
4. **Quality Control:** Dolby certification process for content approval

**Advantages:**
- Most sophisticated HDR system
- Superior scene-adaptive processing
- Best highlight and shadow detail preservation
- Creative tools optimized for HDR grading
- Consistent appearance across DV-certified displays

**Requirements:**
- Licensing fees required
- Certified hardware and software required
- Professional training recommended
- Content approval process

### HLG (Broadcast Standard)

**System Overview:**

HLG provides simplified HDR for broadcast applications:

- **Transfer Function:** BT.2100 HLG (scene-referred)
- **Color Gamut:** Rec.2020
- **Bit Depth:** 10-bit
- **Metadata:** None required (optional metadata possible)
- **Backward Compatible:** SDR-compatible display on non-HDR displays

**Broadcast Implementation:**

```
Live Production Chain:
Camera → HLG Output → Switcher → Transmission → Display

Advantages:
- Single signal for SDR and HDR
- No metadata complexity
- Lower implementation cost
- Easier live production workflow
```

**HLG Reference Displays:**
- Professional: 1000-nit mastering with system gamma 1.2
- Consumer: 600-1000 nits typical
- System gamma varies by display capability

**Use Cases:**
- Live broadcast (sports, news, events)
- Live production without post-production
- Budget-constrained HDR implementation
- Simultaneous SDR/HDR delivery

### HDR System Comparison

| Feature | HDR10 | HDR10+ | Dolby Vision | HLG |
|---------|-------|--------|--------------|-----|
| **Transfer Function** | ST-2084 PQ | ST-2084 PQ | ST-2084 PQ (modified) | BT.2100 HLG |
| **Color Gamut** | Rec.2020 | Rec.2020 | Rec.2020 | Rec.2020 |
| **Bit Depth** | 10-bit | 10-bit | 12-bit | 10-bit |
| **Metadata** | Static (ST-2086) | Dynamic (ST-2094-40) | Dynamic (ST-2094-10) | None required |
| **Licensing** | Open (free) | Open (free) | Proprietary (fee) | Open (free) |
| **Backward Compatible** | No | Yes (HDR10 layer) | Yes (HDR10 layer) | Yes (SDR) |
| **Primary Use** | Streaming, Blu-ray | Streaming, Blu-ray | Cinema, Streaming, Blu-ray | Broadcast, Live |
| **Adoption** | Wide | Moderate | Growing (premium) | Growing (broadcast) |

## Practice: HDR Grading Techniques and Workflows

### HDR Grading Setup

**Hardware Requirements:**

**Reference Display (Minimum):**
- Peak Luminance: 1000 nits for HDR10
- Black Level: <0.005 nits (OLED preferred)
- Color Gamut: >90% P3, >70% Rec.2020
- Calibration: EOTF tracking within ΔE<2
- Bit Depth: 10-bit or greater panel

**Software Configuration:**

**DaVinci Resolve Setup:**
```
Project Settings → Color Management:
- Color Science: DaVinci YRGB Color Managed or ACES
- Timeline Color Space: Rec.2020
- Gamma: ST.2084 (PQ) for HDR10/Dolby Vision
- Gamma: Hybrid Log-Gamma for HLG
- Color Space: Rec.2020 (or P3 for theatrical)

Deliver Page Settings:
- Codec: HEVC (H.265) Main 10 Profile
- Color Space: Rec.2020
- Transfer Function: ST.2084 or HLG
- Metadata: Enable HDR10+ or Dolby Vision if available
```

**ACES for HDR:**
```
Project Settings → Color Management:
- Color Science: ACEScct
- ACES Version: 1.3 (or 2.0 when available)
- Working Space: ACEScct
- Output Transform: Rec.2020+P3 1000-nit ST.2084 ODT
```

### HDR Grading Strategies

**Dynamic Range Management:**

**Highlight Handling:**
- Preserve highlight detail for HDR impact
- Use gentle highlight rolloff (not hard clip)
- Maintain color in highlights (avoid desaturation)
- Reserve peak luminance (10-20% of frame) for HDR impact
- Avoid pushing everything to maximum brightness

**Shadow Detail:**
- HDR provides better shadow detail than SDR
- Use wider dynamic range for shadow separation
- Maintain shadow detail without crushing
- Consider display black level capabilities
- Test on both OLED and LCD displays

**Contrast and Grading:**
- Wider dynamic range allows more contrast flexibility
- Avoid excessive contrast that looks unnatural
- Maintain mid-tone separation
- Use entire dynamic range, not just top end
- Grade for creative intent, not just brightness

**Color Grading:**
- Wider color gamut (Rec.2020) available
- Not all displays can show full Rec.2020
- Test color choices on P3-limited displays
- Maintain color consistency across luminance levels
- Avoid over-saturation that clips gamut

### HDR-Specific Grading Techniques

**Selective Brightness:**

Use HDR's extended range to:
- Make key subjects brighter than surroundings
- Create depth through brightness contrast
- Guide viewer attention with luminance
- Separate foreground from background
- Emphasize important elements

**Creative Highlight Control:**

1. **Glow and Bloom:** Enhanced in HDR due to headroom
2. **Specular Highlights:** Preserve for realistic appearance
3. **Light Sources:** Can be much brighter than SDR
4. **Reflections:** Maintain detail in bright reflections
5. **Windows and Sky:** Control for creative effect

**Shadow Processing:**

1. **Shadow Detail:** HDR reveals more shadow information
2. **Crushing vs Detail:** Balance creative choice with visible detail
3. **Shadow Tint:** More visible in HDR, use carefully
4. **Noise:** More visible in dark areas, use NR judiciously
5. **Black Level:** Set appropriately for target display

### Monitoring and Quality Control

**Waveform Monitoring for HDR:**

**PQ Waveform:**
- Scale: 0 to 10,000 nits (or 0 to mastering target)
- Skin tones: 100-200 nits typical
- Mid-tones: 100-300 nits
- Highlights: 500-4000 nits depending on content
- Peak brightness: Use for HDR impact

**HLG Waveform:**
- Scale: 0 to 1000 nits (normalized)
- Skin tones: 30-50% typical
- Mid-tones: 40-60%
- Highlights: 70-100%
- System gamma affects actual nit values

**False Color for HDR:**
- Different ranges than SDR false color
- Verify skin tone exposure (100-200 nits for PQ)
- Check highlight preservation
- Verify shadow detail
- Confirm target brightness ranges

**Quality Control Process:**

1. **Mastering Display:** Grade on professional reference display
2. **Consumer Display Test:** Verify on typical consumer HDR displays
3. **SDR Check:** Verify SDR compatibility (HLG) or tone mapping (PQ)
4. **Metadata Validation:** Verify HDR10+/Dolby Vision metadata accuracy
5. **Multiple Display Tests:** Test on OLED and LCD displays
6. **Format Validation:** Verify file meets delivery specifications

### Creative Considerations

**HDR as Creative Tool, Not Gimmick:**

- Use extended dynamic range for creative storytelling
- Not every frame needs peak brightness
- Maintain contrast balance across scenes
- Consider viewer comfort (avoid eye strain)
- Preserve natural appearance

**Color Volume Awareness:**

- Not all colors available at all brightness levels
- Display-dependent color gamut
- Test creative choices on target displays
- Maintain color consistency across luminance
- Consider SDR compatibility for wider distribution

**Maintaining Creative Intent:**

- Grade for storytelling, not technical demonstration
- Document HDR grading decisions
- Test on various display types
- Preserve mood and atmosphere
- Consider future viewing environments

## Failure Modes and Troubleshooting

### Metadata Errors

**Symptoms:**
- Content looks wrong on consumer displays
- Incorrect brightness rendering
- Tone mapping artifacts
- Color appearance issues

**Diagnosis:**
1. Verify ST-2086 metadata values are correct
2. Check MaxCLL/MaxFALL accuracy
3. Confirm mastering display parameters
4. Test on reference consumer displays
5. Validate with HDR metadata analyzer tools

**Solutions:**
- Analyze timeline for actual peak values
- Generate accurate MaxCLL/MaxFALL from content
- Set appropriate mastering display metadata
- Test on multiple consumer displays
- Document metadata parameters for QC

### Wrong Mastering Display Target

**Symptoms:**
- Content doesn't translate to consumer displays
- Lost highlight or shadow detail
- Incorrect brightness appearance
- Color reproduction issues

**Root Causes:**
- Mastering for peak brightness higher than typical consumer displays
- Mastering on display with different characteristics than target
- Using mastering display not matching delivery specs
- Not considering consumer display limitations

**Best Practices:**
- Master on 1000-nit display for HDR10 (even if content peaks higher)
- Test on 600-nit consumer displays
- Consider display technology differences (OLED vs LCD)
- Grade for typical consumer capabilities, not edge cases
- Verify appearance across display range

### Clipping Issues

**Symptoms:**
- Lost highlight detail
- Colorful highlights (rainbow artifacts)
- Harsh clip at peak brightness
- No detail in specular highlights

**Causes:**
- Grading brighter than mastering display capability
- Not protecting highlights during grading
- Hard clip instead of rolloff
- Display limitations

**Solutions:**
- Use gentle highlight rolloff curves
- Maintain highlight detail through grading
- Test on displays with different peak brightness
- Reserve headroom for HDR highlights
- Avoid pushing entire frame to maximum

**Highlight Rolloff Techniques:**
- Custom curves for gradual rolloff
- Soft clip operations
- Selective highlight preservation
- Display-specific clipping protection
- Maintain color in highlights

### Color Volume Issues

**Symptoms:**
- Color shifts on different displays
- Clipped colors on some displays
- Inconsistent color reproduction
- Out-of-gamut warnings

**Root Causes:**
- Using colors outside P3 gamut (common on consumer displays)
- Not testing on P3-limited displays
- Color saturation too high for certain brightness levels
- Color grading not considering display gamut limitations

**Solutions:**
1. Test color grading on P3-limited displays
2. Use in-gamut warning features in grading software
3. Maintain colors within P3 for critical skin tones
4. Reserve extreme Rec.2020 colors for creative effect
5. Verify color consistency across display types

**Best Practices:**
- Critical skin tones: Keep within P3 gamut
- Creative colors: Can extend to Rec.2020 if desired
- Saturation varies with brightness (color-volume dependent)
- Test on various display types
- Maintain color harmony across luminance levels

## Mini Glossary

**HDR10** - Open HDR standard using ST-2084 PQ transfer function with Rec.2020 color gamut, 10-bit depth, and static ST-2086 metadata.

**HDR10+** - Enhanced HDR10 standard adding ST-2094-40 dynamic metadata for scene-by-scene optimization, backward compatible with HDR10.

**Dolby Vision** - Proprietary HDR system using modified ST-2084 PQ with ST-2094-10 dynamic metadata, 12-bit processing, and certified mastering/display requirements.

**HLG** [Hybrid Log-Gamma] - Scene-referred HDR transfer function (BT.2100) with backward compatibility to SDR, designed for broadcast applications without metadata requirements.

**Dynamic metadata** - Per-scene or per-frame metadata providing adaptive tone mapping and color volume information for optimal HDR rendering, used in HDR10+ and Dolby Vision.

**Static metadata** - Global metadata applied to entire content, describing mastering display characteristics and content light level ranges, used in HDR10.

**Mastering display** - Reference display used for HDR grading, with specific peak luminance, color gamut, and EOTF characteristics, described in metadata for proper content rendering.

**Nit** - Unit of luminance measurement (candela per square meter, cd/m²), standard for HDR display brightness specification.

**MaxCLL** [Maximum Content Light Level] - HDR metadata value indicating peak brightness level in content, used by displays for tone mapping.

**MaxFALL** [Maximum Frame-Average Light Level] - HDR metadata value indicating typical frame brightness, used by displays for power management and tone mapping.

**ICtCp** - Color space used in Dolby Vision processing, separating intensity (I) from chroma (Ct, Cp) for improved HDR processing with minimal hue shifts.

**CMU** [Content Mapping Unit] - Dolby Vision processing hardware that analyzes content and generates dynamic metadata for optimal HDR rendering.

**Profile** - Dolby Vision implementation variant (e.g., Profile 5 for single-layer streaming, Profile 8.1 for dual-layer Blu-ray), defining encoding structure and compatibility.

**Backward compatibility** - HDR system feature allowing display on non-HDR devices (SDR for HLG, HDR10 for Dolby Vision/HDR10+).

**Tone mapping** - Process of adapting HDR content to display capabilities, critical for PQ content on displays with lower peak brightness than mastering target.

**Color volume** - Combination of color gamut and luminance range, describing available colors at different brightness levels in HDR content.

**HDR impact** - Creative use of peak brightness for visual emphasis and storytelling, typically reserving 10-20% of frame for HDR impact brightness.

**Highlight rolloff** - Gradual transition from mid-tones to peak brightness instead of hard clipping, preserving detail and color in highlights.

**Reference display** - Professionally calibrated HDR mastering display meeting specific technical criteria for accurate content creation.

**Consumer display** - Typical home HDR display with varying capabilities (600-4000 nits peak, varying color gamut coverage), important testing target for HDR content.
