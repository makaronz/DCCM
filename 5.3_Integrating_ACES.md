# 5.3 Integrating ACES

## Theory: OCIO-ACES Configuration and Pipeline Architecture

### OpenColorIO (OCIO) Fundamentals

**OCIO** [OpenColorIO] provides the configuration framework for implementing ACES transforms across software applications. The OCIO-ACES config files define transform paths, color space definitions, and display rules that enable consistent ACES implementation.

**Configuration Architecture:**

```
OCIO Config Structure:
├── colorspaces/          # Color space definitions
│   ├── ACES2065-1       # Archival scene-referred space
│   ├── ACEScg           # Linear working space (AP1)
│   ├── ACEScct          # Log grading space
│   ├── Input spaces     # Camera-native encodings
│   └── Output spaces    # Display-referred encodings
├── displays/            # Display device definitions
├── views/               # Viewing transform combinations
├── roles/               # Named color space roles
└── rules/               # Transform selection rules
```

**ACES OCIO Config Versions:**

- **aces_1.0.3** - Initial stable release
- **aces_1.1** - Enhanced camera support, improved transforms
- **aces_1.2** - ACEScct addition, better VFX integration
- **aces_1.3** - Current stable (as of 2024), improved HDR support
- **aces_2.0** - In development, enhanced RRT and workflow improvements

### Transform Chain Architecture

**Complete ACES Pipeline:**

```
1. Camera Capture
   ├─ RAW sensor data
   ├─ Camera Log encoding
   └─ Manufacturer color science

2. Input Device Transform (IDT)
   ├─ Converts to ACES2065-1 (AP0)
   ├─ Scene-referred linear encoding
   └─ Preserves full dynamic range

3. Optional Working Space Conversion
   ├─ ACEScct for grading (log)
   ├─ ACEScg for VFX (linear)
   └─ ACEScc alternative log space

4. Creative Grading / VFX
   ├─ Color correction in working space
   ├─ Visual effects in ACEScg
   └─ LMT application (optional)

5. Reference Rendering Transform (RRT)
   ├─ Scene-referred to display-referred
   ├─ Tone mapping application
   └─ Display adaptation

6. Output Device Transform (ODT)
   ├─ Display-specific rendering
   ├─ Peak luminance mapping
   └─ Color gamut mapping

7. Final Output
   ├─ SDR Rec.709 (100 nits)
   ├─ HDR10/P3 (1000 nits)
   ├─ Dolby Vision (varies)
   └─ Theatrical DCI-P3 (48 nits)
```

**Transform Path Selection:**

OCIO automatically selects appropriate transforms based on:
- Input color space (determined from IDT selection)
- Working color space (project configuration)
- Display/view combination (output requirements)
- Rules engine (pipeline-specific overrides)

### Project Setup Considerations

**Color Space Roles:**

OCIO defines specific roles for color spaces in the pipeline:
- **Rendering** - Default working space (ACEScg or ACEScct)
- **Reference** - Scene-referred master (ACES2065-1)
- **Color Picking** - Space for UI color pickers
- **Color Timing** - Grading preview space
- **Compositing Log** - Log space for compositing operations

**Display View Combinations:**

Views combine displays and output transforms:
- `ACES -> Rec.709 Output` - SDR monitoring
- `ACES -> P3-DCI (48 nits)` - Theatrical preview
- `ACES -> Rec.2020-P3 (1000 nits)` - HDR10 monitoring
- `ACES -> None` - Bypass monitoring (ACES2065-1 values)

### Custom Transform Integration

**Custom IDTs:**

For unsupported cameras or specialized workflows:
1. Generate IDT using ACES IDT Maker tool
2. Add custom IDT to OCIO config colorspaces
3. Define transform from camera encoding to ACES2065-1
4. Document exposure index and white balance dependencies

**Custom LMTs:**

Creative looks implemented as LMTs:
1. Create look in ACEScct grading space
2. Export as LMT transform (CLF or LUT format)
3. Add to OCIO config as transform between IDT and RRT
4. Apply per-shot or per-sequence as needed

**Custom ODTs:**

For specialized display requirements:
1. Analyze target display characteristics (primaries, white point, EOTF, peak luminance)
2. Create transform from RRT output to display encoding
3. Add to OCIO config as output transform
4. Verify with measurement and visual testing

## Practice: Software-Specific Implementation

### DaVinci Resolve ACES Integration

**Project Configuration:**

```
Project Settings → Color Management:

Color Science: ACEScct (recommended for grading)
ACES Version: 1.3 (current stable) or 2.0 (beta)

Input Transform: "No Input Transform" (applied per-clip)
Working Space: ACEScct (or ACEScg for VFX work)
Output Transform: Target display ODT

Timeline Color Space: ACEScct
Input Color Space: Use clip-level setting
Output Color Space: Follow project setting
```

**Per-Clip IDT Application:**

1. Select clips in Media Pool
2. Right-click → "ACES Input Transform"
3. Navigate hierarchy: Manufacturer → Camera → Recording Format
4. Verify correct selection with metadata
5. Apply to multiple clips of same type

**Example IDT Selection:**
- ARRI → ALEXA 35 → LogC4 (EI 800)
- Sony → VENICE → S-Log3.S-Gamut3.Cine
- RED → HELIUM → IPP2 → RWG → Log3G10

**Timeline-Level Configuration:**

For consistent handling across timeline:
1. Right-click timeline → "Timeline Color Space"
2. Select ACEScct for grading work
3. Use ACEScg only for VFX-heavy sequences
4. Maintain consistent space throughout timeline

**Output Delivery Setup:**

```
Deliver Page Settings:
- Format: MXF, QuickTime, or per delivery spec
- Codec: ProRes, DNxHR, or per delivery spec
- Color Space: Follow project setting (ODT applied)
- Metadata: Embed ACES transform information

SDR Deliveries:
- Output Transform: Rec.709 100-nit ODT
- Gamma: 2.4 or 2.2 (per region)
- Tag video with appropriate color space metadata

HDR Deliveries:
- Output Transform: Rec.2020+P3 1000-nit ST.2084 ODT
- MaxCLL/MaxFALL: Calculate from timeline
- HDR10+ metadata: Generate during render
- Dolby Vision: Export XML for CMU processing
```

**ACEScct vs ACEScc Selection:**

ACEScct (recommended):
- Better shadow behavior with toe
- More intuitive grading response
- Industry standard for ACES grading
- Better highlight rolloff characteristics

ACEScc (alternative):
- Pure log encoding
- Different mathematical formulation
- Less commonly used
- Specific technical applications

### Baselight ACES Implementation

**Scene Configuration:**

1. Create new Baselight scene
2. Configure color management in scene settings
3. Set base color space to ACES2065-1 (linear)
4. Configure view transforms for monitoring

**Layer-Based Color Management:**

Baselight applies color management per layer:
1. Base layer: ACES2065-1 input
2. IDT layer: Apply input transform
3. Grade layers: Work in ACEScct/ACEScc
4. Output layer: Apply RRT+ODT transform

**Working Space Selection:**

- **ACEScc** (Baselight recommendation): Grading with log response
- **ACEScg**: VFX and texture preparation only
- **ACES2065-1**: Linear operations when required

**View Transform Setup:**

Configure multiple view transforms for monitoring:
- SDR Rec.709 for broadcast preview
- P3-D65 for theatrical preview
- HDR ST.2084 for HDR monitoring
- Toggle between views during grading

**Render and Export:**

1. Apply appropriate output transform on final output layer
2. Configure render codec and format for delivery
3. Embed color space metadata in renders
4. Generate per-delivery renders as needed

### Nuke ACES Workflow

**OCIO Configuration:**

1. Install OCIO-ACES config (typically system-wide or project-local)
2. Set OCIO environment variable to config path
3. Configure Nuke to use OCIO color management
4. Verify OCIO knob appears on Read/Write nodes

**Node-Level Color Management:**

```
Read Node:
- Color space: Camera-native encoding (determined per footage)
- Apply IDT automatically or manually with OCIOColorSpace node
- Convert to working space for compositing

Working Space:
- Set project working space to ACEScg (linear)
- All compositing operations in linear ACEScg
- Maintain full dynamic range through pipeline

Write Node:
- Apply RRT+ODT transform at output
- Or output ACES2065-1 for later grading
- Embed color space metadata in renders
```

**Compositing Workflow:**

1. Import all elements with appropriate input color spaces
2. Convert all to ACEScg working space
3. Composite in linear ACEScg
4. Apply creative operations in linear space
5. Apply RRT+ODT only at final output

**Monitor Output:**

Configure viewer for appropriate monitoring:
- Apply RRT+ODT transform for accurate monitoring
- Switch between SDR and HDR views as needed
- Verify appearance on target display types

### Custom Transform Creation

**Creating Custom IDTs:**

Use ACES IDT Maker tool for unsupported cameras:

1. Shoot color chart under controlled lighting
2. Process chart through analysis software
3. Generate IDT transform (CLF or LUT)
4. Integrate into OCIO config
5. Test with known reference material

**LMT Development:**

Create creative looks as LMTs:

1. Develop look in ACEScct grading session
2. Export grade as transform (CLF format recommended)
3. Add to OCIO config as LMT transform
4. Insert into transform chain between IDT and RRT
5. Apply selectively per shot or scene

**Custom ODT Construction:**

For specialized display requirements:

1. Characterize target display (measure primaries, white point, EOTF)
2. Create transform from RRT output to display encoding
3. Account for peak luminance and color volume
4. Test and validate with measurement
5. Integrate into OCIO config for project use

## Failure Modes and Troubleshooting

### Wrong OCIO Configuration

**Symptoms:**
- Missing color spaces or transforms
- Incorrect transform application
- Inconsistent results across applications
- Unable to select required transforms

**Diagnosis:**
1. Verify OCIO environment variable points to correct config
2. Check config version matches project requirements
3. Validate config file integrity (XML syntax)
4. Confirm all required transforms are present

**Solutions:**
- Use standard ACES OCIO config unless custom transforms required
- Version control OCIO configs for reproducibility
- Document custom config modifications
- Test config with all required software applications before production

**Configuration File Location:**

```
System-wide: /opt/OpenColorIO/aces_1.3/config.ocio
User-specific: ~/.config/OpenColorIO/aces_1.3/config.ocio
Project-local: /project/color_management/config.ocio
Environment: $OCIO=/path/to/config.ocio
```

### Missing or Incompatible Transforms

**Symptoms:**
- "Transform not found" errors
- Inability to select required IDT/ODT
- Camera format not available
- Display transform missing

**Root Causes:**
- OCIO config version doesn't include required transform
- Camera model/firmware not supported by ACES version
- Custom transforms not properly integrated
- Transform path not defined in config

**Solutions:**
1. Update to latest ACES OCIO config (currently 1.3)
2. Generate custom IDT for unsupported cameras
3. Add custom transforms to config
4. Verify transform paths are correctly defined

**Version-Specific Issues:**

Different ACES versions have different transform availability:
- ACES 1.0-1.2: Limited camera support, older transform algorithms
- ACES 1.3: Current stable, broad camera support
- ACES 2.0 (beta): Enhanced RRT, improved HDR support

### Version Conflicts in Pipeline

**Symptoms:**
- Color shifts between software applications
- Different appearances on different systems
- Inconsistent VFX integration
- Rendering artifacts

**Diagnosis:**
1. Check OCIO config version on all systems
2. Verify ACES version consistency in project settings
3. Compare transform versions between applications
4. Test with reference material to identify discrepancies

**Prevention:**
- Standardize on single ACES version across pipeline
- Use version control for OCIO configurations
- Document all transform versions used in project
- Create pipeline specification document
- Test cross-application workflow before production

**Cross-Application Testing:**

Validate ACES pipeline across software:
1. Create test scene with known color values
2. Process through each application in pipeline
3. Compare outputs at each stage
4. Verify consistent appearance across all applications
5. Document any discrepancies and resolutions

### Transform Application Order Errors

**Symptoms:**
- Incorrect color appearance
- Washed-out or over-saturated image
- Incorrect contrast or gamma
- Mismatched colors between shots

**Root Causes:**
- Applying IDT to already ACES-converted footage
- Missing transform in chain (IDT, RRT, or ODT)
- Applying transforms in wrong order
- Double-applying transforms

**Correct Transform Order:**

```
RAW/Log Camera Footage
    ↓
Input Device Transform (IDT)
    ↓
ACES2065-1 (AP0, scene-referred linear)
    ↓
Optional: Convert to ACEScct/ACEScg
    ↓
Grading / VFX in working space
    ↓
Optional: Apply LMT (creative look)
    ↓
Reference Rendering Transform (RRT)
    ↓
Output Device Transform (ODT)
    ↓
Display-Referred Output
```

**Verification:**
1. Confirm input footage is in camera-native encoding
2. Verify IDT applied (not bypassed)
3. Check working space conversion (if used)
4. Confirm RRT+ODT applied at output
5. Test with color chart reference if available

### Performance and Optimization

**Symptoms:**
- Slow render times with ACES transforms
- Playback performance degradation
- Excessive memory usage
- Long processing times

**Optimization Strategies:**

**Cache Transforms:**
- Pre-calculate common transform combinations
- Cache transform results for repeated operations
- Use GPU acceleration when available
- Optimize transform resolution for real-time monitoring

**Working Space Selection:**
- Use ACEScct for grading (better performance than ACEScc in some applications)
- Reserve ACEScg for operations requiring linear space
- Minimize unnecessary color space conversions

**Render Optimization:**
- Use proxy resolutions for editorial and preview
- Apply transforms at appropriate resolution for stage
- Batch similar operations for efficiency
- Use hardware acceleration when available

## Mini Glossary

**OCIO** [OpenColorIO] - Open-source color management configuration system providing transform definitions, color space mappings, and display rules for consistent color management across applications.

**Config** [OCIO configuration] - XML-based file defining color spaces, transforms, displays, and views for color-managed workflow, enabling consistent color management across software.

**Transform chain** - Sequence of color space conversions and rendering transforms applied to imagery from input through output, critical for maintaining color accuracy in ACES pipeline.

**Custom transform** - User-created color transform for specific requirements not covered by standard ACES transforms, including IDTs, LMTs, and ODTs for specialized workflows.

**ACES version** - Specific release of ACES specification and transforms, with different versions offering different features, camera support, and rendering characteristics (1.0, 1.1, 1.2, 1.3, 2.0).

**LMT** [Look Modification Transform] - Optional transform applied between IDT and ODT in ACES pipeline to implement creative looks or shot-specific color corrections.

**CLF** [Common LUT Format] - ACES-approved format for storing color transforms as XML, supporting both 1D and 3D transforms with embedded metadata.

**IDT Maker** - Academy-provided tool for generating custom ACES Input Device Transforms for unsupported cameras or specialized capture requirements.

**View transform** - OCIO definition combining display device and output transform, enabling accurate monitoring of different delivery formats during color grading.

**Working space** - Color space used for grading, compositing, or VFX operations, typically ACEScct for grading or ACEScg for VFX work.

**Rendering space** - Default color space for rendering operations in OCIO configuration, typically ACEScg for linear workflow or ACEScct for log workflow.

**Color space role** - Named semantic definition in OCIO config assigning specific purposes to color spaces (rendering, reference, compositing, etc.).

**P3** - DCI-P3 color gamut widely used in digital cinema, with specific primary chromaticity coordinates and D65 white point.

**ST.2084** - SMPTE standard defining Perceptual Quantizer (PQ) transfer function for HDR content, used in ACES HDR ODTs.

**HDR10** - Open HDR standard using ST.2084 PQ transfer function with Rec.2020 color gamut and static metadata.

**Dolby Vision** - Proprietary HDR system using dynamic metadata for scene-by-scene optimization, requiring licensing and certified equipment.

**MaxCLL** [Maximum Content Light Level] - HDR metadata value indicating peak brightness level in content, measured in nits.

**MaxFALL** [Maximum Frame-Average Light Level] - HDR metadata value indicating average frame brightness level, measured in nits.

**CMU** [Content Mapping Unit] - Dolby Vision processing unit that applies dynamic metadata to optimize HDR content for display capabilities.
