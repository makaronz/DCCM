# 7.4 Creating On-Set LUTs and CDLs

## Theory: CDL Format and Color Decision List

### CDL (Color Decision List) Fundamentals

**ASC-CDL Standard:**
- **Purpose**: Industry-standard format for primary grade communication (on-set → post → color grading)
- **Format**: XML or plain text, contains 10 values (SOP + SAT for each clip)
- **Scope**: Primary corrections only (lift/gamma/gain + saturation), not secondary or selective grading
- **Adoption**: Supported by all major grading software (Resolve, Baselight, Lustre, Pablo)

**SOP (Slope, Offset, Power):**
- **Slope (RGB)**: Contrast adjustment (1.0 = no change, >1.0 = increase contrast, <1.0 = decrease contrast)
- **Offset (RGB)**: Lift/brightness adjustment (0.0 = no change, positive = brighter, negative = darker)
- **Power (RGB)**: Gamma/pivot adjustment (1.0 = no change, >1.0 = raise midtones, <1.0 = lower midtones)
- **Each Channel**: R, G, B can be adjusted independently (color grading) or together (contrast/brightness)

**SAT (Saturation):**
- **Single Value**: Saturation adjustment (1.0 = no change, >1.0 = more saturated, <1.0 = less saturated)
- **Scope**: Affects all colors equally (global saturation), not selective saturation (specific hue ranges)
- **Calculation**: Applied after SOP, scales color saturation based on SOP-adjusted RGB values

**ASC-CDL XML Structure:**
```xml
<ColorDecisionList>
  <ColorDecision>
    <EditRate>24</EditRate>
    <TimeCode>01:00:00:00</TimeCode>
    <SOPNode>
      <Slope>1.0 1.0 1.0</Slope>
      <Offset>0.0 0.0 0.0</Offset>
      <Power>1.0 1.0 1.0</Power>
      <Saturation>1.0</Saturation>
    </SOPNode>
  </ColorDecision>
</ColorDecisionList>
```

### CDL vs LUT Comparison

**CDL (Color Decision List):**
- **Advantages**: Small file size (KB), editable (text format), industry standard, preserves creative intent
- **Limitations**: Primary corrections only (no selective/secondary grading), limited color manipulation (SOP + SAT)
- **Best For**: On-set primary grading, shot matching, communicating color decisions to post

**LUT (Look-Up Table):**
- **1D LUT**: Single channel (luma) adjustment, gamma, contrast, brightness (limited color manipulation)
- **3D LUT**: RGB cube (33x33x33 or 65x65x65), complex color transformations (secondary grading, looks)
- **Advantages**: Can represent complex looks (film emulation, creative grades), non-linear transformations
- **Limitations**: Large file size (MB), not editable (binary format), not standardized (multiple formats)
- **Best For**: Display transforms (log to Rec.709), creative looks (film stocks, stylistic grades)

**Combined Workflow (CDL + LUT):**
1. **CDL**: Primary grade (shot matching, exposure, white balance) applied first
2. **LUT**: Creative look (film emulation, stylistic grade) applied after CDL
3. **Order**: Camera Log → CDL (SOP+SAT) → Look LUT (creative) → Display LUT (Rec.709)

### Metadata Embedding

**Where CDL Lives:**
- **Sidecar File**: Separate XML/CSV file with CDL values (referenced by timecode or clip name)
- **Embedded Metadata**: CDL embedded in video file header (ProRes, DNxHD, some raw formats)
- **ALE (Avid Log Exchange)**: CDL values in ALE file (imported by editorial, color grading)
- **Scene Database**: Pomfort LiveGrade library, ShotHub cloud storage, proprietary databases

**Sidecar vs Embedded:**
- **Sidecar (External)**:
  - **Pros**: Editable (text format), portable across systems, can be version controlled
  - **Cons**: Separate file management (can get lost), requires manual linking to clips
  - **Best For**: On-set grading, post flexibility, version control

- **Embedded (Internal)**:
  - **Pros**: Travels with file (can't get lost), automatic in post, streamlined workflow
  - **Cons**: Harder to edit (requires software), limited to certain formats (ProRes, DNxHD)
  - **Best For**: Final delivery, proxy files, archives

**Metadata Standards:**
- **ASC-CDL**: Industry standard (XML), supported by all major software
- **CMX EDL**: Legacy format (timecode + CDL), limited but still used
- **ALE (Avid)**: Editorial standard (shot metadata + CDL), integrates with Media Composer
- **FLEx (FilmLight)**: Baselight format (extended CDL + notes), proprietary but powerful

## Practice: Creating and Managing LUTs/CDLs

### On-Set CDL Workflow

**Step 1: Establish Base Look (Before Shoot):**
- Apply camera LUT (log to Rec.709) for monitoring
- Adjust CDL (SOP+SAT) for desired look (day exterior, night interior, etc.)
- Save base look as preset (reusable across scenes, days, projects)
- Test on camera test footage (verify look translates to different lighting conditions)

**Step 2: Shot Matching (During Shoot):**
- Apply base look preset to new shot
- Fine-tune CDL for shot matching (exposure, white balance, saturation)
- Save CDL with timecode or clip name (auto-save in LiveGrade)
- Document CDL decisions (shot log, PDF report, notes)

**Step 3: CDL Export (Daily or End of Day):**
- Export CDL as ALE (for editorial) and XML/CSV (for color grading)
- Export proxy files (ProRes 422 LT) with embedded CDL (if supported)
- Export LUT library (1D/3D LUTs for base looks, creative looks)
- Generate report (PDF/CSV) with shot metadata, CDL values, thumbnails

**Step 4: Handoff to Post:**
- Deliver camera originals (raw) + sidecar CDL files (XML/CSV)
- Deliver proxy files (ProRes) with embedded CDL
- Deliver ALE file (import into Media Composer, export to color grading)
- Deliver LUT library (reference for colorist, not final grade)

### LUT Creation from Graded Looks

**Extracting CDL from Graded Shot:**
- **Software**: DaVinci Resolve, Pomfort LiveGrade, ColorFront Engine
- **Method**: Apply CDL node in Resolve, adjust SOP+SAT, export as CDL (XML/CSV)
- **Verification**: Load CDL into new project, apply to flat shot, compare to original graded shot

**Baking LUT from CDL + Display Transform:**
- **Purpose**: Create 3D LUT combining CDL + display LUT (for monitoring without software)
- **Software**: Resolve (LUT generator), LUT Utility (convert formats), Pomfort LiveGrade (export LUT)
- **Process**:
  1. Create node tree in Resolve: CDL node → Display LUT node (Rec.709)
  2. Use "Generate LUT" feature (export as 3D .cube file, 33x33x33 or 65x65x65)
  3. Test LUT on flat footage (verify look matches graded version)

**Creative Look LUTs:**
- **Film Emulation**: Create LUT from film stock scan (apply to digital footage for film look)
- **Stylistic Grades**: Create LUT from graded shot (teal & orange, bleach bypass, etc.)
- **Camera Matching**: Create LUT to match different cameras (RED to ARRI, Sony to ARRI)

**LUT Formats:**
- **.cube**: Resolve standard, 3D LUT, text format (readable, editable)
- **.3dl**: Lustre/Light Illusion format, 3D LUT, binary format
- **spi3d**: Pandora format, 3D LUT, binary format
- **.look**: FileMaker Pro format, 1D LUT, legacy
- **Conversion**: LUT Utility (convert between formats), ensure compatibility with monitoring equipment

### Metadata Embedding Workflow

**Embedding CDL in ProRes Proxy Files:**
- **Software**: Pomfort Silverstack, DaVinci Resolve, FFmpeg
- **Process**:
  1. Export CDL as XML (from LiveGrade or Resolve)
  2. Import CDL into Silverstack (link to clips by timecode or clip name)
  3. Export ProRes 422 LT with embedded CDL (Silverstack handles metadata wrapping)
  4. Verify CDL embedded (open in QuickTime Player, inspect metadata)

**Embedding CDL in ALE (Editorial):**
- **Software**: Pomfort LiveGrade, DaVinci Resolve, Excel
- **Process**:
  1. Export ALE from LiveGrade (includes CDL values, timecode, clip name)
  2. Import ALE into Avid Media Composer (bin with clips + CDL columns)
  3. Export EDL from Avid (includes CDL values for color grading)
  4. Import EDL into Resolve (CDL automatically applied to clips)

**Cloud-Based CDL Management:**
- **Pomfort ShotHub**: Cloud library for CDLs, LUTs, shot metadata (real-time collaboration)
- **Frame.io**: Camera-to-cloud CDL delivery (immediate review by colorist/director)
- **ColorFront Cloud**: Real-time grading collaboration (multiple colorists working on same project)

### Version Control and Archiving

**CDL Versioning:**
- **Naming Convention**: `ProjectName_SceneX_TakeY_Date_v01.cdl`
- **Version Numbers**: Increment for each revision (v01, v02, v03)
- **Backup**: Save all versions (don't overwrite old versions), archive after project completion
- **Notes**: Document changes between versions (why CDL was adjusted)

**LUT Library Management:**
- **Organize by Type**: Display LUTs (camera log to Rec.709), Creative LUTs (looks), Utility LUTs (color space conversions)
- **Organize by Project**: Project-specific LUTs in project folder, general LUTs in shared library
- **Version Control**: LUT versions (v1, v2, v3), document changes
- **Archive**: Final LUT library (after lock), store with project deliverables

**Long-Term Archiving:**
- **CDL Files**: Archive with project deliverables (XML/CSV, ALE)
- **LUT Files**: Archive creative LUTs (.cube, .3dl) for reference
- **Documentation**: Archive grading reports (PDF with thumbnails, CDL values)
- **Storage**: LTO tape (long-term), cloud storage (access), hard drive (working copy)

## Failure Modes: Format and Metadata

### Wrong CDL Format

**Incompatible XML Schema:**
- **Symptom**: CDL file won't import (Resolve error: "invalid CDL format"), CDL values don't load
- **Cause**: CDL exported from software using non-standard XML schema (custom tags, wrong namespace)
- **Fix**: Export CDL as standard ASC-CDL (use Resolve, LiveGrade, or ColorFront), verify XML structure
- **Prevention**: Test CDL round-trip (export from on-set software, import into Resolve, verify values)

**CDL Values Out of Range:**
- **Symptom**: CDL imports but values are wrong (clipped, inverted, extreme contrast)
- **Cause**: CDL values outside expected range (Slope >2.0, Offset <-1.0, Power >2.0), software-specific scaling
- **Fix**: Normalize CDL values to standard range (Slope: 0-2, Offset: -1 to +1, Power: 0-2, Saturation: 0-2)
- **Prevention**: Test CDL export (verify values in text editor, compare to on-set grading software)

**Missing Timecode or Clip Name:**
- **Symptom**: CDL imports but doesn't link to clips (all CDLs applied to first clip, or no CDL applied)
- **Cause**: CDL file missing timecode or clip name (only SOP+SAT values), mismatch between CDL and clip names
- **Fix**: Re-export CDL with timecode or clip name (match clip naming convention: A001_C001_0101AB_001.R3D)
- **Prevention**: Verify CDL file format (open in text editor, check for <TimeCode> or <ClipName> tags)

### Missing LUT in Chain

**Broken LUT Path:**
- **Symptom**: Image appears flat (log) or wrong (wrong display transform), LUT not applied
- **Cause**: LUT file missing, wrong LUT path (software can't find LUT), LUT format incompatibility
- **Fix**: Verify LUT exists in expected path, re-link LUT in software, convert LUT to compatible format
- **Prevention**: Test LUT path before shoot (apply LUT in software, verify on monitor), keep LUTs in consistent location

**LUT Not Applied in Correct Order:**
- **Symptom**: Image looks wrong (too dark/washed out), colors shifted (wrong LUT order)
- **Cause**: CDL applied after LUT (should be before), or multiple LUTs in wrong order
- **Fix**: Verify processing order: Camera Log → CDL → Look LUT → Display LUT → Output Transform
- **Prevention**: Document LUT chain in DIT report, use software that enforces correct order (LiveGrade, Resolve)

**LUT Size Mismatch:**
- **Symptom**: LUT loads but colors wrong (banding, clipping), software warning about LUT size
- **Cause**: LUT size mismatch (33x33x33 vs 65x65x65), software expects specific size
- **Fix**: Resize LUT using LUT Utility or Resolve (convert 33^3 to 65^3), regenerate LUT at correct size
- **Prevention**: Test LUT before shoot (load into software, apply to test footage, verify colors)

### Metadata Not Applied in Post

**CDL Embedded but Not Read:**
- **Symptom**: Post receives files with CDL metadata, but CDL not applied in grading software
- **Cause**: Grading software doesn't read embedded CDL (only reads sidecar files), or CDL in wrong location (header vs container)
- **Fix**: Export CDL as sidecar file (XML/CSV) in addition to embedding, import manually into grading software
- **Prevention**: Test CDL round-trip (on-set → post → back to on-set), verify CDL applied correctly

**ALE Import Errors:**
- **Symptom**: ALE won't import (Avid error: "malformed ALE"), or CDL columns missing
- **Cause**: ALE format wrong (wrong column headers, bad delimiters), or Avid version incompatibility
- **Fix**: Export ALE from LiveGrade or Resolve (tested format), verify ALE structure (open in text editor)
- **Prevention**: Test ALE import (export from on-set, import into Avid, verify CDL columns)

**Timecode Mismatch Between CDL and Clips:**
- **Symptom**: CDL applied to wrong shot (timecode offset), or no CDL applied (no timecode match)
- **Cause**: Camera timecode not jammed correctly, or CDL timecode format mismatch (DF vs NDF)
- **Fix**: Re-jam timecode on all cameras (master clock), verify timecode format (24fps = NDF, 29.97 = DF)
- **Prevention**: Jam-sync all cameras daily, document timecode format in camera report, test CDL linking before shoot

### Version Conflicts

**Multiple CDL Versions for Same Shot:**
- **Symptom**: Post receives multiple CDL files for same shot (different grades), confusion about which to use
- **Cause**: On-set grading iterated on same shot (multiple CDL exports), poor version control
- **Fix**: Establish version naming convention (v01, v02, v03), document which version is final
- **Prevention**: Use CDL management software (LiveGrade library, ShotHub), single source of truth

**LUT Version Mismatch:**
- **Symptom**: On-set using LUT v1, post using LUT v2 (different look), confusion about which is correct
- **Cause**: LUT updated during production (newer version created), not communicated to all departments
- **Fix**: Establish LUT library with version control, distribute LUT updates to all departments
- **Prevention**: Centralized LUT library (shared storage, cloud), email/notification for LUT updates

**Creative Changes After On-Set Grading:**
- **Symptom**: Director changes look in post (different from on-set CDL), on-set CDL abandoned
- **Cause**: Creative vision evolved (director/DP changes mind), or on-set grading too rushed
- **Fix**: Document on-set CDL as "reference" (not final), expect creative changes in post
- **Prevention**: Manage expectations (on-set CDL is starting point, not final grade), communicate early if look changes

## Mini Glossary

- **CDL (Color Decision List)**: Industry-standard format (ASC-CDL XML) for primary grade communication (SOP+SAT values) from on-set to post

- **ASC-CDL**: Standardized CDL format (Slope, Offset, Power, Saturation) supported by all major grading software (Resolve, Baselight, Lustre)

- **SOP (Slope, Offset, Power)**: CDL primary correction parameters: Slope (contrast), Offset (brightness/lift), Power (gamma/pivot)

- **SAT (Saturation)**: CDL saturation parameter (single value affecting all colors equally)

- **Grade Extraction**: Pulling CDL values from a graded shot (reverse engineering the primary corrections)

- **Metadata Embedding**: Writing CDL values into video file header (ProRes, DNxHD) or sidecar file (XML, CSV) for portability

- **LUT (Look-Up Table)**: 1D or 3D color transformation (display transform or creative look), applied after CDL in processing chain

- **Sidecar File**: Separate file (XML/CSV) containing CDL values, linked to video files by timecode or clip name

- **ALE (Avid Log Exchange)**: File format (.ale or .xml) containing shot metadata and CDL values, imported by editorial systems

- **Version Control**: System for managing multiple versions of CDLs/LUTs (naming conventions, backup, archiving)
