# 8.1 Overview of Major Codecs

## Theory: Codec Types and Compression Artifacts

### Visually Lossless vs Lossy Compression

**Visually Lossless:**
- **Definition**: Compression that introduces artifacts imperceptible to human eye under normal viewing conditions
- **Compression Ratio**: Typically 3:1 to 6:1 (ProRes 4444, DNxHR 444)
- **Quality**: Indistinguishable from uncompressed at 1:1 viewing (no visible artifacts)
- **Use Case**: Editing, mastering, intermediate codecs (post-production workflow)
- **Examples**: ProRes 4444, DNxHR 444, GoPro CineForm

**Lossy Compression:**
- **Definition**: Compression that introduces visible artifacts (banding, blocking, mosquito noise)
- **Compression Ratio**: 10:1 to 100:1+ (H.264, H.265, AV1)
- **Quality**: Visible artifacts at 1:1 viewing (especially in gradients, motion, textures)
- **Use Case**: Delivery, streaming, web, consumer codecs (final distribution)
- **Examples**: H.264, H.265, AV1, VP9

**Compression Artifacts:**
- **Banding**: Visible steps in smooth gradients (8-bit color, aggressive compression)
- **Macroblocking**: 8x8 or 16x16 pixel blocks visible (low bitrate, complex motion)
- **Mosquito Noise**: Artifacts around edges (ringing, especially in high-contrast areas)
- **Color Bleeding**: Color fringes around edges (chroma subsampling + compression)
- **Posterization**: Loss of color detail (reduced color precision, quantization)

### Intra-Frame vs Inter-Frame Compression

**Intra-Frame (I-Frame) Compression:**
- **Definition**: Each frame compressed independently (no reference to other frames)
- **Advantages**: Easy to edit (frame-accurate cutting), no compression propagation, robust to frame drops
- **Disadvantages**: Larger file sizes (less compression efficiency), higher bitrate
- **Use Case**: Editing codecs, camera originals (ProRes, DNxHD/HR)
- **Examples**: ProRes, DNxHD/HR, MJPEG, JPEG 2000

**Inter-Frame (Long-GOP) Compression:**
- **Definition**: Frames compressed using reference to other frames (I-frames, P-frames, B-frames)
- **GOP Structure**: Group of Pictures (e.g., GOP 12 = I BBP BBP BBP BBP)
  - **I-Frame (Intra)**: Keyframe, compressed independently (like a still image)
  - **P-Frame (Predicted)**: References previous I-frame or P-frame (stores only differences)
  - **B-Frame (Bi-directional)**: References previous and future frames (most efficient)
- **Advantages**: Smaller file sizes (higher compression efficiency), lower bitrate
- **Disadvantages**: Harder to edit (not frame-accurate, requires re-encoding), compression propagates (artifacts spread across GOP)
- **Use Case**: Delivery codecs, streaming, camera originals (H.264, H.265)
- **Examples**: H.264, H.265, AV1, VP9

**GOP (Group of Pictures) Impact:**
- **GOP Length**: Number of frames between I-frames (GOP 12 = I-frame every 12 frames)
- **Editing Impact**: Longer GOP = harder to edit (more re-encoding required for cuts)
- **Quality Impact**: Longer GOP = more efficient compression (smaller files), but artifacts propagate further
- **Typical GOP Values**:
  - **Editing**: GOP 1 (intra-frame only) or GOP 3 (easy editing)
  - **Streaming**: GOP 12-30 (balance quality and file size)
  - **Camera**: GOP 12-60 (varies by codec and bitrate)

### Codec Categories by Use Case

**Camera Codecs (Recording):**
- **RAW**: Uncompressed sensor data (maximum quality, large file sizes, requires debayer)
- **Log Compressed**: Compressed log encoding (visual quality, manageable file sizes)
- **Intra-Frame Compressed**: I-frame only (ProRes, DNxHD/HR), easy to edit
- **Long-GOP Compressed**: Inter-frame (H.264, H.265), efficient storage

**Editing Codecs (Post-Production):**
- **Visually Lossless**: ProRes, DNxHD/HR (easy editing, high quality)
- **Intermediate**: JPEG 2000, CineForm (visually lossless, cross-platform)
- **Proxy**: Low-bitrate versions for offline editing (ProRes Proxy, H.264)

**Delivery Codecs (Distribution):**
- **Broadcast**: ProRes 422 HQ, H.264 (high quality, broadcast standards)
- **Streaming**: H.264, H.265, AV1 (efficient compression, adaptive bitrate)
- **Web**: H.264 (universal compatibility), H.265 (better quality at lower bitrate)
- **Archive**: Uncompressed or visually lossless (long-term preservation)

## Practice: Major Codecs in Production

### ProRes Family (Apple)

**ProRes Variants:**
- **ProRes 4444**: 12-bit 4:4:4, alpha channel support, visually lossless (target: 330 Mbps for 4K)
  - **Use Case**: High-end mastering, compositing, VFX (best quality, large files)
  - **Compression**: Visually lossless, 3:1 compression ratio (from uncompressed 4:4:4)

- **ProRes 4444 XQ**: 12-bit 4:4:4, higher bitrate than standard 4444 (target: 500 Mbps for 4K)
  - **Use Case**: Extreme quality requirements (HDR, high-end VFX, archival)
  - **Compression**: Visually lossless, 2:1 compression ratio (closer to uncompressed)

- **ProRes 422 HQ**: 10-bit 4:2:2, high quality (target: 220 Mbps for 4K)
  - **Use Case**: Editing, mastering, broadcast (good quality, manageable file sizes)
  - **Compression**: Visually lossless, 5:1 compression ratio

- **ProRes 422**: 10-bit 4:2:2, standard quality (target: 147 Mbps for 4K)
  - **Use Case**: General editing, delivery (balance quality and file size)
  - **Compression**: Visually lossless, 7:1 compression ratio

- **ProRes 422 LT**: 10-bit 4:2:2, lower quality (target: 100 Mbps for 4K)
  - **Use Case**: Offline editing, proxy (smaller files, acceptable quality)
  - **Compression**: Lossy compression visible at 1:1, but acceptable for offline

- **ProRes 422 Proxy**: 8-bit 4:2:2, lowest quality (target: 45 Mbps for 4K)
  - **Use Case**: Proxy editing (smallest files, heavy compression artifacts)
  - **Compression**: Heavy lossy compression, visible artifacts, but fast for offline

**ProRes Advantages:**
- **Intra-Frame**: I-frame only (easy editing, frame-accurate)
- **Quality**: Visually lossless (except Proxy/LT which are lossy)
- **Performance**: Optimized for Apple hardware (hardware acceleration on Mac)
- **Industry Standard**: Widely supported (cameras, NLEs, delivery)

**ProRes Limitations:**
- **Apple Ecosystem**: Best performance on Mac (Windows performance slower)
- **File Size**: Larger than H.264/H.265 (more storage required)
- **Limited Bit Depth**: 10-bit for 422 variants (12-bit only for 4444)

### DNxHD/HR Family (Avid)

**DNxHD (720p/1080p only):**
- **DNxHD 444**: 10-bit 4:4:4, 440 Mbps for 1080p (visually lossless)
- **DNxHD 220**: 10-bit 4:2:2, 220 Mbps for 1080p (high quality editing)
- **DNxHD 145**: 8-bit 4:2:2, 145 Mbps for 1080p (standard editing)
- **DNxHD 36**: 8-bit 4:2:0, 36 Mbps for 1080p (offline proxy)

**DNxHR (4K/UHD support):**
- **DNxHR 444**: 12-bit 4:4:4, similar to ProRes 4444 (visually lossless)
- **DNxHR HQX**: 10-bit 4:2:2, 740 Mbps for 4K (high quality editing)
- **DNxHR HQ**: 10-bit 4:2:2, 550 Mbps for 4K (standard editing)
- **DNxHR SQ**: 8-bit 4:2:2, 365 Mbps for 4K (standard quality)
- **DNxHR LB**: 8-bit 4:2:0, 180 Mbps for 4K (low bitrate proxy)

**DNxHD/HR Advantages:**
- **Cross-Platform**: Good performance on Windows and Mac
- **Avid Integration**: Optimized for Media Composer (native editing)
- **Quality**: Visually lossless (similar to ProRes)
- **Open Source**: Free to implement (not proprietary like ProRes)

**DNxHD/HR Limitations:**
- **Less Common**: Not as widely supported as ProRes (especially in camera support)
- **Windows Performance**: Better than ProRes on Windows, but still not universal
- **File Size**: Similar to ProRes (larger than H.264/H.265)

### H.264/AVC (Advanced Video Coding)

**H.264 Profiles:**
- **High Profile**: 8-bit 4:2:0, up to 4:2:2 10-bit in some implementations (most common for delivery)
- **High 10 Profile**: 10-bit 4:2:0, better color precision (less banding)
- **High 4:2:2 Profile**: 10-bit 4:2:2, higher quality (less color bleeding)

**H.264 Use Cases:**
- **Camera Recording**: DSLRs, mirrorless cameras (H.264 8-bit 4:2:0)
- **Delivery**: Web, streaming, broadcast (H.264 most compatible codec)
- **Proxy Editing**: Low-bitrate H.264 for offline editing (small files)

**H.264 Advantages:**
- **Universal Compatibility**: Plays on all devices, browsers, players
- **Efficient Compression**: 50% smaller than H.262 (MPEG-2) at similar quality
- **Hardware Acceleration**: Encodes/decodes quickly (hardware support in GPUs)

**H.264 Limitations:**
- **8-bit Color**: Most implementations are 8-bit (banding in gradients)
- **4:2:0 Chroma**: Color subsampling (color bleeding, not ideal for grading)
- **Long-GOP**: Inter-frame compression (harder to edit, artifacts propagate)
- **Lossy Compression**: Visible artifacts at low bitrates (banding, blocking)

### H.265/HEVC (High Efficiency Video Coding)

**H.265 Improvements over H.264:**
- **Compression Efficiency**: 50% better than H.264 (same quality at half bitrate)
- **10-bit/12-bit Support**: Better color precision (less banding)
- **4:2:2 Chroma**: Available (less color bleeding than 4:2:0)
- **Higher Resolution**: Optimized for 4K/8K (more efficient than H.264 at high resolutions)

**H.265 Use Cases:**
- **Camera Recording**: High-end cameras (H.265 10-bit 4:2:0 or 4:2:2)
- **Delivery**: 4K streaming, UHD broadcast (better quality than H.264 at lower bitrate)
- **Archive**: Smaller files than H.264 (similar quality, less storage)

**H.265 Advantages:**
- **Efficient Compression**: Smaller files than H.264 (50% reduction at similar quality)
- **High Quality**: 10-bit/12-bit support (better color precision)
- **Future-Proof**: Standard for 4K/8K (replacing H.264 for high-resolution delivery)

**H.265 Limitations:**
- **Compatibility**: Not as universal as H.264 (older devices don't support H.265)
- **Encoding Speed**: Slower to encode than H.264 (more complex compression)
- **Licensing**: More expensive licensing fees than H.264

### AV1 (AOMedia Video 1)

**AV1 Features:**
- **Compression Efficiency**: 30% better than H.265 (same quality at lower bitrate)
- **Royalty-Free**: No licensing fees (unlike H.264/H.265)
- **10-bit/12-bit Support**: High bit depth (better color precision)
- **4:2:0/4:2:2/4:4:4**: Full chroma subsampling options

**AV1 Use Cases:**
- **Streaming**: Netflix, YouTube (adopting AV1 for better quality at lower bitrate)
- **Web**: Modern browsers support AV1 (Chrome, Firefox, Edge)
- **Future Delivery**: Replacing H.264/H.265 for web streaming

**AV1 Advantages:**
- **Best Compression**: Most efficient codec available (smallest files at high quality)
- **Royalty-Free**: No licensing fees (free to use)
- **Open Source**: Developed by Alliance for Open Media (AOM)

**AV1 Limitations:**
- **Encoding Speed**: Very slow to encode (hardware acceleration still emerging)
- **Compatibility**: Not supported on older devices/browsers (requires modern hardware)
- **Adoption**: Still emerging (not as widespread as H.264/H.265)

### JPEG XS (ISO/IEC 21122)

**JPEG XS Features:**
- **Visually Lossless**: Mezzanine codec (light compression, artifacts imperceptible)
- **Low Latency**: <1 frame delay (faster than H.264/H.265)
- **High Quality**: 4:4:4 or 4:2:2 chroma, 10/12-bit color
- **Compression Ratio**: 2:1 to 6:1 (much lighter than H.264/H.265)

**JPEG XS Use Cases:**
- **Live Broadcasting**: Low latency for live production (sports, news)
- **IP Video**: ST 2110 infrastructure (visually lossless over IP networks)
- **Wireless Monitoring**: Teradek Bolt 4K X (uncompressed quality over wireless)

**JPEG XS Advantages:**
- **Quality**: Visually lossless (no visible artifacts)
- **Speed**: Very low latency (suitable for live production)
- **Efficiency**: Better compression than uncompressed (2:1 to 6:1 ratio)

**JPEG XS Limitations:**
- **Limited Adoption**: Newer codec (not as widely supported as ProRes/H.264)
- **Higher Bitrate**: Higher bitrate than H.264/H.265 (requires more bandwidth)
- **Hardware**: Requires specialized hardware for encoding/decoding

## Failure Modes: Codec Selection and Compatibility

### Wrong Codec for Delivery

**Incompatible Codec for Platform:**
- **Symptom**: Video won't play on target platform (web, broadcast, cinema)
- **Cause**: Codec not supported (ProRes for web, H.265 for old DVD players, etc.)
- **Fix**: Re-encode to correct codec (H.264 for web, ProRes for broadcast, etc.)
- **Prevention**: Research delivery specifications before shoot (codec, bitrate, color space)

**Insufficient Quality for Delivery:**
- **Symptom**: Visible artifacts (banding, blocking) in final delivery
- **Cause**: Codec too lossy (H.264 low bitrate, 8-bit color), or wrong codec variant (ProRes LT instead of HQ)
- **Fix**: Re-encode to higher quality codec (ProRes 422 HQ, H.264 high bitrate)
- **Prevention**: Test codec before final delivery (encode sample, check quality on target display)

**Overspec'd Codec (Unnecessary Quality):**
- **Symptom**: File sizes unnecessarily large (wasted storage, slower transfer)
- **Cause**: Using higher quality codec than needed (ProRes 4444 for web delivery)
- **Fix**: Use appropriate codec (H.264 for web, ProRes 422 for editing, ProRes 4444 for VFX)
- **Prevention**: Match codec to use case (editing, delivery, streaming, archival)

### Generation Loss

**Repeated Encoding (Loss Accumulation):**
- **Symptom**: Quality degrades with each encode (artifacts accumulate, colors shift)
- **Cause**: Editing/grading in lossy codec (H.264), then re-encoding to H.264 for delivery (generation loss)
- **Fix**: Edit in visually lossless codec (ProRes, DNxHR), encode to delivery codec only once
- **Prevention**: Workflow: Camera RAW → ProRes/DNxHR (editing) → H.264/H.265 (delivery)

**Transcoding Between Lossy Codecs:**
- **Symptom**: Severe quality loss (blocking, banding, color shifts)
- **Cause**: Converting H.264 to H.265 (both lossy, artifacts compounded)
- **Fix**: Go back to camera original (RAW or high-quality ProRes), then encode to target codec
- **Prevention**: Archive camera originals (don't delete RAW/ProRes after editing)

**Re-Grading Lossy Codecs:**
- **Symptom**: Banding, blocking, color degradation after grading
- **Cause**: Grading H.264 footage (already lossy, grading amplifies artifacts)
- **Fix**: Grade from camera original (RAW or high-quality ProRes), then encode to lossy
- **Prevention**: Always grade from highest quality source available (RAW > ProRes > H.264)

### Compatibility Issues

**Codec Not Supported by Player/Platform:**
- **Symptom**: Video won't play, or plays with errors (stuttering, artifacts)
- **Cause**: Player doesn't support codec (QuickTime doesn't support H.265 natively, old media players)
- **Fix**: Use compatible codec (H.264 for universal playback, or update player/software)
- **Prevention**: Test playback on target platform before delivery (web player, broadcast server)

**Color Space Mismatch:**
- **Symptom**: Colors wrong (washed out, oversaturated) on target display
- **Cause**: Codec color space mismatch (Rec.709 footage displayed on P3 monitor)
- **Fix**: Convert to correct color space (use color management, LUTs)
- **Prevention**: Document color space (Rec.709, P3, HDR), verify on target display

**Bit Depth Mismatch:**
- **Symptom**: Banding on display (smooth gradients show visible steps)
- **Cause**: 10-bit footage displayed on 8-bit pipeline (monitor, player, codec)
- **Fix**: Use 10-bit display pipeline (10-bit monitor, codec that supports 10-bit)
- **Prevention**: Test bit depth (display 10-bit gradient, verify no banding)

### Performance Issues

**Codec Too Heavy for Hardware:**
- **Symptom**: Stuttering playback, slow rendering, system crashes
- **Cause**: Codec too demanding (H.265 on old computer, ProRes 4444 on slow storage)
- **Fix**: Use lighter codec (H.264 for editing on slow computers, ProRes 422 instead of 4444)
- **Prevention**: Test codec performance before shoot (playback test footage, check system specs)

**Storage Bottleneck:**
- **Symptom**: Dropped frames during playback (storage can't keep up with bitrate)
- **Cause**: Storage too slow (HDD for high-bitrate ProRes 4444, or 4K H.264)
- **Fix**: Use faster storage (NVMe SSD, RAID), or lower bitrate codec (ProRes 422 instead of 4444)
- **Prevention**: Calculate data rate before shoot (ensure storage can handle codec bitrate)

**CPU Bottleneck (Encoding/Decoding):**
- **Symptom**: Slow encoding (H.265 takes hours), stuttering playback
- **Cause**: CPU can't handle codec complexity (H.265/AV1 require powerful CPU)
- **Fix**: Use hardware acceleration (GPU encoding/decoding), or use lighter codec (H.264)
- **Prevention**: Benchmark codec performance (encode test footage, check speed)

## Mini Glossary

- **Visually Lossless**: Compression introducing artifacts imperceptible to human eye (3:1 to 6:1 ratio, e.g., ProRes 4444)

- **Lossy Compression**: Compression introducing visible artifacts (10:1 to 100:1+ ratio, e.g., H.264, H.265)

- **Intra-Frame**: Each frame compressed independently (I-frame only, easy editing, larger files, e.g., ProRes)

- **Inter-Frame**: Frames compressed using references to other frames (I/P/B-frames, smaller files, harder to edit, e.g., H.264)

- **Generation Loss**: Quality degradation from repeated encoding (accumulating artifacts, avoid multiple transcodes)

- **GOP (Group of Pictures)**: Structure of inter-frame compression (I-frame + P-frames + B-frames, longer GOP = more efficient but harder to edit)

- **Bitrate**: Data rate (Mbps) determining quality/file size (higher bitrate = better quality but larger files)

- **I-Frame (Intra)**: Keyframe compressed independently (starting point for GOP, like a still image)

- **P-Frame (Predicted)**: References previous I-frame or P-frame (stores only differences, more efficient)

- **B-Frame (Bi-directional)**: References previous and future frames (most efficient, increases latency)
