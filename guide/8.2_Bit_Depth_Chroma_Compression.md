# 8.2 Bit-Depth, Chroma Subsampling, and Compression

## Theory: Digital Color Precision

### Bit Depth Fundamentals

**What is Bit Depth?**
- **Definition**: Number of bits used to represent each color channel (red, green, blue)
- **Impact**: Determines number of possible color values (2^bit depth = number of shades)
- **Color Precision**: Higher bit depth = more shades, smoother gradients, less banding

**Bit Depth Values:**
- **8-bit**: 2^8 = 256 shades per channel (16.7 million total colors)
  - **Limitation**: Visible banding in smooth gradients (sky, skin highlights)
  - **Use Case**: Delivery codec (H.264 web streaming), consumer displays

- **10-bit**: 2^10 = 1,024 shades per channel (1.07 billion total colors)
  - **Advantage**: Smooth gradients, less banding, better color precision
  - **Use Case**: Editing codec (ProRes 422, DNxHR), color grading, HDR

- **12-bit**: 2^12 = 4,096 shades per channel (68.7 billion total colors)
  - **Advantage**: Excellent gradients, minimal banding, best for grading
  - **Use Case**: RAW video, high-end production, mastering

- **16-bit**: 2^16 = 65,536 shades per channel (281 trillion total colors)
  - **Advantage**: Virtually infinite gradients (far beyond human perception)
  - **Use Case**: Intermediate codecs (ProRes 4444 XQ), compositing, VFX

**Banding:**
- **Cause**: Insufficient bit depth (8-bit) creates visible steps in gradients
- **Visible In**: Smooth gradients (sky, walls, skin highlights), color transitions
- **Fix**: Use 10-bit or higher (ProRes 422 10-bit, DNxHR 10-bit, H.265 10-bit)
- **Workaround**: Add dithering (noise) to mask banding (but increases file size)

**Bit Depth in Practice:**
- **Capture**: 12-bit or 14-bit RAW (maximum quality, requires debayer)
- **Editing**: 10-bit ProRes/DNxHR (balance quality and performance)
- **Delivery**: 8-bit H.264 (universal compatibility, but banding possible)
- **HDR**: 10-bit minimum (PQ/HLG require 10-bit for smooth gradients)

### Chroma Subsampling

**What is Chroma Subsampling?**
- **Definition**: Reducing color resolution (chroma) while keeping full luma (brightness) resolution
- **Human Vision**: Eyes more sensitive to brightness (luma) than color (chroma)
- **Purpose**: Reduce data (lower bitrate, smaller files) with minimal perceived quality loss

**Chroma Subsampling Notation:**
- **Format**: J:a:b (J = horizontal luma samples, a = chroma samples on first line, b = chroma samples on second line)
- **Ratio**: (J + a + b) / (J * 2) = chroma subsampling ratio relative to 4:4:4

**Common Chroma Subsampling Formats:**

**4:4:4 (No Subsampling):**
- **Color Resolution**: Full chroma resolution (same as luma)
- **Quality**: Best color accuracy (no color bleeding, sharp color edges)
- **Data Rate**: Highest (1.5x more data than 4:2:2)
- **Use Case**: VFX, compositing, green screen, color grading (need precise color)

**4:2:2 (Horizontal Subsampling):**
- **Color Resolution**: Half horizontal chroma resolution (full vertical)
- **Quality**: Excellent color quality (minimal color bleeding, acceptable for most grading)
- **Data Rate**: 33% less than 4:4:4 (standard for editing codecs)
- **Use Case**: Editing, color grading, broadcast quality (ProRes 422, DNxHR)

**4:2:0 (Horizontal and Vertical Subsampling):**
- **Color Resolution**: Quarter chroma resolution (half horizontal, half vertical)
- **Quality**: Visible color bleeding (edges, fine details), not ideal for grading
- **Data Rate**: 50% less than 4:4:4 (standard for delivery codecs)
- **Use Case**: Delivery codec (H.264, H.265), web streaming, consumer content

**4:1:1 (Heavy Subsampling - Legacy):**
- **Color Resolution**: Quarter horizontal chroma resolution (full vertical)
- **Quality**: Significant color bleeding (obsolete for modern production)
- **Data Rate**: Very low (legacy DV format)
- **Use Case**: Obsolete (historical only, not used in modern production)

**4:2:2:4 (4:4:4 with Alpha Channel):**
- **Color Resolution**: Full chroma resolution (4:4:4)
- **Alpha**: Additional channel for transparency (compositing, VFX)
- **Use Case**: Compositing, VFX, motion graphics (ProRes 4444)

### Quantization and Compression

**Quantization:**
- **Definition**: Mapping continuous color values to discrete levels (determined by bit depth)
- **Impact**: Lower bit depth = fewer levels = more quantization error (banding, posterization)
- **Example**: 8-bit quantizes 10-bit data (losing precision, introducing banding)

**Quantization Error:**
- **Cause**: Rounding errors during compression (8-bit can't represent 10-bit values accurately)
- **Visible As**: Banding, posterization, color shifts
- **Reduction**: Higher bit depth (10-bit, 12-bit) reduces quantization error

**Compression Ratio:**
- **Definition**: Ratio of uncompressed size to compressed size (e.g., 10:1 compression)
- **Calculation**: Uncompressed bitrate / Compressed bitrate = Compression ratio
- **Trade-off**: Higher compression = smaller files but more artifacts

**Compression Ratios by Codec:**
- **Visually Lossless**: 3:1 to 6:1 (ProRes 4444, DNxHR 444)
- **Editing Codecs**: 5:1 to 10:1 (ProRes 422, DNxHR HQ)
- **Delivery Codecs**: 20:1 to 100:1+ (H.264, H.265, AV1)

**Compression Artifacts:**
- **Banding**: Visible steps in gradients (low bit depth, aggressive compression)
- **Blocking**: 8x8 or 16x16 pixel blocks (low bitrate, inter-frame compression)
- **Mosquito Noise**: Artifacts around edges (ringing, high-frequency detail loss)
- **Color Bleeding**: Color fringes around edges (chroma subsampling + compression)

## Practice: Bit Depth and Chroma Selection

### Bit Depth Selection

**Capture Bit Depth:**
- **RAW Video**: 12-bit or 14-bit (maximum quality, flexible post-production)
  - **Advantages**: Maximum color precision, highlight/shadow recovery, white balance flexibility
  - **Disadvantages**: Large file sizes, requires debayer, slower workflow

- **Log Compressed**: 10-bit (good quality, manageable file sizes)
  - **Advantages**: Smaller files than RAW, easier editing, still good for grading
  - **Disadvantages**: Less highlight/shadow recovery than RAW, locked white balance

- **8-bit**: Consumer cameras, low-end production
  - **Advantages**: Smallest files, faster workflow, universal compatibility
  - **Disadvantages**: Banding in gradients, limited grading flexibility

**Editing Bit Depth:**
- **10-bit**: Recommended for editing and grading (ProRes 422, DNxHR)
  - **Why**: Smooth gradients, less banding, better color precision
  - **Use Case**: Color grading, HDR delivery, high-quality production

- **8-bit**: Acceptable for offline editing (proxy editing)
  - **Why**: Smaller files, faster editing, acceptable for reference
  - **Use Case**: Offline editing, documentary, news (quick turnaround)

**Delivery Bit Depth:**
- **8-bit**: Standard for web streaming (H.264 8-bit)
  - **Why**: Universal compatibility, smaller files (faster streaming)
  - **Limitation**: Banding possible in gradients (especially HDR content)

- **10-bit**: Required for HDR delivery (PQ/HLG)
  - **Why**: HDR needs 10-bit for smooth gradients (higher dynamic range)
  - **Use Case**: Dolby Vision, HDR10+, HDR broadcast

### Chroma Subsampling Selection

**4:4:4 (No Subsampling):**
- **When to Use**: VFX, compositing, green screen, high-end color grading
- **Benefits**: Precise color (no color bleeding), sharp edges, best for keying
- **Codecs**: ProRes 4444, DNxHR 444, uncompressed
- **Cost**: Larger file sizes (1.5x more data than 4:2:2)

**4:2:2 (Horizontal Subsampling):**
- **When to Use**: Editing, color grading, broadcast quality
- **Benefits**: Excellent color quality (minimal color bleeding), standard for production
- **Codecs**: ProRes 422, DNxHR, XAVC-I, some H.265 implementations
- **Cost**: Moderate file sizes (33% more data than 4:2:0)

**4:2:0 (Horizontal and Vertical Subsampling):**
- **When to Use**: Delivery codec, web streaming, consumer content
- **Benefits**: Smallest files (50% less data than 4:4:4), efficient streaming
- **Codecs**: H.264, H.265, AV1 (most consumer delivery)
- **Cost**: Color bleeding, not ideal for grading or VFX

**Chroma Subsampling Decision Tree:**
```
Need precise color (VFX, green screen)?
├─ Yes → 4:4:4 (ProRes 4444, DNxHR 444)
└─ No → Need color grading?
    ├─ Yes → 4:2:2 (ProRes 422, DNxHR)
    └─ No → 4:2:0 (H.264/H.265 delivery)
```

### Compression Quality Settings

**Bitrate Selection:**
- **Rule of Thumb**: Higher bitrate = better quality (but larger files)
- **4K Bitrates**:
  - **ProRes 422 HQ**: 220 Mbps (visually lossless)
  - **ProRes 422**: 147 Mbps (good quality)
  - **ProRes 422 LT**: 100 Mbps (acceptable quality)
  - **H.264 (High Quality)**: 50-80 Mbps (good delivery quality)
  - **H.264 (Web Streaming)**: 10-20 Mbps (acceptable for web)

- **1080p Bitrates**:
  - **ProRes 422 HQ**: 55 Mbps (visually lossless)
  - **ProRes 422**: 36 Mbps (good quality)
  - **H.264 (High Quality)**: 10-20 Mbps (good delivery)
  - **H.264 (Web Streaming)**: 5-10 Mbps (acceptable for web)

**Constant Bitrate (CBR) vs Variable Bitrate (VBR):**
- **CBR (Constant Bitrate)**:
  - **Definition**: Same bitrate throughout (regardless of scene complexity)
  - **Advantage**: Predictable file sizes, better for streaming (consistent bandwidth)
  - **Disadvantage**: Wastes bitrate on simple scenes, insufficient for complex scenes

- **VBR (Variable Bitrate)**:
  - **Definition**: Bitrate adjusts based on scene complexity (more for complex scenes, less for simple)
  - **Advantage**: Better quality per file size (allocates bitrate where needed)
  - **Disadvantage**: Less predictable file sizes, not ideal for streaming (bandwidth spikes)

**Compression Quality Tiers (H.264/H.265):**
- **Low Quality**: High compression (low bitrate, small files, visible artifacts)
- **Medium Quality**: Moderate compression (acceptable for web streaming)
- **High Quality**: Low compression (good for delivery, minimal artifacts)
- **Visually Lossless**: Very low compression (artifacts imperceptible, large files)

## Failure Modes: Banding, Bleeding, Artifacts

### Banding in Gradients

**Visible Steps in Gradients:**
- **Symptom**: Smooth gradients (sky, walls) show visible steps/bands
- **Cause**: 8-bit color (insufficient precision), aggressive compression, steep gradients
- **Fix**: Use 10-bit or higher (ProRes 422 10-bit, H.265 10-bit), add dithering (noise) to mask banding
- **Prevention**: Shoot 10-bit or higher, avoid steep gradients (add subtle fill light to smooth transitions)

**Banding in Sky:**
- **Symptom**: Blue sky shows horizontal bands (visible steps in brightness/color)
- **Cause**: 8-bit codec + gradient compression (H.264 low bitrate)
- **Fix**: Use 10-bit codec (ProRes 422, H.265 10-bit), increase bitrate, add dithering
- **Prevention**: Shoot 10-bit, avoid overexposing sky (keep detail, reduce gradient steepness)

**Banding in Skin Tones:**
- **Symptom**: Skin highlights show bands (especially in cheekbones, forehead)
- **Cause**: 8-bit color + aggressive lighting (steep highlight falloff)
- **Fix**: Use 10-bit codec (ProRes 422 10-bit), soften lighting (diffusion, fill light)
- **Prevention**: Expose for highlights (avoid clipping), use 10-bit capture

**Solarization (Posterization):**
- **Symptom**: Color shifts in highlights (flesh tones shift to magenta, etc.)
- **Cause**: Insufficient bit depth (8-bit) + overexposure (clipping highlights)
- **Fix**: Use 10-bit or higher, expose for highlights (protect highlight detail)
- **Prevention**: Use 10-bit capture, monitor exposure (waveform, false color)

### Color Bleeding

**Color Fringes Around Edges:**
- **Symptom**: Color bleeding around high-contrast edges (red/blue halos)
- **Cause**: 4:2:0 chroma subsampling (quarter color resolution)
- **Fix**: Use 4:2:2 (ProRes 422, DNxHR) or 4:4:4 (ProRes 4444) for capture/editing
- **Prevention**: Shoot 4:2:2 or 4:4:4, avoid 4:2:0 for grading or VFX

**Soft Color Edges:**
- **Symptom**: Color edges not sharp (chroma blur, especially in fine details)
- **Cause**: 4:2:0 chroma subsampling (color resolution quarter of luma)
- **Fix**: Use 4:2:2 (sharper color edges), or 4:4:4 (crisp color edges)
- **Prevention**: Avoid 4:2:0 for content with fine color detail (textiles, patterns)

**Green Screen Bleeding:**
- **Symptom**: Green spill around subject (green edges, keying issues)
- **Cause**: 4:2:0 chroma subsampling (color bleeding into subject edges)
- **Fix**: Use 4:4:4 for green screen capture (ProRes 4444, DNxHR 444)
- **Prevention**: Always shoot 4:4:4 for green screen (critical for clean keys)

### Compression Artifacts

**Macroblocking:**
- **Symptom**: 8x8 or 16x16 pixel blocks visible (especially in flat areas, motion)
- **Cause**: Low bitrate (<20Mbps for H.264), long GOP, complex motion
- **Fix**: Increase bitrate (50Mbps+ for H.264 4K), use shorter GOP (I-frame only for editing)
- **Prevention**: Use higher bitrate codec (ProRes, DNxHR) for capture/editing

**Mosquito Noise (Ringing):**
- **Symptom**: Artifacts around high-contrast edges (shimmering, noise-like pattern)
- **Cause**: Aggressive compression (low bitrate, high quantization)
- **Fix**: Increase bitrate, use higher quality preset (less compression)
- **Prevention**: Use visually lossless codec (ProRes, DNxHR) for capture/editing

**Color Shifting:**
- **Symptom**: Colors change hue or saturation (skin tones shift, greens become cyan)
- **Cause**: Chroma subsampling (4:2:0) + compression artifacts, quantization error
- **Fix**: Use 4:2:2 or 4:4:4 chroma (reduce color bleeding), higher bitrate
- **Prevention**: Shoot 4:2:2 or 4:4:4, use 10-bit or higher (reduce quantization error)

### Insufficient Bit Depth

**8-bit Limitations:**
- **Symptom**: Banding in gradients, color shifts, limited grading flexibility
- **Cause**: 8-bit codec (H.264, ProRes Proxy) insufficient for smooth gradients
- **Fix**: Use 10-bit codec (ProRes 422, DNxHR, H.265 10-bit)
- **Prevention**: Always shoot 10-bit or higher for color grading

**8-bit for HDR:**
- **Symptom**: Severe banding in HDR highlights (especially in bright sky, specular highlights)
- **Cause**: HDR needs 10-bit or higher (8-bit insufficient for HDR dynamic range)
- **Fix**: Use 10-bit HDR codec (PQ/HLG 10-bit), avoid 8-bit for HDR
- **Prevention**: HDR requires minimum 10-bit (PQ/HLG standards)

**10-bit for SDR:**
- **Symptom**: Overkill (larger files, minimal quality improvement over 8-bit for SDR)
- **Cause**: 10-bit capture for 8-bit delivery (unnecessary quality for most SDR content)
- **Fix**: 8-bit acceptable for SDR delivery (but use 10-bit for editing/grading)
- **Prevention**: Match capture bit depth to delivery (10-bit capture for 10-bit HDR, 8-bit acceptable for 8-bit SDR)

## Mini Glossary

- **Bit Depth**: Number of bits per color channel (8-bit = 256 shades, 10-bit = 1,024 shades, 12-bit = 4,096 shades)

- **Chroma Subsampling**: Reducing color resolution (chroma) while keeping full brightness (luma) resolution (4:4:4 = no subsampling, 4:2:2 = half horizontal, 4:2:0 = quarter)

- **Quantization**: Mapping continuous color values to discrete levels (determined by bit depth, lower bit depth = more quantization error)

- **Compression Ratio**: Ratio of uncompressed size to compressed size (10:1 = compressed to 1/10th original size)

- **Banding**: Visible steps in smooth gradients due to insufficient bit depth (8-bit) or aggressive compression

- **Artifact**: Visual defect from compression (blocking, mosquito noise, color bleeding, banding)

- **4:4:4**: No chroma subsampling (full color resolution, best for VFX/compositing)

- **4:2:2**: Half horizontal chroma resolution (standard for editing codecs, good for grading)

- **4:2:0**: Quarter chroma resolution (standard for delivery codecs, not ideal for grading)

- **Posterization**: Loss of color detail due to quantization (similar to banding, visible as color shifts/steps)
