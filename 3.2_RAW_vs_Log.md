# 3.2 RAW Capture vs. Log Capture

## Theory: Sensor Data Acquisition Paths

### RAW Capture Architecture

RAW capture preserves the unprocessed or minimally processed sensor data before most image processing pipeline (ISP) operations. The fundamental difference is **where** the logarithmic encoding happens in the signal chain.

**RAW Signal Flow:**

```
Scene Light → Lens → Sensor → ADC → RAW File
                            ↓
                     [Optional: Minimal Processing]
                     - Black level subtraction
                     - Linearization (defective pixel correction)
                     - Basic metadata embedding
```

**Log-Encoded Signal Flow:**

```
Scene Light → Lens → Sensor → ADC → ISP Pipeline → Log Encoding → Codec → File
                                        ↓
                            [Full Processing Chain]
                            - Demosaicing
                            - White Balance application
                            - Color Matrix Transform
                            - Noise Reduction
                            - Sharpening
                            - Log Gamma application
                            - Color Space Conversion
```

### Bayer Pattern and Color Filter Array (CFA)

Most digital cinema cameras use a Bayer CFA arrangement:

```
Bayer Pattern (2x2 repeating unit):
┌─────────────┬─────────────┐
│  Green      │   Red       │
│  (50% site) │   (25% site)│
├─────────────┼─────────────┤
│  Blue       │   Green     │
│  (25% site) │   (50% site)│
└─────────────┴─────────────┘

Sampling Ratios:
- Green: 50% (luminance information)
- Red: 25%
- Blue: 25%
```

**CFA Spectral Transmission:**

```
I_measured(x,y,λ) = ∫ I_scene(λ) × CFA(x,y,λ) × QE(λ) dλ

Where:
- I_measured: Raw sensor value at pixel (x,y)
- I_scene: Scene spectral radiance
- CFA: Color filter array spectral transmission
- QE: Sensor quantum efficiency (wavelength-dependent)
- Integration over visible spectrum (~400-700nm)
```

**Implications:**
- Green channel has 2× sampling of red/blue
- Luminance resolution is effectively √2 higher than chrominance resolution
- Demosaicing required to reconstruct missing color values

### Demosaicing Algorithms

**Fundamental Problem:** Each photosite captures ONE color value, but we need THREE (R, G, B) for each pixel location.

**Common Demosaicing Approaches:**

1. **Bilinear Interpolation (Simple, Low Quality):**
```
For missing R at G pixel location:
R_interp(x,y) = (R(x-1,y) + R(x+1,y) + R(x,y-1) + R(x,y+1)) / 4
```

2. **Variable Number of Gradients (VNG) - Better:**
```
Adaptive interpolation based on local gradients:
- Horizontal interpolation if vertical gradient > horizontal gradient
- Vertical interpolation if horizontal gradient > vertical gradient
- Diagonal interpolation if both gradients similar
```

3. **Patterned Pixel Grouping (PPG) - High Quality:**
```
Uses larger kernel (5×5 or 7×7) with edge detection:
G_interp = Σ(w_i × G_i) / Σ(w_i)
where w_i are weights based on edge similarity
```

4. **Frequency-Domain Methods - Highest Quality:**
```
- Luminance extracted from high-frequency G channel
- Chrominance extracted from low-frequency R-B differences
- Minimizes aliasing artifacts
- Computationally expensive
```

**Demosaicing Artifacts:**
- **Moiré:** High-frequency patterns create false colors
- **Zippering:** Stair-step artifacts along diagonal edges
- **Color Fringing:** Chromatic aberration exacerbated by interpolation

### White Balance in RAW vs. Log

**RAW White Balance (Metadata Operation):**

```
Digital gain applied during decode:
R_WB = R_raw × gain_R
G_WB = G_raw × gain_G
B_WB = B_raw × gain_B

Where gains are typically 1.0-4.0 to equalize channel responses
```

**Advantage:** No information loss, fully reversible

**Log White Balance (Baked-In):**

```
WB applied BEFORE log encoding, permanently altering values:
R_log = log_gain(R_raw × gain_R)
G_log = log_gain(G_raw × gain_G)
B_log = log_gain(B_raw × gain_B)

Cannot be fully reversed after encoding
```

**Mathematical Impact:**
```
WB error in RAW: Correctable with ±0.5 stop accuracy
WB error in Log: Permanent color cast, limited recovery

Example: 3200K footage shot with 5600K WB
- RAW: Apply 0.56× blue gain, 1.44× red gain (minimal quality loss)
- Log: Permanent orange cast, blue channel clipped, difficult recovery
```

### RAW Metadata Structure

Typical RAW file metadata includes:

```
Header Information:
- Sensor dimensions (active pixels)
- Black level (pedestal) offset
- White clipping level
- Analog gain (ISO setting)
- White balance coefficients (R, G, B gains)

Image Data:
- Compressed Bayer pattern values
- Optional compression ratios (3:1, 5:1, 12:1)

Sidecar Information:
- Shooting time/date
- Lens metadata
- GPS data
- Camera settings
- Thumbnail/previews
```

## Practice: RAW Decode Settings and Quality Comparisons

### RAW Development Parameters

**1. Decode Resolution:**

```
Full Sensor (e.g., 4.6K on RED): Maximum quality, large files
2K/1080p: Faster processing, reduced quality
1/2 Resolution: Proxy editing, final from full resolution
```

**2. Demosaic Algorithm Selection:**

```
Quality vs. Speed Trade-off:

Fast Processing (Bilinear):
- Real-time playback possible
- Visible artifacts on fine detail
- Acceptable for offline editing

Standard Quality (VNG/Adaptive):
- Good balance
- Minor artifacts only on extreme patterns
- Typical for dailies

High Quality (PPG/Frequency-domain):
- Near-optimal reconstruction
- Minimal aliasing
- Required for VFX work and final grade
```

**3. Color Space and Gamma:**

```
Common Decode Options:

Camera Native (e.g., REDWideGamutRGB/Log3G10):
- Maximum gamut
- Log gamma for maximum DR
- Best for archiving

ACES (ACES2065-1):
- Device-independent
- Linear light
- Standard for VFX pipelines

Rec.709 (Gamma 2.4):
- Video standard
- Limited gamut
- Faster grading but less flexibility
```

**4. Highlight Roll-off:**

```
Hard Clip: No rolloff, maximum detail
Soft Clip: Smooth rolloff, more "film-like" but loses subtle highlight detail
Custom: User-defined knee point and slope
```

### RAW vs. Log Quality Comparison

**Metric: Signal-to-Noise Ratio at 18% Gray**

| Format | SNR (dB) | Effective DR | Color Accuracy | Flexibility |
|--------|----------|--------------|----------------|-------------|
| RAW (12-bit uncompressed) | 58-62 | 15+ stops | ±1000K WB error | Full ISO, WB, curve |
| RAW (12-bit 3:1 compressed) | 56-60 | 15 stops | ±800K WB error | Full ISO, WB, curve |
| ProRes 4444 Log (10-bit) | 54-57 | 13-14 stops | ±200K WB error | Limited curve only |
| ProRes 422 Log (10-bit) | 52-55 | 12-13 stops | ±150K WB error | Limited curve only |
| H.264 Log (8-bit) | 48-52 | 10-11 stops | ±100K WB error | Very limited |

**Practical Quality Differences:**

1. **Shadow Push:**
```
Scenario: 2-stop underexposure, push to normal

RAW 12-bit: SNR penalty ~3dB, still acceptable
ProRes Log 10-bit: SNR penalty ~6dB, visible noise
H.264 Log 8-bit: SNR penalty ~9dB, severe noise and banding
```

2. **White Balance Correction:**
```
Scenario: 3200K lighting, accidentally set WB to 5600K

RAW: Perfect recovery, apply metadata correction
ProRes Log: Permanent orange cast, blue channel starvation
H.264 Log: Severe color cast, artifacts after correction
```

3. **Highlight Recovery:**
```
Scenario: Accidental 0.5-stop overexposure

RAW: Recoverable with slight highlight rolloff
ProRes Log: Partially recoverable with curve adjustment
H.264 Log: Clipped highlights unrecoverable
```

### Log Bake-In Decision Matrix

**Choose Log When:**
- Turnaround time critical (no RAW processing bottleneck)
- Limited storage/bandwidth for massive RAW files
- Straightforward delivery (no extreme color grades)
- Collaborative workflow with non-technical team
- Camera supports high-quality log (10+ bit external)

**Choose RAW When:**
- VFX work requiring clean keys and maximum detail
- Unknown delivery formats (future-proofing)
- Extreme color grading planned
- Possibility of major WB/exposure errors
- Archival requirements for maximum quality
- Camera has limited internal log quality

**Hybrid Approach:**
```
Shoot RAW but bake-in:
- Rec.709 LUT for dailies/fast turnaround
- Separate camera-original RAW archived for final grade

Advantage:
- Fast editorial workflow
- Full RAW quality preserved
- Flexibility for creative changes
```

## Failure Modes: Common RAW and Log Issues

### RAW-Specific Failures

**1. Incorrect Demosaicing Choice**

**Symptoms:**
- False color moiré on fine patterns (fabrics, brickwork)
- Jagged edges on diagonal lines
- Loss of fine detail

**Detection:**
```
Test chart: Siemens Star or zone plate
Visual inspection: Rotating artifacts, color fringing
Measurement: MTF (Modulation Transfer Function) drop
```

**Solution:**
```
Use high-quality demosaic for critical shots:
- VNG for general use
- Frequency-domain for VFX
- Accept lower quality only for offline editing
```

**2. Metadata Corruption**

**Symptoms:**
- Incorrect white balance (green/magenta cast)
- Wrong exposure interpretation
- Black level errors (lifted shadows or crushed blacks)

**Prevention:**
```
1. Verify metadata in post software
2. Cross-reference clip metadata with camera reports
3. Test decode with different metadata interpretation
4. Keep sidecar (.xml, .json) backups of critical metadata
```

**3. Compression Artifacts**

**Symptoms of Over-Compressed RAW:**
- Noise banding in smooth gradients
- Posterization in shadows
- Macro-blocking (especially with motion)

**Thresholds:**
```
Acceptable: 3:1 to 5:1 compression
Warning: 8:1 to 12:1 compression (visible under critical examination)
Critical: >12:1 compression (artifacts visible in normal viewing)
```

**4. Clipped RAW Channels**

**Cause:** Even in RAW, individual color channels can clip before others

**Symptoms:**
- One channel at maximum (e.g., R=4095 in 12-bit)
- Color shifts in highlights (pink/orange cast)
- Irrecoverable highlight detail

**Detection:**
```
Check individual channel values:
- If any channel = max code value, that channel clipped
- Highlight recovery limited to unclipped channels only
```

### Log-Specific Failures

**1. Improper White Balance Bake-In**

**Consequences:**
- Permanent color cast requiring aggressive correction
- Reduced dynamic range (underutilized channels)
- Color accuracy degradation

**Quantification:**
```
WB Error Impact on SNR:
- ±200K error: ~1dB SNR penalty (minor)
- ±500K error: ~2-3dB SNR penalty (moderate)
- ±1000K error: ~4-6dB SNR penalty (severe)
```

**Best Practice:**
```
1. Set WB accurately on set (use gray card)
2. Double-check WB with color temperature meter
3. If error suspected, shoot RAW instead
4. Document intended WB for reference
```

**2. Insufficient Bit Depth**

**Symptoms:**
- Visible banding in gradients (skies, shadows)
- Posterization in subtle color transitions
- Limited grading flexibility

**Bit Depth Requirements:**
```
For Log Encoding:
- 8-bit: NOT recommended for log (severe banding)
- 10-bit: Minimum acceptable for production log
- 12-bit: Recommended for high-end work
- 16-bit/float: Ideal for mastering and VFX
```

**3. Dynamic Range Mismatch**

**Problem:** Applying camera-specific LUT to footage with different DR

**Example:**
```
Apply LogC4 LUT (15-stop DR) to S-Log3 (14-stop DR):
- S-Log3 highlights clip before LUT expects
- Shadow rolloff doesn't match curve
- Incorrect middle gray placement
```

**Detection:**
```
1. Compare actual vs. expected middle gray CV
2. Check for premature highlight clipping
3. Verify shadow rolloff matches expected curve
```

**4. Codec Quality Bottleneck**

**Problem:** High-quality sensor data bottlenecked by heavy compression

**Example Chain:**
```
Sensor (14 stops DR) → Log encoding (13 stops effective) →
H.264 8-bit codec (8 stops usable)

Result: Massive quality loss from sensor to delivery
```

**Prevention:**
```
Maintain quality chain:
- Use 10-bit+ codec for log
- Prefer intra-frame compression (ProRes, DNxHD)
- Avoid long-GOP codecs for critical footage
- Test full pipeline before production
```

### Shared Failure Modes

**1. Exposure Errors**

**Impact in RAW vs. Log:**
```
Overexposure +1 stop:
- RAW: Recovery possible, minimal quality loss
- Log: Highlight rolloff, reduced flexibility

Overexposure +2 stops:
- RAW: Partial recovery, some highlight detail lost
- Log: Significant highlight clipping, difficult recovery

Underexposure -1 stop:
- RAW: Lift in grade, SNR penalty ~3dB
- Log: Shadow noise becomes visible

Underexposure -2 stops:
- RAW: Severe noise but potentially usable with denoising
- Log: Often unusable, severe noise and banding
```

**2. Color Space Confusion**

**Problem:** Incorrect color space interpretation in post

**Example:**
```
Footage shot: ARRI Wide Gamut
Interpreted as: Rec.709

Result:
- Desaturated colors
- Incorrect hue relationships
- Difficulty achieving intended look
```

**Solution:**
```
1. Always document camera color space
2. Use camera manufacturer LUTs for monitoring
3. Verify color space in post software
4. Test workflow before production
```

## Mini Glossary: RAW vs. Log Terms

**CFA (Color Filter Array):** Bayer pattern filter array over sensor, alternating red, green, and blue filters to capture color information.

**Demosaicing:** Algorithmic reconstruction of full RGB image from single-channel-per-pixel Bayer pattern data.

**White Balance:** Digital gain applied to red, green, and blue channels to compensate for color temperature of light source.

**RAW Metadata:** Sidecar information embedded in RAW files describing capture parameters (ISO, WB, exposure, camera model).

**Bake-In:** Permanently applying image processing (white balance, color grading, noise reduction) during encoding, making later changes difficult.

**Debayer:** Alternative term for demosaicing, the process of interpolating missing color values from Bayer pattern.

**Bilinear Interpolation:** Simple demosaicing method averaging neighboring pixel values, fast but lower quality.

**Adaptive Interpolation:** Demosaicing method that selects interpolation direction based on local edge orientation, higher quality than bilinear.

**Chromatic Aberration:** Lens defect causing different wavelengths to focus at different distances, exacerbated by demosaicing.

**Moiré Pattern:** Interference artifact when scene detail frequency exceeds sensor sampling frequency, creates false colors.

**Zippering Artifact:** Stair-step pattern along diagonal edges caused by poor demosaicing.

**ISO Speed:** Analog gain applied at sensor level before A/D conversion, affects signal-to-noise ratio.

**Exposure Index (EI):** Metadata setting affecting middle gray placement, distinct from analog ISO gain.

**Black Level:** Pedestal offset added to signal to prevent absolute zero values, subtracted during RAW processing.

**White Clipping Level:** Maximum code value before signal saturation, typically 4095 for 12-bit.

**Linear Sensor Data:** Direct A/D converter output before gamma or log encoding, proportional to scene luminance.

**Compressed RAW:** Lossy or lossless compression applied to RAW data, reducing file size with minimal quality impact (3:1 to 12:1 typical).

**Uncompressed RAW:** Full sensor data without compression, maximum quality but largest file sizes.

**Sidecar File:** Separate metadata file (XML, JSON) associated with RAW clips, contains processing instructions.

**Develop/Decode:** Process of converting RAW sensor data to viewable RGB image with demosaicing, color correction, and gamma.

**ISP (Image Signal Processor):** Camera hardware/firmware performing demosaicing, color correction, noise reduction, sharpening.

**Color Filter Array Transmissivity:** Spectral transmission curves of R, G, B filters, determines color accuracy and sensitivity.

**Quantum Efficiency (QE):** Sensor's ability to convert photons to electrons, typically 40-60% for modern cinema cameras.

**Full Well Capacity:** Maximum number of electrons each photosite can hold before saturation, determines dynamic range.

**Read Noise:** Electronic noise added during sensor readout, determines shadow noise floor.

**Fixed Pattern Noise:** Non-uniformity in sensor response, calibrated out via black level subtraction and flat-field correction.

**Dark Current:** Thermally generated electrons accumulated during exposure, increases with temperature and exposure time.

**Binning:** Combining multiple adjacent photosites to increase sensitivity at cost of resolution.

**Skipping:** Reading subset of photosites for faster frame rates at cost of aliasing and resolution.

**Windowing:** Reading smaller portion of sensor for higher frame rates, crop factor applies.

**Oversampling:** Reading full sensor resolution then downsampling to output resolution, improves quality and reduces aliasing.

**Anamorphic De-squeeze:** Horizontal scaling factor (1.33×, 2×) applied to anamorphic footage for correct aspect ratio.

**ACES (Academy Color Encoding System):** Standardized color management system for device-independent color interchange.

**Scene-Referred:** Image data representing actual scene luminance and color, independent of display.

**Display-Referred:** Image data optimized for specific display characteristics (gamma, gamut, brightness).

**Color Space:** 3D volume of reproducible colors defined by primaries and white point.

**Gamut:** Range of colors reproducible within a color space.

**Primary Chromaticities:** X,Y coordinates of red, green, and blue primaries defining color space gamut.

**White Point:** Chromaticity coordinates of reference white, typically D65 (Rec.709) or DCI (P3).

**Tone Curve:** Function mapping scene luminance to display code values (gamma, log, PQ, HLG).

**Dynamic Range:** Ratio between maximum signal and noise floor, expressed in stops (log2) or decibels (20×log10).

**Signal-to-Noise Ratio (SNR):** Ratio of signal power to noise power, expressed in decibels (dB).

**Bit Depth:** Number of bits per sample, determines number of possible code values (2^bit_depth).

**Code Value (CV):** Digital number representing pixel brightness, 0 to (2^bit_depth - 1).

**Quantization Error:** Difference between actual analog value and quantized digital value, source of digital noise.

**Dithering:** Adding controlled noise before quantization to prevent banding and posterization.

**Compression Ratio:** Ratio of uncompressed to compressed data size, higher = more compression.

**Intra-frame Compression:** Compressing each frame independently (ProRes, DNxHD), easier editing.

**Inter-frame Compression:** Using temporal redundancy between frames (H.264, HEVC), higher compression but harder editing.

**Long-GOP:** Group of Pictures structure with I-frames and P/B frames, efficient but complex editing.

**All-I (All Intra):** Every frame is an I-frame, larger files but easier editing.

**Visually Lossless:** Compression that introduces artifacts below threshold of human perception under normal viewing.

**Transcode:** Convert from one codec/format to another, typically generation quality loss.

**Native Editing:** Editing camera-original files without transcoding, maintains quality but requires high performance.
