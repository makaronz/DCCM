# 9.5 IMF Workflows for Streaming

## Theory: Interoperable Master Format (IMF) Architecture

### IMF Overview (SMPTE ST-2067)

**IMF** [Interoperable Master Format | SMPTE ST-2067 suite] is a standardized framework for creating **platform-agnostic, version-controlled master packages** that can be delivered to multiple distributors (Netflix, Disney+, Apple TV+, HBO Max, Amazon Prime Video) without re-creating separate mezzanine files for each platform. Developed collaboratively by Hollywood studios, post-production facilities, and streaming platforms (standardized 2013-2018), IMF addresses the **fragmented delivery landscape** where each distributor previously required unique file formats, codecs, color spaces, and metadata structures — resulting in dozens of mezzanine masters from a single finished title.

IMF achieves **"create once, deliver everywhere"** through:

- **Componentized structure**: Separate **essence tracks** (video, audio, subtitles) stored as independent files, enabling reconfiguration without re-encoding
- **Composition Playlist (CPL)** [SMPTE ST 2067-3]: XML document describing how to combine essence tracks into a playable composition, analogous to an edit decision list (EDL) but standardized
- **Image Composition Playlist (ICL)** [SMPTE ST 2067-2]: Optional metadata track describing color information (color space, transfer function, mastering display), essential for HDR delivery
- **Output Profile List (OPL)** [SMPTE ST 2067-8]: Optional XML document describing supported output configurations (codecs, resolutions, frame rates), enabling platforms to validate compliance

**IMF essence** typically uses **JPEG 2000** [SMPTE ST 2067-20] for video (mezzanine codec, visually lossless at 250-400 Mbps for 4K) or **ProRes/DNxHR** (lighter IMF implementations), **PCM** or **Dolby Atmos** for audio [SMPTE ST 2067-21], and **IMSC** [TTML IMSC1] for subtitles [SMPTE ST 2067-22]. Essence files are **track files** (`.mxf`) containing one or more **track** resources (video frames, audio samples, subtitle segments).

### Composition Playlist (CPL) Architecture

**CPL** [Composition Playlist | SMPTE ST 2067-3] is the heart of IMF: an XML document that **orchestrates playback** by specifying which essence files to play, in what order, for how long, and with what edits. Think of a CPL as a **standardized edit list** that can be interpreted by any IMF-compliant player or tool (e.g., Netflix's IMF Tool, Disney's delivery pipeline, DaVinci Resolve's IMF export).

**CPL structure**:

```xml
<CompositionPlaylist xmlns="http://www.smpte-ra.org/schemas/2067-3/2016">
  <Id>urn:uuid:12345678-1234-1234-1234-123456789abc</Id> <!-- Unique identifier -->
  <Annotation>Feature Title - Theatrical Version</Annotation> <!-- Human-readable name -->
  <IssueDate>2024-11-15T00:00:00Z</IssueDate> <!-- Creation timestamp -->
  <Creator>Post Facility Name</Creator>
  <ContentKind>feature</ContentKind> <!-- "feature", "trailer", "short", "episode" -->
  <EditRate>24000 1001</EditRate> <!-- Frame rate as rational number: 23.976 fps -->

  <!-- Essence references -->
  <SegmentList>
    <Segment>
      <Id>urn:uuid:segment-1</Id>
      <SequenceList>
        <!-- Main picture (video) sequence -->
        <MainImageSequence>
          <Id>urn:uuid:video-sequence-1</Id>
          <TrackId>urn:uuid:video-track-1</TrackId>

          <!-- Resource list: actual essence files -->
          <ResourceList>
            <Resource>
              <Id>urn:uuid:video-resource-1</Id>
              <EditRate>24000 1001</EditRate>
              <IntrinsicDuration>143828</IntrinsicDuration> <!-- Total frames in resource -->
              <EntryPoint>0</EntryPoint> <!-- Start frame (0-based) -->
              <SourceDuration>143828</SourceDuration> <!-- Frames to play from this resource -->
              <TrackFileId>urn:uuid:abcd1234-abcd-1234-abcd-123456789abc</TrackFileId> <!-- Essence file UUID -->
            </Resource>
          </ResourceList>
        </MainImageSequence>

        <!-- Audio sequence (typically multiple tracks: dialogue, music, effects) -->
        <MainAudioSequence>
          <Id>urn:uuid:audio-sequence-1</Id>
          <TrackId>urn:uuid:audio-track-1</TrackId>
          <ResourceList>
            <Resource>
              <Id>urn:uuid:audio-resource-1</Id>
              <EditRate>48000 1</EditRate> <!-- Audio sample rate -->
              <IntrinsicDuration>3460000</IntrinsicDuration> <!-- Total samples -->
              <EntryPoint>0</EntryPoint>
              <SourceDuration>3460000</SourceDuration>
              <TrackFileId>urn:uuid:defg5678-defg-5678-defg-567890123456</TrackFileId>
            </Resource>
          </ResourceList>
        </MainAudioSequence>
      </SequenceList>
    </Segment>
  </SegmentList>
</CompositionPlaylist>
```

**Key CPL concepts**:

- **EditRate**: Frame rate expressed as rational number (numerator denominator). Common rates: 24000 1001 (23.976 fps), 25000 1000 (25 fps), 30000 1001 (29.97 fps), 60000 1001 (59.94 fps)
- **IntrinsicDuration**: Total length of the resource in frames (video) or samples (audio)
- **EntryPoint**: Start frame within the resource (enables trimming without re-encoding)
- **SourceDuration**: Number of frames/samples to play from this resource (enables clip extraction from larger essence)
- **TrackFileId**: UUID reference to the actual essence file (`.mxf`), linking CPL to media

**Multi-version CPLs**: IMF supports multiple compositions within a single **IMP** (IMF Package). For example:
- **Theatrical version** (CPL 1): 2h 15m, includes end credits
- **Extended version** (CPL 2): 2h 28m, includes deleted scenes
- **Airline-safe version** (CPL 3): 1h 58m, censored content

Each CPL references the same underlying essence files where possible (e.g., main feature video), but may include alternative resources for modified segments.

### ICL: Image Composition Playlist (Color Metadata)

**ICL** [Image Composition Playlist | SMPTE ST 2067-2] is an **optional supplemental CPL** that carries **color-related metadata** essential for HDR delivery and color accuracy. When delivering HDR content to Netflix, Disney+, or other platforms, the ICL ensures the streaming platform's encoding pipeline correctly interprets the color characteristics of the IMF essence.

**ICL contents**:

```xml
<ImageCompositionPlaylist xmlns="http://www.smpte-ra.org/schemas/2067-2/2016">
  <Id>urn:uuid:icl-12345678</Id>
  <ContentKind>feature</ContentKind>

  <!-- Color metadata for each video resource -->
  <MainImageSequence>
    <ResourceList>
      <Resource>
        <Id>urn:uuid:video-resource-1</Id>

        <!-- Color primaries (gamut) -->
        <ColorPrimaries>
          <ColorPrimary>ITR-R.BT709</ColorPrimary> <!-- or DCI-P3, BT2020 -->
        </ColorPrimaries>

        <!-- Transfer function (gamma curve) -->
        <TransferCharacteristic>
          <TransferCharacteristic>SMPTE ST 2084:2014 (PQ)</TransferCharacteristic> <!-- or HLG, BT709 -->
        </TransferCharacteristic>

        <!-- Mastering display luminance and chromaticity -->
        <MasteringDisplay>
          <PrimaryR>0.680, 0.320</PrimaryR> <!-- DCI-P3 red -->
          <PrimaryG>0.265, 0.690</PrimaryG> <!-- DCI-P3 green -->
          <PrimaryB>0.150, 0.060</PrimaryB> <!-- DCI-P3 blue -->
          <WhitePoint>0.314, 0.351</WhitePoint> <!-- D65 -->
          <MaxDisplayMasteringLuminance>1000.00</MaxDisplayMasteringLuminance> <!-- 1000 nits -->
          <MinDisplayMasteringLuminance>0.0050</MinDisplayMasteringLuminance> <!-- Black level -->
        </MasteringDisplay>

        <!-- Content's actual peak luminance (may differ from mastering display) -->
        <MaxContentLightLevel>4000</MaxContentLightLevel> <!-- 4000 nits max CLL -->
        <MaxFrameAverageLightLevel>200</MaxFrameAverageLightLevel> <!-- 200 nits max FALL -->
      </Resource>
    </ResourceList>
  </MainImageSequence>
</ImageCompositionPlaylist>
```

**ICL color parameters**:

- **ColorPrimaries**: Defines color gamut. Common values: `ITR-R.BT709` (HD Rec.709), `DCI-P3` (digital cinema P3), `ITR-R.BT2020` (UHD wide gamut)
- **TransferCharacteristic**: Defines transfer function (gamma curve). Common values: `SMPTE ST 2084:2014 (PQ)` (Dolby Vision, HDR10), `ARIB STD-B67 (HLG)` (BBC/NHK HLG), `ITR-R.BT709` (SDR gamma 2.4)
- **MasteringDisplay**: Describes the display used for color grading (primaries, white point, peak luminance). Used by streaming platforms to map HDR content to consumer displays (tone mapping)
- **MaxContentLightLevel (CLL)**: Maximum pixel brightness in the content (e.g., specular highlight at 4000 nits). Platforms use this to prevent clipping during tone mapping
- **MaxFrameAverageLightLevel (FALL)**: Maximum average frame brightness across the content (e.g., 200 nits typical for HDR10, 600 nits for bright HDR10+). Used for adaptive tone mapping

**ICL importance for HDR**: Without ICL, streaming platforms must **guess** the color characteristics of IMF essence, leading to incorrect tone mapping, crushed blacks, or blown-out highlights. ICL provides authoritative metadata that platforms use to configure their encoding pipelines (e.g., Netflix's Per-Title Encode, Disney+ HDR optimization).

### OPL: Output Profile List (Compliance Metadata)

**OPL** [Output Profile List | SMPTE ST 2067-8] is an **optional XML document** that describes the **output configurations** (codecs, resolutions, frame rates, bit depths) supported by the IMF package. Platforms can validate an IMF package against their delivery specifications by comparing the OPL to their requirements (e.g., Netflix's "Photon" spec, Disney's "Titan" spec).

**OPL contents**:

```xml
<OutputProfileList xmlns="http://www.smpte-ra.org/schemas/2067-8/2016">
  <Id>urn:uuid:opl-12345678</Id>

  <!-- Output profile: describes one target configuration -->
  <OutputProfile>
    <Id>urn:uuid:output-profile-netflix-4k-hdr</Id>
    <Annotation>Netflix 4K HDR Delivery</Annotation>

    <!-- Video essence characteristics -->
    <EssenceDescriptor>
      <Codec>http://www.smpte-ra.org/reg/395/2015/13/1/amwa #jpeg2000</Codec> <!-- JPEG 2000 -->
      <Resolution>3840 2160</Resolution> <!-- 4K UHD -->
      <EditRate>24000 1001</EditRate> <!-- 23.976 fps -->
      <BitDepth>12</BitDepth> <!-- 12-bit color -->
      <ChromaSampling>4:2:0</ChromaSampling>
      <ColorPrimaries>ITR-R.BT2020</ColorPrimaries> <!-- UHD wide gamut -->
      <TransferCharacteristic>SMPTE ST 2084:2014 (PQ)</TransferCharacteristic> <!-- HDR10 -->
    </EssenceDescriptor>

    <!-- Audio essence characteristics -->
    <AudioEssenceDescriptor>
      <Codec>http://www.smpte-ra.org/reg/3355/2015/13/1/amwa #pcm</Codec> <!-- PCM -->
      <SampleRate>48000 1</SampleRate> <!-- 48 kHz -->
      <BitDepth>24</BitDepth> <!-- 24-bit audio -->
      <ChannelCount>8</ChannelCount> <!-- 7.1 surround -->
    </AudioEssenceDescriptor>
  </OutputProfile>
</OutputProfileList>
```

**OPL use cases**:

- **Platform validation**: Netflix's IMF ingest tool compares the delivered OPL to Netflix's delivery spec, rejecting packages that don't match (e.g., wrong codec, resolution, color space)
- **Multi-format delivery**: A single IMF package can include multiple OPLs describing different output configurations (e.g., 4K HDR, HD SDR, theatrical DCP), enabling platforms to select the appropriate OPL for their needs
- **Quality control**: QC facilities use OPL to verify the IMF package meets contractual requirements before delivery

**OPL limitations**: Not all platforms require OPL (e.g., Disney+ may accept IMF without OPL if CPL/ICL are complete). OPL is most valuable when platform delivery specs are **strict and standardized** (e.g., Netflix's platform-agnostic delivery).

## Practice: IMF Creation for Streaming Platforms

### Platform-Specific IMF Requirements

**Netflix** (as of 2024-2025) requires IMF for all original content and most licensed content. Netflix's delivery specification ("Photon" spec) mandates:

- **Video essence**: JPEG 2000, 12-bit 4:2:0, **PQ (ST 2084)** transfer function, **BT.2020** color primaries, 3840×2160 (4K) or 1920×1080 (HD), 23.976/24/25/29.97 fps
- **Audio essence**: **PCM 24-bit 48 kHz** or **Dolby Digital Plus** (5.1 or 7.1), **Dolby Atmos** (object-based audio, optional for Atmos titles)
- **Subtitle essence**: **IMSC1** (TTML profile for IMF), timed text/xml format with styling support
- **CPL requirements**: Single CPL per title (theatrical/extended versions as separate CPLs), **EditRate** must match video frame rate, **IssueDate** must be within 6 months of delivery, **ContentKind** must be "feature", "trailer", "short", or "episode"
- **ICL requirements**: **Mandatory for HDR**, must include **MasteringDisplay** (DCI-P3 or BT2020 primaries, 1000-4000 nits peak, 0.005 nits black), **MaxCLL/MaxFALL** (measured from content)
- **OPL requirements**: Optional but recommended (helps Netflix validate against Photon spec)
- **Packaging**: All essence files and CPLs packaged in **IMP (IMF Package)** directory structure, delivered via **Aspera** or physical hard drive

**Disney+** (as of 2024-2025) accepts IMF for all original content (Marvel, Lucasfilm, Pixar, Disney Branded Television). Disney's delivery specification ("Titan" spec) requires:

- **Video essence**: JPEG 2000, 12-bit 4:2:0, **PQ (ST 2084)** or **HLG (ST-B67)** transfer function, **BT.2020** or **DCI-P3** color primaries, 3840×2160 (4K) or 1920×1080 (HD), 23.976/24/25/29.97 fps
- **Audio essence**: **PCM 24-bit 48 kHz** (5.1 or 7.1), **Dolby Atmos** (required for Atmos titles), **Dolby Digital Plus** (fallback for non-Atmos)
- **Subtitle essence**: **IMSC1** (TTML), must include **forced narrative** subtitles for non-English dialogue
- **CPL requirements**: Single CPL per title (multiple versions as separate CPLs), **EditRate** must match video frame rate
- **ICL requirements**: **Mandatory for HDR**, must include **MasteringDisplay** (DCI-P3 or BT2020), **MaxCLL/MaxFALL**
- **OPL requirements**: Not required (Disney uses internal validation tools)
- **Packaging**: IMP directory structure, delivered via **Aspera** or **Signiant**

**Apple TV+** (as of 2024-2025) accepts IMF for most original content, but also accepts **ProRes** mezzanine files as an alternative. Apple's delivery spec requires:

- **Video essence**: JPEG 2000 or ProRes 422 HQ, 10-bit or 12-bit 4:2:2 or 4:2:0, **PQ (ST 2084)** or **HLG (ST-B67)**, **BT.2020** or **DCI-P3**, 3840×2160 (4K) or 1920×1080 (HD)
- **Audio essence**: **PCM 24-bit 48 kHz**, **Dolby Atmos** (optional), **Dolby Digital Plus** (5.1 or 7.1)
- **Subtitle essence**: **IMSC1** or **WebVTT** (Apple accepts both)
- **CPL/ICL requirements**: Same as Netflix/Disney for IMF packages
- **Alternative delivery**: ProRes 422 HQ mezzanine with **color metadata embedded** (CDL, ASC CDL) instead of CPL/ICL

### IMF Creation Workflow

**Step 1: Prepare Master**

Start from **color-graded master** in DaVinci Resolve, Adobe Premiere, or Avid Media Composer:

- **Export master** as **uncompressed** or **lightweight mezzanine** (ProRes 4444, DNxHR 444) at target resolution (4K or HD), frame rate (23.976/24/25/29.97), bit depth (10-bit or 12-bit)
- **Verify color space**: Ensure project is set to **BT.2020/PQ** (HDR10) or **DCI-P3/PQ** for cinema HDR. Use waveform monitor to verify peak luminance (1000-4000 nits) and black level (0.005 nits)
- **Measure CLL/FALL**: Use color grading software's analysis tools (DaVinci Resolve's "Color Page → HDR Scope") to measure **MaxCLL** (maximum pixel brightness) and **MaxFALL** (maximum frame average brightness). Record these values for ICL metadata
- **Audio mix**: Export audio stems (dialogue, music, effects) as **PCM 24-bit 48 kHz** or encode to **Dolby Digital Plus**/**Dolby Atmos** using Dolby tools (Dolby Audio Bridge, Dolby Media Encoder)

**Step 2: Encode Essence**

Encode video essence to **JPEG 2000** using IMF-compliant encoder:

- **Recommended tools**: **intoPIX TicoXS JPEG 2000 SDK**, **FFmpeg** (libopenjpeg), **PIXELTOOLS' JPEG 2000 encoder**
- **FFmpeg command** (libopenjpeg):
  ```bash
  ffmpeg -i master.mov \
    -c:j2000 jpeg2000 \
    -pix_fmt xyz12le \  # 12-bit XYZ color space (optional, or yuv420p12le)
    -frames:v 1 \  # Encode all frames (FFmpeg's jpeg2000 encoder processes frame-by-frame)
    -qscale 1 \  # Quality: 1 (highest) to 20 (lowest). Use 1-3 for IMF
    -tile_size 256x256 \  # JPEG 2000 tile size (256x256 recommended for 4K)
    -compression_level 100  # Compression level (100 = highest, 0 = lossless)
  ```

  **Note**: FFmpeg's JPEG 2000 encoder (`-c:j2000 jpeg2000`) has limited support for IMF-compliant encoding. For production use, consider **intoPIX TicoXS SDK** or commercial IMF creation tools (Marquise Technologies' "Sandeo", Colorfront's "Transkoder", Netflix's open-source "IMF Tool").

- **Encoding parameters**:
  - **Bit depth**: 12-bit (required for HDR), 10-bit acceptable for SDR
  - **Chroma subsampling**: 4:2:0 (standard for streaming), 4:2:2 optional for higher quality
  - **Compression ratio**: 6:1 to 10:1 for visually lossless quality (e.g., 4K HDR at 250-400 Mbps)
  - **Tile size**: 256×256 or 512×512 (larger tiles = better compression, slower decode)
  - **Color space**: XYZ (digital cinema standard) or YCbCr (video standard)

- **Audio essence** encoding:
  - **PCM**: Export directly from DAW (Pro Tools, Nuendo) or NLE as **WAV** or **BWAV** (24-bit 48 kHz)
  - **Dolby Digital Plus**: Encode using **Dolby Media Encoder** (`-acodec ac3` in FFmpeg, but limited support)
  - **Dolby Atmos**: Encode using **Dolby Atmos Production Suite** or **Dolby Audio Bridge** (requires Dolby tools and licensing)

**Step 3: Create CPL**

Generate CPL using **IMF authoring tool**:

- **Recommended tools**:
  - **Netflix's IMF Tool** (open-source, Python-based, GitHub: `netflix/imf-tool`)
  - **Marquise Sandeo** (commercial, full-featured IMF creation suite)
  - **Colorfront Transkoder** (commercial, high-end mastering/transcoding)
  - **Open-source IMF libraries**: `libimf` (C++), `imf-utils` (Python)

- **Netflix IMF Tool workflow**:
  ```bash
  # Install Netflix IMF Tool
  pip install imf-tool

  # Create CPL from essence files
  imf-tool create-cpl \
    --video-essence video.mxf \
    --audio-essence audio.mxf \
    --edit-rate 24000 1001 \
    --output feature_cpl.xml \
    --annotation "Feature Title - Theatrical Version" \
    --content-kind feature

  # Create ICL with color metadata
  imf-tool create-icl \
    --cpl feature_cpl.xml \
    --color-primaries DCI-P3 \
    --transfer-characteristic ST-2084 \
    --mastering-display-primaries 0.680,0.320 0.265,0.690 0.150,0.060 \
    --mastering-display-white 0.314,0.351 \
    --max-mastering-luminance 1000 \
    --min-mastering-luminance 0.005 \
    --max-cll 4000 \
    --max-fall 200 \
    --output feature_icl.xml
  ```

- **CPL structure verification**:
  - **EditRate** matches video frame rate (e.g., `24000 1001` for 23.976 fps)
  - **TrackFileId** UUIDs match essence file UUIDs (use `uuidgen` or IMF tool's UUID generation)
  - **IntrinsicDuration** matches actual essence length (use `ffprobe` to verify frame count)
  - **EntryPoint/SourceDuration** are correct (0 to full length for unedited resources)

**Step 4: Package IMF**

Assemble IMP (IMF Package) directory structure:

```
Feature_Title_IMF/
├── CPL/
│   ├── feature_cpl.xml         # Main composition playlist
│   └── feature_icl.xml         # Image composition playlist (color metadata)
├── Video/
│   ├── feature_reel1_v01.mxf   # JPEG 2000 video essence (reel 1)
│   ├── feature_reel2_v01.mxf   # JPEG 2000 video essence (reel 2, if applicable)
│   └── ...
├── Audio/
│   ├── feature_eng_5.1.a_mxf   # PCM 5.1 audio essence (English)
│   ├── feature_eng_Atmos.a_mxf # Dolby Atmos audio essence (English)
│   └── ...
├── Subtitles/
│   ├── feature_eng_subs.xml    # IMSC1 subtitles (English)
│   ├── feature_spa_subs.xml    # IMSC1 subtitles (Spanish)
│   └── ...
└── ASSETMAP.xml                 # Asset map: UUIDs to file paths (optional, some platforms don't require)
```

- **ASSETMAP** [SMPTE ST 429-9]: Optional XML document that maps **UUIDs to file paths**, enabling IMF players to locate essence files. Some platforms (Netflix) require ASSETMAP, others (Disney+) generate it internally during ingest.

**Step 5: Compliance Testing**

Validate IMF package against platform delivery specs:

- **Netflix IMF Tool validation**:
  ```bash
  imf-tool validate \
    --cpl feature_cpl.xml \
    --icl feature_icl.xml \
    --video-essence video/*.mxf \
    --audio-essence audio/*.mxf \
    --spec netflix-photon-v4  # Netflix's delivery spec version 4
  ```

- **Common validation checks**:
  - **CPL well-formedness**: XML schema validation (SMPTE ST 2067-3)
  - **ICL completeness**: All required color metadata present (MasteringDisplay, MaxCLL/MaxFALL)
  - **Essence file integrity**: MXF format validation (SMPTE ST 2067-20 for JPEG 2000)
  - **UUID consistency**: All TrackFileId UUIDs in CPL match actual essence file UUIDs
  - **Frame rate matching**: CPL EditRate matches video essence frame rate
  - **Duration consistency**: CPL IntrinsicDuration matches essence length
  - **Codec compliance**: JPEG 2000 parameters match platform spec (bit depth, chroma subsampling, compression ratio)
  - **Audio compliance**: PCM/ Dolby Digital Plus/ Atmos parameters match spec (sample rate, bit depth, channel count)
  - **Subtitle compliance**: IMSC1 format validation (TTML schema, styling support)

- **Platform-specific validation tools**:
  - **Netflix**: **Photon IMF Validator** (internal tool, available to Netflix partners via delivery portal)
  - **Disney+**: **Titan IMF Validator** (internal tool, available to Disney partners via delivery portal)
  - **Apple TV+**: **IMF Validation via iTunes Producer** (Apple's delivery tool)

**Step 6: Delivery**

Deliver IMF package to platform:

- **Netflix**: Deliver via **Aspera** (faspex) or **physical hard drive** (LTO-6 or newer). Upload IMP directory to Netflix's delivery portal, then submit delivery via **Netflix Partner Portal** (requires partner account). Netflix's QC team validates package and notifies of issues within **24-48 hours**.
- **Disney+**: Deliver via **Aspera** or **Signify**. Upload IMP directory to Disney's delivery portal, then submit via **Disney Media Hub** (requires partner account). Disney's QC team validates within **48-72 hours**.
- **Apple TV+**: Deliver via **iTunes Producer** (Apple's desktop delivery tool) or **Aspera**. Upload IMP directory, then submit via **iTunes Connect** (requires Apple Developer account). Apple's QC team validates within **24-48 hours**.

### Multi-Version IMF Creation

Creating multiple versions (theatrical, extended, airline-safe) from single IMF package:

**Approach 1: Multiple CPLs, Shared Essence**

- **Create base CPL** for theatrical version (references all essence files)
- **Create extended CPL** that replaces specific segments with alternative resources:
  ```xml
  <Segment>
    <SequenceList>
      <MainImageSequence>
        <ResourceList>
          <!-- Reel 1: Shared with theatrical -->
          <Resource>
            <TrackFileId>urn:uuid:reel1-video</TrackFileId>
            <SourceDuration>25000</SourceDuration> <!-- First reel -->
          </Resource>
          <!-- Reel 2: Extended scene (different from theatrical) -->
          <Resource>
            <TrackFileId>urn:uuid:reel2-extended-video</TrackFileId> <!-- Alternative essence -->
            <SourceDuration>3000</SourceDuration> <!-- Extended scene (3 minutes longer) -->
          </Resource>
          <!-- Reel 3: Shared with theatrical -->
          <Resource>
            <TrackFileId>urn:uuid:reel3-video</TrackFileId>
            <SourceDuration>25000</SourceDuration>
          </Resource>
        </ResourceList>
      </MainImageSequence>
    </SequenceList>
  </Segment>
  ```

- **Benefit**: Minimize storage by sharing unchanged reels, only encode unique segments

**Approach 2: Reordering CPLs**

- Create **airline-safe CPL** that skips censored scenes by **not referencing** those resources:
  ```xml
  <ResourceList>
    <!-- Reel 1: Shared -->
    <Resource>
      <TrackFileId>urn:uuid:reel1-video</TrackFileId>
      <SourceDuration>25000</SourceDuration>
    </Resource>
    <!-- SKIP Reel 2 (censored content) -->
    <!-- Reel 3: Shared -->
    <Resource>
      <TrackFileId>urn:uuid:reel3-video</TrackFileId>
      <SourceDuration>25000</SourceDuration>
    </Resource>
  </ResourceList>
  ```

- **Benefit**: No re-encoding required, simply omit resources from CPL

## Failure Modes: IMF Delivery Issues

### IMF Creation Errors

**Problem**: CPL or ICL generation fails due to malformed XML, missing metadata, or incorrect essence references.

**Causes**:
- **XML schema violations**: CPL/ICL doesn't conform to SMPTE ST 2067-3/2067-2 schema (e.g., missing required elements, invalid attribute values)
- **UUID mismatches**: TrackFileId UUIDs in CPL don't match actual essence file UUIDs (essence files have embedded UUIDs in MXF header)
- **Duration inconsistencies**: CPL IntrinsicDuration doesn't match essence length (e.g., CPL says 143828 frames, but essence file only contains 143800 frames)
- **EditRate mismatches**: CPL EditRate doesn't match video essence frame rate (e.g., CPL says 24000 1001 for 23.976 fps, but video is actually 25000 1000 for 25 fps)
- **Missing ICL metadata**: ICL missing required MasteringDisplay, MaxCLL, or MaxFALL values for HDR content
- **Invalid color metadata**: ICL contains inconsistent or out-of-range values (e.g., MaxCLL < MaxFALL, or MaxMasteringLuminance < MaxContentLightLevel)

**Detection**:
- **Schema validation**: Use XML validation tools (xmllint, XMLSpy) to validate CPL/ICL against SMPTE schemas
- **IMF validation tools**: Netflix IMF Tool, Marquise Sandeo validation, Colorfront Transkoder validation
- **FFmpeg inspection**: Use `ffprobe` to verify essence file properties (frame count, frame rate, codec)
  ```bash
  ffprobe -v error -show_streams -of json video.mxf
  # Look for: nb_read_frames (frame count), r_frame_rate (frame rate), codec_name (jpeg2000)
  ```

**Prevention**:
- **Use IMF creation tools**: Don't manually write CPL/ICL XML; use Netflix IMF Tool, Marquise Sandeo, or other validated tools
- **Validate before delivery**: Run IMF validation tools (imf-tool validate) before submitting to platform
- **Check UUID consistency**: Use `mxf2raw` or `mxfsplit` to extract UUIDs from essence files, verify CPL TrackFileId matches
- **Measure color metadata accurately**: Use color grading software's analysis tools to measure MaxCLL/MaxFALL, don't guess

**Recovery**:
- **Regenerate CPL/ICL**: Fix errors in IMF creation tool, regenerate CPL/ICL
- **Re-encode essence**: If essence file is corrupted or incorrect parameters, re-encode from master
- **Update metadata**: Correct ICL color metadata if values were entered incorrectly

### CPL Issues

**Problem**: CPL references incorrect essence files, wrong segments, or has ordering issues, causing playback failures or incorrect version delivery.

**Causes**:
- **Wrong TrackFileId**: CPL references UUID of non-existent essence file (typo in UUID, or essence file not included in package)
- **Incorrect EntryPoint/SourceDuration**: CPL specifies wrong start frame or duration for resource, causing incorrect segment to play or播放 truncated
- **Segment order issues**: Resources in wrong order (e.g., Reel 2 before Reel 1), causing film to play out of sequence
- **Missing resources**: CPL references essence file that wasn't included in IMP directory (e.g., audio track referenced but file missing)
- **Duplicate UUIDs**: Multiple resources have same TrackFileId UUID (UUID collision), causing ambiguity

**Detection**:
- **Playback testing**: Use IMF player (Netflix IMF Tool's playback feature, open-source players like **IMF Player** from IMFC) to verify CPL plays correctly
- **Visual inspection**: Open CPL XML in text editor, verify TrackFileId UUIDs, EntryPoint, SourceDuration values
- **UUID scanning**: Use `find`/`grep` to search for all UUIDs in CPL, cross-reference with essence file UUIDs
  ```bash
  grep -o "urn:uuid:[a-f0-9-]*" feature_cpl.xml
  mxf2raw --uuid video/*.mxf  # Extract UUIDs from MXF files
  ```

**Prevention**:
- **Automated CPL generation**: Use IMF creation tools that auto-generate UUIDs and verify consistency
- **Validation tools**: Run validation before delivery (imf-tool validate, platform validators)
- **QC workflow**: Have QC technician review CPL XML for obvious errors (wrong order, missing resources)
- **Version control**: Track CPL versions using **IssueDate** and **Id** UUIDs; don't overwrite CPLs, create new versions

**Recovery**:
- **Fix CPL**: Edit CPL XML (or regenerate from IMF tool) to correct TrackFileId, EntryPoint, SourceDuration, or ordering
- **Re-package IMP**: Add missing essence files, remove duplicate UUIDs
- **Test playback**: Verify corrected CPL plays correctly before re-delivery

### QC Failures

**Problem**: Platform QC team rejects IMF package due to quality issues (artifacts, color errors, audio sync problems).

**Causes**:
- **JPEG 2000 compression artifacts**: Too high compression ratio causes visible blockiness or banding in flat gradients (e.g., sky, skin tones)
- **Color space mismatches**: Video encoded in wrong color space (e.g., Rec.709 instead of BT.2020), causing color shift
- **HDR metadata incorrect**: ICL MasteringDisplay doesn't match actual content (e.g., ICL says 1000 nits peak, but content mastered at 4000 nits), causing incorrect tone mapping
- **Audio sync drift**: Audio essence not perfectly aligned with video (e.g., audio starts 1 frame late due to EditRate mismatch)
- **Subtitle timing errors**: IMSC1 subtitles not synced to dialogue (e.g., subtitles appear 2 seconds early)
- **Missing forced narratives**: Non-English dialogue not subtitled (required for international distribution)

**Detection**:
- **Visual QC**: QC technician watches full content on reference monitor, checks for artifacts, color issues, sync problems
- **Automated QC tools**: Use **Colorfront Engine** (QC/transcoding tool), **Marquise Sandeo QC**, **Netflix's Photon QC** to automatically detect issues
- **Color analysis**: Use waveform monitor/vectorscope to verify color space, peak luminance, black level
- **Audio sync test**: Use tools like **Vegas Pro**, **DaVinci Resolve** to verify audio-video alignment (check for drift throughout feature)

**Prevention**:
- **Conservative JPEG 2000 encoding**: Use lower compression ratio (6:1 instead of 10:1) to avoid artifacts, even if file size is larger
- **Color space verification**: Confirm project color space before encoding (check NLE/grading software settings)
- **Accurate ICL metadata**: Measure MaxCLL/MaxFALL from actual content, don't guess or copy from another title
- **Audio sync testing**: After encoding, verify audio sync at multiple points (beginning, middle, end) to detect drift
- **Subtitle QC**: Have native speaker verify subtitle timing and translation accuracy

**Recovery**:
- **Re-encode essence**: Re-encode video with lower JPEG 2000 compression ratio, correct color space
- **Fix ICL**: Update ICL metadata with accurate MaxCLL/MaxFALL, MasteringDisplay
- **Re-mix audio**: Fix audio sync in DAW/NLE, re-export PCM/ Dolby Digital Plus/ Atmos
- **Re-time subtitles**: Adjust IMSC1 subtitle timing (using **Subtitle Edit**, **Netflix's subtitle tool**)
- **Re-test**: Run full QC again after fixes before re-delivery

### Delivery Rejections

**Problem**: Platform rejects IMF delivery due to spec violations (wrong codec, resolution, frame rate, packaging format).

**Causes**:
- **Wrong codec**: Video encoded with ProRes instead of JPEG 2000, or audio encoded as AAC instead of PCM
- **Wrong resolution**: 4K content at 4096×2160 (DCI 4K) instead of 3840×2160 (UHD 4K), or vice versa
- **Wrong frame rate**: 24 fps instead of 23.976 fps (24000 1001), or 25 fps for Netflix US (which expects 23.976)
- **Wrong color space**: Rec.709 instead of BT.2020, or SDR instead of HDR
- **Missing CPL/ICL**: Package doesn't include CPL or ICL (required by most platforms)
- **Incorrect packaging**: Files not in correct directory structure, or ASSETMAP missing/incorrect
- **Platform-specific violations**: Netflix's Photon spec requires **12-bit JPEG 2000**, but delivered 10-bit; Disney's Titan spec requires **PQ transfer**, but delivered HLG

**Detection**:
- **Platform delivery spec review**: Carefully read platform's latest delivery specification (Netflix Photon v4, Disney Titan v3, Apple TV+ Delivery Spec 2024)
- **Pre-delivery validation**: Run platform's validation tool (Netflix IMF Validator, Disney Titan Validator, Apple iTunes Producer validation)
- **FFmpeg/media info inspection**: Verify codec, resolution, frame rate, bit depth, color space
  ```bash
  ffprobe -v error -show_streams -of json video.mxf | jq '.streams[0] | {
    codec_name, width, height, r_frame_rate, bits_per_sample, color_space, color_transfer
  }'
  ```

**Prevention**:
- **Read platform specs carefully**: Don't assume specs are same across platforms (Netflix, Disney, Apple all have slight variations)
- **Use IMF creation tools**: Tools like Netflix IMF Tool, Marquise Sandeo have built-in spec compliance checks
- **Test delivery**: Deliver test package to platform (watermarked or placeholder content) to verify process before delivering actual content
- **Consult platform reps**: Ask platform delivery representatives for clarification on ambiguous spec requirements

**Recovery**:
- **Re-encode to correct spec**: Re-encode video/audio with correct codec, resolution, frame rate, color space
- **Fix CPL/ICL**: Regenerate CPL/ICL with correct metadata (EditRate, ICL color space)
- **Re-package**: Reorganize files into correct directory structure, include ASSETMAP if required
- **Re-deliver**: Submit corrected package; platforms typically provide **5-10 business days** to fix rejections without penalty

## Mini Glossary

**IMF** [Interoperable Master Format | SMPTE ST 2067 suite] — Standardized framework for creating platform-agnostic master packages using **componentized essence** (video, audio, subtitles) and **XML playlists** (CPL, ICL, OPL) that can be delivered to multiple distributors (Netflix, Disney+, Apple TV+) without re-creating separate mezzanine files. Developed 2013-2018 by Hollywood studios, post facilities, streaming platforms to address fragmented delivery landscape. Core components: **CPL** (edit list), **ICL** (color metadata), **OPL** (compliance metadata), **IMP** (packaged directory structure). Replaces traditional **mezzanine master** (single QuickTime/ MXF) with **componentized master** enabling reconfiguration without re-encoding. Adopted by Netflix (mandatory for originals 2018+), Disney+ (mandatory for originals 2020+), Apple TV+ (optional, ProRes accepted).

**CPL** [Composition Playlist | SMPTE ST 2067-3] — XML document that **orchestrates IMF playback** by specifying which essence files to play, in what order, for how long, and with what edits. Analogous to **edit decision list (EDL)** but standardized, platform-agnostic. Contains: **Id** (UUID), **Annotation** (human-readable name), **IssueDate** (creation timestamp), **EditRate** (frame rate as rational: 24000 1001 for 23.976 fps), **ContentKind** (feature/trailer/short/episode), **Segment** (one or more segments), **Sequence** (video/audio/subtitle tracks), **Resource** (essence file references with **TrackFileId** UUID, **IntrinsicDuration**, **EntryPoint**, **SourceDuration**). Single CPL per version (theatrical, extended, airline-safe). Validated against SMPTE ST 2067-3 schema. Created using tools: Netflix IMF Tool, Marquise Sandeo, Colorfront Transkoder.

**ICL** [Image Composition Playlist | SMPTE ST 2067-2] — Optional supplemental CPL that carries **color metadata** essential for HDR delivery: **ColorPrimaries** (gamut: BT.709, DCI-P3, BT.2020), **TransferCharacteristic** (gamma: PQ, HLG, BT.709), **MasteringDisplay** (primary chromaticities, white point, peak luminance, black level), **MaxContentLightLevel (CLL)** (maximum pixel brightness in content, e.g., 4000 nits), **MaxFrameAverageLightLevel (FALL)** (maximum average frame brightness, e.g., 200 nits). Mandatory for HDR delivery to Netflix/Disney. Ensures streaming platforms' encoding pipelines correctly interpret color characteristics, preventing incorrect tone mapping (crushed blacks, blown highlights). Created using Netflix IMF Tool (`imf-tool create-icl`) or by editing XML manually with accurate measurements from color grading software (DaVinci Resolve HDR Scope).

**OPL** [Output Profile List | SMPTE ST 2067-8] — Optional XML document describing **output configurations** (codecs, resolutions, frame rates, bit depths, color spaces) supported by IMF package. Enables platforms to validate compliance against delivery specs (Netflix Photon, Disney Titan). Contains **OutputProfile** elements with **EssenceDescriptor** (video codec, resolution, EditRate, bit depth, chroma subsampling, color primaries, transfer characteristic) and **AudioEssenceDescriptor** (audio codec, sample rate, bit depth, channel count). Single OPL can describe multiple output profiles (4K HDR, HD SDR, theatrical DCP). Platforms use OPL to verify package matches requirements before ingest. Optional (Netflix recommends, Disney doesn't require). Created using IMF authoring tools or manually.

**IMP** [IMF Package] — Packaged directory structure containing all CPLs, essence files, and metadata for IMF delivery. Structure: `CPL/` (CPL/ICL XML files), `Video/` (JPEG 2000 MXF files), `Audio/` (PCM/Dolby/DTS MXF files), `Subtitles/` (IMSC1 TTML XML files), `ASSETMAP.xml` (optional UUID-to-filepath mapping). Delivered via **Aspera**/**Signiant** (high-speed file transfer) or **physical hard drive** (LTO-6/7). Platforms ingest IMP, validate against delivery spec, transcode to distribution codecs (AV1/HEVC/H.264 for streaming). Multiple IMPs can be delivered for different versions (theatrical, extended, airline-safe). Each IMP identified by **package UUID** and **package name** (e.g., `Feature_Title_Theatrical_IMF`).

**Composition** — General term for **playable sequence** created by combining essence resources according to CPL instructions. In IMF context, "composition" typically refers to **feature film, episode, trailer, or short** created from one CPL. Multiple compositions (versions) can exist in single IMP (theatrical version, extended version, airline-safe version), each with its own CPL referencing overlapping essence files. Platform selects appropriate composition CPL based on distribution needs (e.g., Netflix streams theatrical version, airline gets airline-safe version). Composition distinct from **essence** (raw media files) and **playlist** (CPL XML that references essence).

**Compliance** — Adherence to **platform delivery specifications** (Netflix Photon v4, Disney Titan v3, Apple TV+ Delivery Spec 2024). Compliance encompasses: **video essence** (JPEG 2000, 12-bit, 4:2:0, PQ/BT.2020, 3840×2160/1920×1080, 23.976/24/25/29.97 fps), **audio essence** (PCM 24-bit 48 kHz, Dolby Digital Plus, Dolby Atmos, 5.1/7.1), **subtitles** (IMSC1 TTML, forced narratives, translation accuracy), **CPL/ICL** (well-formed XML, correct EditRate, complete color metadata), **packaging** (IMP directory structure, ASSETMAP). Platforms validate compliance using **automated tools** (Netflix IMF Validator, Disney Titan Validator, Apple iTunes Producer) before accepting delivery. Non-compliant packages rejected with **QC report** detailing issues (technical errors, quality problems). Facilities typically have **5-10 business days** to fix and re-deliver.

**Delivery spec** — Platform-specific document detailing **technical requirements** for IMF delivery. Major specs: **Netflix Photon v4** (2024), **Disney Titan v3** (2024), **Apple TV+ Delivery Spec** (2024), **HBO Max Delivery Spec** (2023). Specs cover: **video** (codec, resolution, frame rate, bit depth, chroma subsampling, color space, transfer function, peak luminance), **audio** (codec, sample rate, bit depth, channel count, loudness: -23 LUFS ±2), **subtitles** (format: IMSC1, languages, forced narratives, character limits), **metadata** (CPL/ICL/OPL requirements, ASSETMAP), **packaging** (IMP structure, file naming, delivery method: Aspera/Signiant/hard drive). Specs updated annually (e.g., Netflix Photon v3 → v4 adds HDR10+ support, changes loudness requirements). Facilities must subscribe to platform partner portals to access latest specs and validation tools.

**Photon** [Netflix Photon Spec] — Netflix's IMF delivery specification (version 4 as of 2024). Requires: **video essence** (JPEG 2000, 12-bit 4:2:0, PQ ST-2084, BT.2020 or DCI-P3, 3840×2160 or 1920×1080, 23.976/24/25/29.97 fps, 250-400 Mbps), **audio essence** (PCM 24-bit 48 kHz, Dolby Digital Plus 5.1/7.1, Dolby Atmos optional, -23 LUFS ±2), **subtitles** (IMSC1 TTML, all dialogue languages, forced narratives for non-English dialogue, 32-40 characters per line max), **CPL** (well-formed XML, EditRate matches video, ContentKind: feature/trailer/short/episode), **ICL** (mandatory for HDR: MasteringDisplay, MaxCLL, MaxFALL), **OPL** (optional but recommended). Validated using **Netflix IMF Validator** (internal tool) or Netflix's open-source **imf-tool** (`imf-tool validate --spec netflix-photon-v4`). Non-compliant deliveries rejected with **QC ticket** detailing issues. Netflix provides **Partner Portal** for submission, tracking, and QC reports.

**Titan** [Disney Titan Spec] — Disney+'s IMF delivery specification (version 3 as of 2024). Similar to Netflix Photon but with differences: **video essence** (JPEG 2000, 12-bit 4:2:0, PQ or HLG, BT.2020 or DCI-P3, 3840×2160 or 1920×1080, 23.976/24/25/29.97 fps), **audio essence** (PCM 24-bit 48 kHz, Dolby Digital Plus 5.1/7.1, Dolby Atmos required for Atmos titles), **subtitles** (IMSC1 TTML, forced narratives required, character limits: 42 characters max), **CPL/ICL** (same as Netflix), **OPL** (not required). Validated using **Disney Titan Validator** (internal tool). Delivered via **Aspera** to **Disney Media Hub**. QC turnaround: **48-72 hours**. Disney provides **Partner Portal** for submission and tracking. Spec differences: Disney accepts HLG (Netflix doesn't), requires Atmos for Atmos titles (Netflix optional), has slightly looser subtitle character limits (42 vs 32-40).

**IMSC** [IMSC1 | TTML Profile for IMF] — **W3C Timed Text Markup Language (TTML)** profile for IMF subtitles. IMSC1 extends TTML with features for **subtitling and captioning**: **styling** (font, color, position), **timing** (start/end times, duration), **positioning** (region-based layout), **metadata** (language, role). Used for **closed captions** (SDH), **subtitles** (translation), **forced narratives** (non-English dialogue translation). IMSC1 files are XML (`*.xml` or `*.ttml`) with `<tt>` root element containing `<body>` with `<div>` regions and `<p>` paragraph elements. Example:
```xml
<tt xmlns="http://www.w3.org/ns/ttml">
  <body>
    <div region="bottom">
      <p begin="00:01:23.456" end="00:01:26.789">(whispering) I can't believe we're here.</p>
    </div>
  </body>
</tt>
```
IMSC1 supports **inline styling** (`<span style="color:red">`), **CSS classes** (`style="class"`), **region positioning** (`region="top"` for top-screen captions). Validated against **TTML IMSC1 schema**. Created using subtitle tools (Netflix's subtitle tool,Subtitle Edit), exported from captioning software (CPC, MacCaption).

**JPEG 2000 for IMF** [SMPTE ST 2067-20] — JPEG 2000 codec specifically configured for IMF essence. Uses **wavelet-based transform** (DWT) with **9/7 irreversible filter** for lossy compression or **5/3 reversible filter** for lossless. Typical IMF parameters: **12-bit XYZ or YCbCr 4:2:0**, **6:1 to 10:1 compression ratio** (250-400 Mbps for 4K HDR), **tile size 256×256 or 512×512**, **codeblock size 64×64 or 32×32**, **decomposition levels 5-6** (wavelet transform depth). Encoded using tools: **intoPIX TicoXS JPEG 2000 SDK**, **FFmpeg** (`-c:j2000 jpeg2000`), **PIXELTOOLS JPEG 2000 encoder**. Stored in **MXF container** (OP-ATOM, wrapper pattern: Clip-Wrapped). MXF file contains **JPEG 2000 codestreams** (one per frame) with **embedded UUID** in MXF header (TrackFileId). Decoded by IMF players (Netflix's player, open-source IMF Player) for QC/validation. JPEG 2000 chosen for IMF due to **visually lossless quality**, **random access** (frame-level indexing), and **standardization** (SMPTE ST 2067-20).

**ASSETMAP** [SMPTE ST 429-9] — Optional XML document in IMP that maps **UUIDs to file paths**, enabling IMF players to locate essence files. Contains **<AssetList>` with `<Asset>` elements, each with **<Id>` (UUID) and **<ChunkList>` with `<Chunk>` containing **<Path>` (relative file path). Example:
```xml
<AssetMap xmlns="http://www.smpte-ra.org/reg/335/2009/13/2/am">
  <Id>urn:uuid:12345678-1234-1234-1234-123456789abc</Id>
  <AssetList>
    <Asset>
      <Id>urn:uuid:abcd1234-abcd-1234-abcd-123456789abc</Id> <!-- Essence UUID -->
      <ChunkList>
        <Chunk>
          <Path>Video/feature_reel1_v01.mxf</Path> <!-- File path -->
        </Chunk>
      </ChunkList>
    </Asset>
  </AssetList>
</AssetMap>
```
ASSETMAP required by Netflix (as of 2024), optional for Disney+/Apple TV+. Some platforms generate ASSETMAP internally during ingest (Disney+), while others require it in package (Netflix). Created using IMF tools (Netflix IMF Tool, Marquise Sandeo) or manually. ASSETMAP UUID must match **package UUID** (IMP identifier). If missing, some platforms auto-generate; others reject delivery.

**Netflix IMF Tool** — Open-source Python tool suite for IMF creation and validation, maintained by Netflix (GitHub: `netflix/imf-tool`). Features: **CPL creation** (`imf-tool create-cpl`), **ICL creation** (`imf-tool create-icl`), **validation** (`imf-tool validate --spec netflix-photon-v4`), **playback testing** (`imf-tool play`). Supports **JPEG 2000 essence** (MXF), **PCM/Dolby audio** (MXF), **IMSC subtitles** (TTML). Lightweight alternative to commercial tools (Marquise Sandeo, Colorfront Transkoder). Used by smaller facilities and independent filmmakers. Installation: `pip install imf-tool`. Documentation: [https://github.com/netflix/imf-tool](https://github.com/netflix/imf-tool). Limitations: No GUI, limited batch processing, no advanced color management (ICL must be manually configured with measured MaxCLL/MaxFALL). For professional/high-volume work, commercial tools recommended.

**Marquise Sandeo** — Commercial IMF creation and mastering suite, widely used by major studios and post facilities. Features: **GUI-based CPL/ICL/OPL creation**, **batch encoding** (multiple titles concurrently), **advanced color management** (automatic MaxCLL/MaxFALL measurement, HDR monitoring), **QC tools** (artifact detection, sync verification), **platform-specific validation** (Netflix Photon, Disney Titan, Apple TV+). Supports **JPEG 2000, ProRes, DNxHR** essence, **PCM, Dolby, DTS** audio, **IMSC, SCC, STL** subtitles. Pricing: **$10,000-50,000/year** (per-seat or facility license). Alternative to Netflix IMF Tool for professional workflows. Website: [https://www.marquise-technologies.com/sandeo](https://www.marquise-technologies.com/sandeo). Used by facilities like **Company 3, Deluxe, Technicolor** for studio deliveries (Disney, Warner Bros, Netflix).

**Colorfront Transkoder** — High-end transcoding and IMF mastering tool, developed by Colorfront (Hungary). Used by top-tier facilities for **HDR mastering, IMF creation, and platform delivery**. Features: **GPU-accelerated JPEG 2000 encoding** (10-20x faster than CPU), **advanced color management** (ACES pipeline, HDR/SDR cross-conversion), **automated MaxCLL/MaxFALL measurement**, **batch processing** (hundreds of titles), **QC integration** (Colorfront Engine QC). Supports **all IMF essence types**, **platform presets** (Netflix, Disney, Apple), **multi-version CPLs** (theatrical, extended, airline). Pricing: **$50,000-100,000/year** (facility license). Used by **major studios** (Disney, Marvel, Lucasfilm) for premium content mastering. Website: [https://www.colorfront.com/transkoder](https://www.colorfront.com/transkoder). Known for **speed and quality** but high cost and steep learning curve.

**Dolby Atmos** [Object-Based Audio | Dolby] — Immersive audio format using **audio objects** (3D-positioned sounds) rather than traditional channels. In IMF context, Dolby Atmos delivered as **essence track** (MXF or WAV) encoded with **Dolby Atmos Metadata** (object positions, bed audio configuration). Typical IMF Atmos configuration: **7.1.4 bed** (7.1 surround + 4 height channels) + **up to 128 dynamic objects** (moving sounds). Encoded using **Dolby Atmos Production Suite** or **Dolby Audio Bridge**, delivered as **Dolby Digital Plus with Atmos** (for streaming) or **Dolby TrueHD with Atmos** (for Blu-ray). Streaming platforms (Netflix, Disney+, Apple TV+) support Atmos for select titles (requires platform licensing and compatible playback devices). Atmos essence in IMF identified by **TrackFileId UUID** and **EssenceDescriptor** codec identifier (`http://www.smpte-ra.org/reg/XXXX/atmos`). Required by Disney for Atmos originals (2022+), optional for Netflix (but supported). Mastering facilities need **Dolby Atmos tools and certification** (`Dolby Atmos Mastering Suite` license ~$10,000/year).

**Forced narrative** — Subtitle displayed when **non-English dialogue** occurs in primarily English-language content (or reverse for non-English content). Distinguished from regular subtitles by **automatic display** (viewer cannot turn off) and **limited duration** (only during foreign language segment). In IMF, forced narratives delivered as **separate subtitle essence** or **integrated into main subtitle track** with **role="forced-narrative"` attribute. Example:
```xml
<span tts:role="forced-narrative">(speaking French) Merci beaucoup.</span>
```
Required by Netflix/Disney for international distribution (e.g., Spanish dialogue in English film must have forced narrative in English for accessibility). QC checks: **timing accuracy** (sync to dialogue), **translation accuracy** (convey meaning, not literal), **character limits** (32-42 characters per line). Created during **subtitle localization** process, typically by same vendor creating main subtitles (Iyuno-SDI, Deluxe, Pixelogic). Missing forced narratives common QC rejection reason.
