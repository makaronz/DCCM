# 4.2 Technical LUTs vs. Creative LUTs

## Theory: Transform Principles and Look Creation

### Technical LUT Fundamentals

**Purpose:** Mathematically precise color space conversions ensuring accuracy and predictability

**Core Principles:**

```
Technical Transform Requirements:

1. Reversibility: Transform should be invertible (or approximately invertible)
2. Accuracy: Minimize error (ΔE < 1.0 for critical work)
3. Determinism: Same input always produces same output
4. Metadata preservation: Maintain intent throughout pipeline

Technical LUT Categories:
- Camera IDTs: Log/RAW → Working space (ACES, Rec.709 linear)
- Display ODTs: Working space → Display (Rec.709, P3, HDR)
- Rendering Transforms: Scene-referred → Display-referred
- Look-ahead Transforms: Preview final output during grading
```

**Color Science Behind Technical LUTs:**

```
Gamut Transformation Mathematics:

For converting from source gamut (RGB_s) to target gamut (RGB_t):

1. Convert source RGB to CIE XYZ:
[X]   [x_r x_g x_b]   [R_s]
[Y] = [y_r y_g y_b] × [G_s]
[Z]   [z_r z_g z_b]   [B_s]

Where x,y,z are primary chromaticities for each channel

2. Apply chromatic adaptation (if needed):
[X_d]        [M_CAT]     [X_s]
[Y_d] = [M_illuminant_s→t] × [Y_s]
[Z_d]                    [Z_s]

Using Bradford or CAT02 transform matrix

3. Convert XYZ to target RGB:
[R_t]   [x_r'^-1 y_r'^-1 z_r'^-1]   [X_d]
[G_t] = [x_g'^-1 y_g'^-1 z_g'^-1] × [Y_d]
[B_t]   [x_b'^-1 y_b'^-1 z_b'^-1]   [Z_d]

Where x',y',z' are target primary chromaticities (inverted matrix)
```

### Creative LUT Fundamentals

**Purpose:** Artistic color grading creating specific mood, atmosphere, or aesthetic

**Creative Intent Categories:**

```
1. Film Stock Emulation:
   - Kodak Vision3 250D/5219
   - Fujifilm Eterna 250D
   - Classic motion picture looks

2. Stylistic Grades:
   - "Teal and orange" (blockbuster style)
   - Bleach bypass (high contrast, desaturated)
   - Sepia/monochrome (period piece)
   - Cross-processed (color shifts)

3. Show-Specific Looks:
   - Netflix "House of Cards" desaturated blue
   - "Mad Men" vintage 1960s Kodachrome
   - "The Matrix" green tint

4. Mood Enhancement:
   - Day-for-night conversion
   - Dawn/dusk golden hour
   - Gloomy/desaturated drama
   - Warm/romantic comedy
```

**Creative LUT Creation Workflow:**

```
Method 1: From Reference Grade

1. Create target look in Resolve/Baselight:
   - Primary grading (contrast, color balance)
   - Secondary grading (qualifier windows)
   - Film grain, blur, effects
   - Save as "look" project

2. Extract LUT from grade:
   - Apply grade to identity chart (Macbeth, grayscale)
   - Export graded chart values
   - Create LUT mapping input → graded output
   - Test on various scenes

Method 2: Film Stock Scanning

1. Shoot physical film stock test:
   - Capture color charts, skin tones, gradients
   - Process at professional lab
   - Scan on high-end scanner (Arriscan, Director)

2. Create emulation LUT:
   - Digitally photograph same scene with digital camera
   - Match digital to scanned film appearance
   - Create LUT representing digital→film transform
   - Validate with additional test footage

Method 3: Algorithmic Generation

1. Define film stock characteristics:
   - Toe/shoulder curves (logarithmic rolloff)
   - Color cross-talk (bleed between channels)
   - Grain characteristics (size, distribution)
   - Development effects (push/pull)

2. Generate LUT procedurally:
   - Apply tone curve to all channels
   - Add color casts (e.g., cyan shadows, yellow highlights)
   - Introduce film grain (can be separate process)
   - Adjust saturation for film look
```

### CDL (Color Decision List) Integration

**CDL Specification:**

```
ASC-CDL SOP + SAT Model:

For each color channel (R, G, B):

1. Slope (contrast):
   out = in × slope

2. Offset (brightness):
   out = out + offset

3. Power (gamma):
   out = sign(out) × |out|^power

4. Saturation:
   Apply last: adjusts distance from neutral axis

Mathematical formulation:
For pixel (R, G, B):

R' = (R × slope_R + offset_R)^power_R
G' = (G × slope_G + offset_G)^power_G
B' = (B × slope_B + offset_B)^power_B

Luma = 0.2126×R' + 0.7152×G' + 0.0722×B'

R_out = Luma + sat × (R' - Luma)
G_out = Luma + sat × (G' - Luma)
B_out = Luma + sat × (B' - Luma)

Where:
- slope: Default 1.0, range 0.0-10.0
- offset: Default 0.0, range -1.0 to +1.0
- power: Default 1.0, range 0.0-10.0
- sat (saturation): Default 1.0, range 0.0-10.0
```

**CDL vs. Creative LUT:**

```
CDL Characteristics:
- Elementary 9 parameters (slope/offset/power per channel + saturation)
- Mathematically simple, fast to apply
- Limited creative control
- Industry standard, interoperable
- Often used as starting point before creative LUT

Creative LUT Characteristics:
- Unlimited degrees of freedom
- Can represent arbitrary color transformations
- Can include secondary corrections
- File sizes larger (especially 3D LUTs)
- Often generated from CDL + additional grading

Typical Workflow:
1. Apply CDL for primary color correction
2. Apply creative LUT for complex look
3. Fine-tune with additional grading
```

## Practice: Show LUTs and Look Workflows

### Show LUT Development Process

**Phase 1: Creative Brief**

```
Collaboration between:
- Director (overall vision)
- Cinematographer (photographic approach)
- Colorist (technical implementation)
- Producer (budgetary constraints)

Documentation:
- Visual references (films, photographs, paintings)
- Mood boards (color palettes, textures)
- Scene examples (day interior, night exterior, etc.)
- Technical requirements (delivery formats, HDR/SDR)
```

**Phase 2: Look Development**

```
Iterative Process:

1. Initial grade test:
   - Grade representative scenes from pilot/first episode
   - Create multiple look options (2-3 variations)
   - Present to director/DP for feedback

2. Refinement:
   - Adjust based on notes
   - Test across different scene types
   - Verify works in different lighting conditions

3. Stress Testing:
   - Test on challenging scenes (high contrast, mixed lighting)
   - Verify skin tone reproduction across diverse actors
   - Check compatibility with VFX plates

4. Freeze Look:
   - Create master show LUT
   - Document creation process
   - Generate variations for different situations
```

**Phase 3: Documentation and Distribution**

```
Show LUT Package Contents:

1. Master Look LUT:
   - 33×33×33 or 64×64×64 3D LUT
   - Camera-specific versions (ARRI, Sony, RED)
   - HDR and SDR variants

2. Documentation:
   - Creative intent description
   - Technical specifications (color spaces, gamma)
   - Application instructions
   - Known limitations/edge cases

3. Quality Control Tools:
   - Test pattern images
   - Verification charts (Macbeth, skin tones)
   - Before/after examples

4. Communication:
   - DIT briefing (on-set monitoring setup)
   - VFX supervisor handoff
   - Color grader training
```

### Technical LUT Validation

**Testing Methodology:**

```
1. Identity Test:
   Input: Gradient test chart (black to white, full color gamut)
   Expected Output: Accurate reproduction within tolerance
   Test: ΔE < 1.0 across entire chart

2. Middle Gray Test:
   Input: 18% gray card
   Expected Output: 18% gray in target color space
   Test: ±2% tolerance (e.g., 17.64-18.36%)

3. Skin Tone Test:
   Input: Caucasian, Asian, African American skin tone patches
   Expected Output: Natural, pleasing reproduction
   Test: Subjective evaluation + ΔE < 2.0 in skin tone regions

4. Gamut Boundary Test:
   Input: Saturated colors at gamut edge
   Expected Output: Clipping or soft-clipping at predictable locations
   Test: No unexpected hue shifts near boundaries

5. Round-Trip Test:
   Transform: A → B → A (e.g., Rec.709 → P3 → Rec.709)
   Expected Output: Return to original (within tolerance)
   Test: ΔE < 1.5 for round-trip
```

**Failure Detection:**

```
Common Technical LUT Errors:

1. Color Cast:
   Symptom: Neutral grays appear tinted (magenta, green, etc.)
   Detection: Check gray scale patches on Macbeth chart
   Quantify: Δa*, Δb* > 2 in CIELAB space
   Fix: Rebuild LUT with correct white point/chromatic adaptation

2. Hue Shift:
   Symptom: Colors rotate around hue circle
   Detection: Compare hue angles before/after transform
   Quantify: Δh > 3° for any primary color
   Fix: Verify primary chromaticities matrix

3. Saturation Error:
   Symptom: Overall color too muted or oversaturated
   Detection: Measure ΔC* (chroma difference) in CIELAB
   Quantify: ΔC* > 5 indicates significant error
   Fix: Adjust tone curve or gamut mapping parameters

4. Clipping:
   Symptom: Loss of highlight or shadow detail
   Detection: Check code values 0 and 1023 for hard clipping
   Quantify: >1% of pixels at clip point
   Fix: Adjust tone curve for softer rolloff
```

### Creative LUT Workflow Integration

**On-Set Workflow:**

```
Purpose: Monitor with intended look during principal photography

Equipment:
- 1. ACES or camera-specific IDT for color accuracy
- 2. Show look LUT (creative intent)
- 3. Display LUT (Rec.709 for monitoring)

Pipeline:
Camera Log → IDT → Show Look → Display LUT → Monitor

Example (ARRI Alexa):
1. Load ARRI IDT (LogC4 → ACES)
2. Apply show look LUT (ACES → ACES + look)
3. Convert to Rec.709 (ACES → Rec.709 ODT)
4. Display on calibrated monitor

Benefits:
- DPs see final look during shooting
- Consistency across multiple DPs/episodes
- Faster communication of visual intent

Considerations:
- Monitor must be calibrated (Rec.709 gamma 2.4, D65)
- False color for exposure still uses separate LUT
- Switch between look view and technical view as needed
```

**Post-Production Workflow:**

```
Editorial (Offline):
- Apply show LUT for color-corrected dailies
- Editors work with intended look
- Faster creative decisions

VFX:
- Work in scene-linear space (ACES, ACEScg)
- Apply show LUT for preview only
- Render plates in scene-linear for flexibility
- Compositing in scene-linear space
- Apply show LUT in final grade

Color Grading:
- Option 1: Start with show LUT, refine from there
- Option 2: Grade from scratch, apply show LUT at end
- Option 3: Hybrid (show LUT + additional creative grading)

Best Practice:
- Maintain show LUT as "starting point"
- Allow creative deviation for specific scenes
- Document any look changes episode-to-episode
- Keep show LUT version-controlled
```

## Failure Modes: Technical vs. Creative Confusion

### Applying Creative LUT as Technical

**Problem:** Using a creative look LUT for color space conversion

**Symptoms:**
- Incorrect middle gray placement
- Color casts in neutral areas
- Loss of shadow/highlight detail
- Difficulty matching shots

**Example:**

```
Wrong:
Camera Log (S-Log3) → "Vintage Film" Creative LUT → Rec.709 display

Result:
- S-Log3 decoded incorrectly (creative LUT expects LogC4)
- Yellow/warm cast added (not part of Rec.709 spec)
- Middle gray at 60% instead of 45% (too bright)
- Shadows crushed (film look has toe, not technical accuracy)

Correct:
S-Log3 → S-Log3 IDT (ACES) → "Vintage Film" LUT (creative) → Rec.709 ODT → Display
```

**Detection:**

```
Quick Checks:
1. Measure 18% gray card position:
   - Should be ~40-45% code value in Rec.709
   - If 55-65%, creative LUT applied as technical

2. Check neutral areas:
   - Gray walls, roads, shirts should be neutral
   - Color cast indicates creative LUT applied too early

3. Compare skin tones:
   - Should look natural in Rec.709
   - Overly stylized indicates creative LUT issue

4. Test with known LUT:
   - Apply manufacturer Rec.709 LUT
   - Compare to current look
   - Large difference indicates wrong LUT type
```

### Double LUT Application

**Problem:** Applying same transform twice in pipeline

**Symptoms:**
- Overly saturated colors
- Excessive contrast
- "Plastic" skin tones
- Loss of subtle detail

**Example Scenarios:**

```
Scenario 1: Double Rec.709 Gamma
Pipeline:
Camera Log → Rec.709 LUT → (grade) → Rec.709 LUT → Display

Result:
- Gamma 2.4 applied twice (gamma 5.76 total)
- Midtones way too bright
- Shadows crushed, highlights blown out

Fix:
Remove second Rec.709 LUT, grade in gamma 2.4 space

Scenario 2: Double Log Decode
Pipeline:
Camera Log → Log LUT → (save as Rec.709) → Log LUT → Display

Result:
- Log decoded twice (log → linear → log decoded)
- Flat, washed-out appearance
- Incorrect color reproduction

Fix:
Determine where log decoding should occur
Only apply once in pipeline
```

**Prevention Checklist:**

```
Pipeline Documentation:

1. Map entire color pipeline:
   Camera → [Transform 1] → [Transform 2] → ... → Display

2. Verify each stage:
   - What color space entering?
   - What color space leaving?
   - Is transform necessary?

3. Check LUT types:
   - Technical LUT (IDT/ODT): Apply once at input/output
   - Creative LUT: Apply once in middle of pipeline
   - Monitor LUT: Apply only for viewing, not to file

4. Test with known input:
   - Feed simple gradient into pipeline
   - Verify output matches expected
   - Check for double-processing artifacts
```

### LUT Bake-In Errors

**Problem:** Applying LUTs destructively during editorial, preventing changes

**Symptoms:**
- Cannot adjust color grading
- VFX integration difficult (color mismatch)
- Delivery format limitations
- Quality loss from multiple generations

**When Bake-In IS Acceptable:**

```
1. Dailies for Editorial:
   - Apply Rec.709 LUT for fast viewing
   - Archive camera-original separately
   - Final grade from camera originals

2. Final Delivery:
   - Apply output LUT for final format
   - No further changes needed
   - Acceptable for lock picture

3. Monitoring Only:
   - Apply LUT to monitor output
   - Record to separate file (not destructive)
   - Can disable LUT for grading
```

**When Bake-In is WRONG:**

```
1. VFX Plates:
   Wrong: Bake Rec.709 LUT before VFX
   Right: Supply scene-linear plates, apply LUT in comp

2. Color Grading Source:
   Wrong: Grade baked LUT footage
   Right: Grade camera originals, apply LUT at end

3. Archival Masters:
   Wrong: Archive with baked creative look
   Right: Archive camera originals + LUT separately
```

### Look Inconsistency

**Problem:** Show LUT doesn't work across all scenes/episodes

**Causes:**

```
1. Exposure Mismatch:
   - Show LUT created for normal exposure
   - Underexposed scenes look different
   - Overexposed scenes clip or shift

2. Lighting Differences:
   - Show LUT optimized for tungsten interior
   - Day exterior shifts color balance
   - Mixed lighting breaks the look

3. Camera Mismatch:
   - Show LUT created for ARRI Alexa
   - Sony Venice footage looks different
   - Different sensor characteristics, color response

4. Format Changes:
   - Show LUT created for SDR Rec.709
   - HDR master requires different approach
   - Show look may not translate to HDR
```

**Solutions:**

```
1. Create Show LUT Variants:
   - Interior (tungsten) version
   - Exterior (daylight) version
   - Low-light version
   - High-contrast version

2. Scene-Specific Exceptions:
   - Document which scenes deviate from show LUT
   - Allow creative breaks for specific story reasons
   - Colorist communicates changes to director

3. Camera-Specific LUTs:
   - Create show LUT for each camera model
   - Maintain consistent look across cameras
   - Test cross-camera compatibility

4. Format-Specific LUTs:
   - Create SDR and HDR versions
   - Maintain creative intent across formats
   - Test both versions side-by-side
```

## Mini Glossary: Technical vs. Creative LUT Terms

**IDT (Input Device Transform):** Technical LUT converting camera-specific color space (Log/RAW) to standardized working space (ACES, Rec.709 linear), ensuring accurate color representation.

**ODT (Output Device Transform):** Technical LUT converting working color space to display-specific output (Rec.709 gamma 2.4, P3, HDR), optimizing for target display characteristics.

**RRT (Reference Rendering Transform):** ACES transform mapping scene-referred color to output-referred color space, standardizing appearance across different delivery formats.

**Look LUT:** Creative LUT implementing specific color grade or aesthetic (film emulation, stylized grade), applied artistically rather than technically correct.

**Show LUT:** Standardized creative LUT developed for television series or film to maintain visual consistency across episodes, DPs, and colorists.

**CDL (Color Decision List):** Industry-standard elementary grade format with 9 parameters (slope, offset, power per RGB channel + saturation), often used as starting point for creative grades.

**ASC-CDL:** American Society of Cinematographers standard for CDL format, ensuring interoperability between different color grading systems and software.

**SOP:** Slope (contrast), Offset (brightness), Power (gamma) - the three elementary corrections per color channel in CDL system.

**SAT (Saturation):** CDL parameter adjusting overall color saturation by scaling distance from neutral axis, applied after SOP corrections.

**Film Stock Emulation:** Creative LUT mimicking appearance of specific motion picture film stocks (Kodak, Fujifilm) through color and tone reproduction.

**Bleach Bypass:** Creative technique (and corresponding LUT) skipping bleach step in film processing, creating high-contrast, desaturated, silvery appearance.

**Cross-Processing:** Creative technique (and LUT) using film chemistry for different emulsion type (e.g., slide film processed as negative), creating color shifts.

**Day-for-Night:** Creative grade/LUT making daylight footage appear as night scene through color correction (blue tint, lower exposure, contrast increase).

**Look Development:** Process of creating and refining creative color grades through iterative collaboration between director, DP, and colorist.

**Dailies Colorist:** Colorist creating graded versions of footage for editorial and on-set review, often using show LUTs or developing looks.

**Final Colorist:** Colorist creating final graded master for delivery, working from camera originals and show LUT as starting point.

**DI (Digital Intermediate):** Digital color grading and finishing process replacing photochemical color timing, offering greater creative control and precision.

**Color Timer:** Traditional photochemical color grading role, replaced by digital colorist in DI workflow.

**Telecine:** Process transferring film to video, historically included color timing, now replaced by digital scanning and grading.

**Grade Suite:** Facility with color grading theater (projector, large screen, calibrated environment) for critical color evaluation and creative grading.

**Online Editor:** Editor performing final assembly, conforming, and color correction of edited program before delivery.

**Conform:** Process matching edited offline sequence to high-resolution camera originals for online and color grading.

**Color Managed Workflow:** Systematic approach to color consistency using standardized color spaces and transforms throughout production pipeline.

**ACES (Academy Color Encoding System):** Industry-standard color management architecture developed by AMPAS for device-independent color interchange.

**OCIO (OpenColorIO):** Open-source color management configuration system used in VFX and animation for transform management and color space conversion.

**Scene-Referred:** Image data representing actual scene luminance and color, independent of any display characteristics, ideal for VFX and compositing.

**Display-Referred:** Image data optimized for specific display (gamma, gamut, brightness), not suitable for further processing or compositing.

**Working Color Space:** Intermediate color space for grading and compositing (ACEScg, Rec.709 linear, P3 linear), chosen for quality and workflow considerations.

**Rec.709:** Standard HDTV color space with BT.709 primaries and gamma 2.4, most common delivery format for broadcast and web.

**DCI-P3:** Digital cinema color space with wider gamut than Rec.709, used for theatrical projection.

**Rec.2020:** Ultra-HD color space with very wide gamut, used for HDR and UHDTV delivery.

**P3 (Display P3):** Apple display color space based on DCI-P3 with D65 white point, used for Apple devices.

**Gamma:** Power-law transfer function (Y = X^γ) encoding luminance, typically gamma 2.2-2.6 for display-referred imagery.

**Linear:** OETF where output is directly proportional to input (no gamma), used for scene-referred and compositing workflows.

**Scene Linear:** Working color space where pixel values are directly proportional to scene luminance, essential for photorealistic VFX.

**Display Linear:** Misnomer sometimes used for gamma-encoded space, technically incorrect but common in some software.

**Transfer Function:** Mathematical relationship (gamma, log, PQ, HLG) between scene luminance and code values.

**OETF (Opto-Electronic Transfer Function):** Camera-side transfer function encoding scene luminance to electrical signal (log, gamma).

**EOTF (Electro-Optical Transfer Function):** Display-side transfer function decoding electrical signal to display luminance (gamma 2.4, PQ, HLG).

**OOTF (Opto-Optical Transfer Function):** Overall system transfer from scene luminance to display luminance, combination of OETF and EOTF.

**PQ (Perceptual Quantizer):** HDR transfer function (SMPTE ST 2084) for absolute luminance encoding up to 10,000 nits, used for Dolby Vision, HDR10.

**HLG (Hybrid Log-Gamma):** HDR transfer function (ARIB STD-B67) using relative luminance scaling, backward compatible with SDR.

**Nit:** Unit of luminance (candela per square meter, cd/m²), used for HDR display brightness specifications (100, 1000, 4000 nits).

**Stop:** Logarithmic unit of exposure or dynamic range, 1 stop = 2× or 0.301 decades (log10).

**Dynamic Range:** Ratio between maximum and minimum reproducible signals, expressed in stops (log2) or decibels (20×log10).

**Bit Depth:** Number of bits per sample determining number of possible code values (2^bit_depth).

**Codec:** COder/DECoder software compressing and decompressing video data (ProRes, DNxHD, H.264).

**Wrapper:** Container format holding encoded video, audio, and metadata (MOV, MXF, MP4).

**Transcode:** Convert from one codec/format to another, typically introducing quality loss.

**Native Editing:** Editing camera-original files without transcoding, maintaining quality but requiring high performance.

**Offline:** Low-resolution editing for creative decisions, followed by online conform to high-resolution originals.

**Online:** Final assembly, grading, and finishing of high-resolution program for delivery.

**Proxy:** Low-resolution version of footage for offline editing or remote review.

**Mezzanine:** Intermediate codec quality near-original but more manageable (ProRes 4444, DNxHR 444).

**Visually Lossless:** Compression introducing artifacts below threshold of human perception under normal viewing.

**Generation Loss:** Quality degradation from multiple encode/decode cycles or transcodes.

**Master:** Final, highest-quality version of program for archival and creating distribution copies.

**Delivery:** Final encoded versions formatted for specific distribution platforms (broadcast, streaming, cinema).

**Distribution:** Process of delivering final program to networks, streaming services, or cinemas.

**QC (Quality Control):** Systematic review of delivered program for technical issues (color, audio, errors).

**Technical Review:** QC focusing on technical specifications (color space, gamma, levels, aspect ratio).

**Creative Review:** QC focusing on creative aspects (grading consistency, visual effects, edit continuity).

**Compliance:** Meeting broadcaster or platform technical requirements (closed captioning, color space, loudness).
