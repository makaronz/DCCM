# 6.1 PQ and HLG Fundamentals

## Theory: EOTF and Opto-Optical Transfer Functions

### PQ (Perceptual Quantizer) - SMPTE ST-2084

**Mathematical Definition**:
PQ is a **signal-based EOTF** (Electro-Optical Transfer Function) designed for **absolute luminance** encoding. It maps digital code values to absolute display luminance in nits (cd/m²).

**Forward EOTF** (Signal → Luminance):
```
L = P_max × ( ( (c + a) / (1 + a × (c + a)) )^b )^γ
```

Where:
- L = Output luminance (nits)
- c = Normalized signal value [0, 1]
- P_max = Peak system luminance (10,000 nits for PQ)
- a = c1 - c2 + 1 = 1.6275
- b = c2 / c1 = 0.5915
- c1 = 3.4351e-04
- c2 = 2.0329e-04
- γ = 2.2222

**Inverse EOTF** (Luminance → Signal):
```
c = ( ( (L / P_max)^(1/γ) )^(1/b) - a ) / (1 - a × ( (L / P_max)^(1/γ) )^(1/b) )
```

**Key Characteristics**:
- **Absolute Luminance**: Code 1.0 = 10,000 nits (defined maximum)
- **Perceptual Uniformity**: ~12 bits perceptual resolution (vs. 8-10 bit linear)
- **System Gamut**: Designed for Rec.2020 color primaries
- **Metadata Required**: Mastering display nits (Min/Max luminance)

**Bit Depth Requirements**:
- **10-bit**: Acceptable for 600-1000 nit mastering (banding in darks)
- **12-bit**: Recommended for HDR (minimal banding)
- **16-bit float (EXR)**: Ideal for HDR grading (no banding)

### HLG (Hybrid Log-Gamma) - ARIB STD-B67

**Mathematical Definition**:
HLG is a **scene-referred opto-optical transfer function (OOTF)** designed for **relative luminance** encoding. It combines log encoding (highlights) with gamma encoding (midtones/shadows).

**Forward OOTF** (Scene Light → Signal):
```
For 0 ≤ E_s ≤ 1/12:
  E' = √3 × E_s

For 1/12 < E_s ≤ 1:
  E' = a × ln(E_s - b) + c
```

Where:
- E_s = Scene linear luminance [0, 1]
- E' = Non-linear signal [0, 1]
- a = 0.17883277
- b = 0.28466892
- c = 0.55991073

**Inverse OOTF** (Signal → Display Light):
```
For 0 ≤ E' ≤ 1/2:
  E_s = (E' / √3)² × α

For 1/2 < E' ≤ 1:
  E_s = exp( (E' - c) / a ) + b × α
```

Where α = 1.2 × (1 - β) + β, β = sqrt(3)/2

**System Gamma** (Display Adaptation):
```
γ_system = 1.2 × (1 - (L_w / L_max)) + (L_w / L_max)
```
Where L_w = peak display white (nits), L_max = system peak (1000 nits)

**Key Characteristics**:
- **Relative Luminance**: Signal scales with display capability (0-1000 nits)
- **Backward Compatible**: Same signal displays on SDR and HDR (different interpretation)
- **Scene-Referred**: Optimized for camera signals (log + gamma hybrid)
- **No Metadata Required**: Self-describing (system gamma adaptation)

**Bit Depth Requirements**:
- **10-bit**: Acceptable (HLG designed for 10-bit broadcast)
- **12-bit**: Improved dark detail
- **8-bit**: Not recommended for HDR (banding in shadows)

### EOTF vs. OOTF: Critical Distinction

**EOTF (Electro-Optical Transfer Function)**:
- **Signal → Light**: Digital code → display luminance
- **Display-Referred**: Encodes absolute display characteristics
- **PQ Example**: Code 0.58 = 100 nits on 1000-nit display, 100 nits on 4000-nit display (absolute)

**OOTF (Opto-Optical Transfer Function)**:
- **Scene Light → Signal → Display Light**: Encodes scene luminance, adapts to display
- **Scene-Referred**: Preserves scene appearance across display capabilities
- **HLG Example**: Code 0.75 = relative highlight (scales: 300 nits on 600-nit display, 500 nits on 1000-nit display)

**Practical Difference**:
- **PQ**: Grade for specific mastering display (e.g., 1000 nits). Change display → re-grade.
- **HLG**: Grade for scene appearance. Display adapts automatically (within 1000-nit range).

### PQ vs. HLG Comparison Table

| Characteristic | PQ (ST-2084) | HLG (B67) |
|---------------|--------------|-----------|
| **Transfer Function** | EOTF (signal-based) | OOTF (scene-based) |
| **Luminance Encoding** | Absolute (nits) | Relative (scene) |
| **System Peak** | 10,000 nits | 1,000 nits |
| **Bit Depth** | 12-bit recommended | 10-bit acceptable |
| **Metadata** | Required (MaxCLL/MaxFALL) | Optional (system gamma) |
| **Backward Compatible** | No (SDR displays black) | Yes (SDR displays SDR) |
| **Primary Use** | Cinema, streaming, gaming | Broadcast, live production |
| **Dynamic Metadata** | Dolby Vision, HDR10+ | HLG Phase 2 (emerging) |
| **Grading Approach** | Display-referred | Scene-referred |
| **Camera Support** | RED, Sony (S-Log4), ARRI (LogC4 PQ) | Sony (HLG), Panasonic (V-Log HLG) |
| **Monitor Support** | Most HDR monitors | Broadcast HDR monitors |
| **Complexity** | Higher (metadata management) | Lower (plug-and-play) |

### Opto-Optical Transfer Function (OOTF) Theory

**What is OOTF?**
The OOTF describes the complete imaging chain from **scene luminance → captured signal → displayed luminance**. Unlike EOTF (display only), OOTF includes:

1. **Camera Capture**: Scene luminance → electrical signal
2. **Encoding**: Signal → compressed code value
3. **Display**: Code value → displayed luminance

**Why HLG Uses OOTF**:
- **Scene Preservation**: HLG maintains scene appearance (contrast ratio, highlight roll-off)
- **Display Adaptation**: OOTF scales scene to display capability (600-1000 nits)
- **Camera Integration**: HLG designed to match camera opto-electronic functions (OECF)

**OOTF vs. EOTF Visual Difference**:
- **PQ (EOTF)**: Grade for specific display. 1000-nit grade looks different on 600-nit display (tone mapping on monitor).
- **HLG (OOTF)**: Grade for scene. Display adapts; similar appearance across 600-1000 nits (within range).

## Practice: PQ and HLG Implementation

### PQ Exposure and Camera Settings

**Exposure Strategy** (Middle Gray):
- **Middle Gray Placement**: 10 nits (typical for 1000-nit mastering)
- **Exposure Meter**: Set to ISO 850, meter middle gray at f/4.0 → EV = middle gray
- **Camera Settings**: Adjust EI/gain to preserve 10 nits at code value 0.58 (PQ mid-gray)

**PQ Camera Support**:

| Camera | PQ Support | Log → PQ Workflow |
|--------|-----------|-------------------|
| RED V-Raptor | IPP2 PQ (in-camera) | RWG/IPP2 → PQ 1000-nit |
| Sony VENICE 2 | S-Log4 (PQ-based) | S-Log4 → S-Log3 → IDT → PQ |
| ARRI Alexa 35 | LogC4 (PQ-compatible) | LogC4 → IDT → PQ via ODT |
| Blackmagic 6K | Gen5 Color Science | Film Gen5 → IDT → PQ via ODT |

**PQ Shooting Tips**:
- **Expose for Highlights**: Preserve highlights up to 1000 nits (10 stops above middle gray)
- **Monitor with PQ LUT**: Apply on-set PQ monitoring LUT (1000-nit target)
- **Check MaxCLL**: Measure brightest highlights (aim <4000 nits for HDR10 deliverable)

### HLG Camera Settings

**HLG Exposure** (Middle Gray):
- **Middle Gray**: 25% of signal (code value 0.25 = 25% peak)
- **Scene Linear**: Middle gray at 0.25 relative luminance (scales with display)
- **Exposure Meter**: ISO 850, f/4.0 → middle gray = 0.25 HLG signal

**HLG Camera Support**:

| Camera | HLG Support | HLG Workflow |
|--------|-------------|--------------|
| Sony Alpha/a7S | HLG1/2/3 (in-camera) | HLG3 → SDR/HDR auto |
| Panasonic GH6 | HLG (V-Log HLG) | HLG → broadcast-ready |
| Canon R5 | HLG (PQ-lite) | HLG → log conversion needed |
| Blackmagic 6K | No native HLG | Film Gen5 → custom HLG LUT |

**HLG Shooting Tips**:
- **Middle Gray at 0.25**: Place middle gray at 25% signal (histogram center)
- **Highlight Preservation**: HLG protects up to 1000 nits (12 stops above middle gray)
- **Monitor in HLG**: Use HLG-capable monitor (auto-detects HLG signal)

### HDR Monitoring Setup

**PQ Monitor Setup**:
1. **Display Configuration**:
   - **EOTF**: ST-2084 (PQ)
   - **Peak Luminance**: 1000 nits (HDR10) or 4000 nits (Dolby)
   - **Color Primaries**: Rec.2020 (or P3 for HDR10)
   - **White Point**: D65

2. **Calibration**:
   - Use Calman or LightSpace with HDR pattern generator
   - Target: 1000 nits peak, 0.005 nits black (200,000:1 contrast)
   - Validate: HDR stripes test (10-100% steps)

3. **Metadata Setup**:
   - MaxCLL (Maximum Content Light Level): Brightest frame (nits)
   - MaxFALL (Maximum Frame-Average Light Level): Brightest average (nits)
   - Example: Sunset shot = 800 nits MaxCLL, 150 nits MaxFALL

**HLG Monitor Setup**:
1. **Display Configuration**:
   - **OOTF**: HLG (B67)
   - **System Gamma**: Auto (adapts to display peak)
   - **Color Primaries**: Rec.2020 (or P3)
   - **White Point**: D65

2. **Calibration**:
   - HLG-specific calibration curves (different from PQ)
   - Target: 1000 nits peak, 0.05 nits black
   - Validate: HLG conformance pattern (ARIB STD-B67)

3. **Auto-Detection**:
   - Modern HDR monitors detect HLG signal (via HDMI 2.0b+)
   - Apply system gamma based on display capability

**HDR Monitor Recommendations**:
- **Grading**: Sony BVM-HX310 (1000 nits, OLED), Dolby Pulsar (4000 nits, LCD)
- **Editing**: ASUS ProArt PA32UCX (mini-LED, 1000 nits)
- **On-Set**: SmallHD 1303 HDR (1000 nits, portable)

### Metadata Management (MaxCLL, MaxFALL)

**MaxCLL (Maximum Content Light Level)**:
- **Definition**: Brightest single pixel in content (nits)
- **Purpose**: Tone mapping on consumer displays (protect highlight clipping)
- **Measurement**: Analyze exported HDR file (Dolby Vision Tools, ffmpeg)
- **Typical Values**: 600-1000 nits (HDR10), 1000-4000 nits (Dolby Vision)

**MaxFALL (Maximum Frame-Average Light Level)**:
- **Definition**: Brightest average luminance across frame (nits)
- **Purpose**: Protect OLED displays from burn-in (sustained bright areas)
- **Measurement**: Frame-by-frame average, take maximum
- **Typical Values**: 100-400 nits (depends on scene brightness)

**Workflow**:
1. **Grade HDR**: Grade for target mastering display (e.g., 1000 nits)
2. **Analyze**: Run metadata analysis tool (Resolve, Dolby Tools)
3. **Review**: Check MaxCLL/MaxFALL values (ensure within spec)
4. **Embed**: Include in HDR10+ Dolby Vision metadata

**Example Analysis**:
```
Scene: Sunset over ocean
MaxCLL: 850 nits (sun reflection)
MaxFALL: 120 nits (frame average, mostly sky/water)

Scene: Indoor office (fluorescent lighting)
MaxCLL: 400 nits (overhead lights)
MaxFALL: 80 nits (dim office)
```

## Failure Modes: Common HDR Mistakes

### PQ/HLG Confusion

**Symptom**: Wrong contrast, incorrect highlight rendering, metadata errors

**Common Mistakes**:
1. **Grading PQ as HLG**: Applying scene-referred grading to display-referred signal
   - Example: Grading PQ footage with HLG monitoring LUT
   - Result: Incorrect contrast (PQ expects absolute nits, HLG scales)

2. **Grading HLG as PQ**: Treating relative signal as absolute
   - Example: HLG footage interpreted as PQ (wrong EOTF)
   - Result: Wrong brightness (HLG 0.75 ≠ PQ 0.75)

3. **Mixing PQ and HLG**: Using both in same timeline without conversion
   - Example: VFX renders in PQ, plates in HLG
   - Result: Visible mismatch at shot boundaries

**Solution**:
- **Choose One**: Commit to PQ or HLG per project (rarely mix)
- **Convert Properly**: Use OCIO transforms (HLG↔PQ conversion via ACES)
- **Label Clearly**: Tag clips with transfer function (PQ/HLG)
- **Test Charts**: Verify with grayscale chart (neutral grays)

### Wrong Mastering Display

**Symptom**: Clipping on consumer displays, tone mapping artifacts

**Common Issues**:
1. **Grading Too Bright**: 4000-nit grade viewed on 600-nit consumer display
   - Example: Dolby Cinema master (4000 nits) → HDR10 consumer (600 nits)
   - Result: Monitor tone mapping (unpredictable, destroys highlights)

2. **Grading Too Dark**: 600-nit grade viewed on 1000-nit display
   - Example: Conservative grade for baseline HDR
   - Result: Wasted HDR capability (undersaturated highlights)

3. **Display Mismatch**: Grading on P3 monitor, delivering Rec.2020
   - Example: Grading HDR on P3 monitor, delivering HDR10 (Rec.2020)
   - Result: Out-of-gamut colors (cyan/magenta issues)

**Solution**:
- **Master for Target**: Grade on display matching deliverable (1000-nit for HDR10)
- **Target Baseline**: Master for 600-1000 nits (typical consumer HDR)
- **Gamut Matching**: Grade in Rec.2020 for HDR10, P3 for Dolby
- **Consumer Testing**: View grade on consumer HDR display (validate)

### Metadata Errors

**Symptom**: Burn-in on OLED displays, tone mapping failures, playback issues

**Common Mistakes**:
1. **MaxFALL Too High**: Sustained brightness causes OLED burn-in
   - Example: MaxFALL 600 nits (bright scene for 30 seconds)
   - Result: Consumer OLED reduces brightness aggressively (APL management)

2. **MaxCLL Too Low**: Wasted HDR capability
   - Example: MaxCLL 400 nits on 1000-nit mastering
   - Result: Conservative tone mapping (no true HDR pop)

3. **Missing Metadata**: No MaxCLL/MaxFALL in HDR10 file
   - Example: Export HDR10 without metadata
   - Result: Consumer display defaults to 1000 nits (may clip)

**Solution**:
- **Measure Properly**: Use analysis tools (Dolby Tools, ffmpeg)
- **Conservative MaxFALL**: Aim <200 nits average (protect OLED)
- **Accurate MaxCLL**: Measure actual peak (don't estimate)
- **Validate Playback**: Test on consumer HDR display (Sony, LG, Samsung)

## Mini Glossary: PQ/HLG Terminology

- **PQ (Perceptual Quantizer)**: Signal-based EOTF defined by SMPTE ST-2084. Encodes absolute luminance (0-10,000 nits). Used for HDR10, Dolby Vision, streaming HDR.

- **HLG (Hybrid Log-Gamma)**: Scene-referred OOTF defined by ARIB STD-B67. Encodes relative luminance (scene-based). Backward compatible with SDR. Used for broadcast HDR.

- **EOTF (Electro-Optical Transfer Function)**: Signal → display luminance mapping. Display-referred encoding. PQ is EOTF-based.

- **OOTF (Opto-Optical Transfer Function)**: Scene light → signal → display light mapping. Scene-referred encoding. HLG is OOTF-based.

- **MaxCLL (Maximum Content Light Level)**: Brightest single pixel in HDR content (nits). Used for tone mapping on consumer displays.

- **MaxFALL (Maximum Frame-Average Light Level)**: Brightest frame average (nits). Protects OLED displays from burn-in.

- **ST-2084**: SMPTE standard defining PQ transfer function. Used for HDR10, Dolby Vision, HDR10+.

- **ARIB STD-B67**: Japanese standard defining HLG transfer function. Used for broadcast HDR (BBC, NHK).

- **Rec.2020**: ITU-R BT.2020 color primaries (UHDTV). Wider gamut than P3, used for HDR10.

- **Perceptual Uniformity**: Transfer function property where equal code value steps ≈ equal perceptual brightness steps. PQ achieves ~12-bit perceptual resolution.

- **Scene-Referred**: Colorimetry representing original scene luminance. HLG is scene-referred.

- **Display-Referred**: Colorimetry optimized for specific display. PQ is display-referred.

- **System Gamma**: Display adaptation factor for HLG. Scales scene to display capability (1.2 for 1000 nits).

- **Backward Compatibility**: HLG displays on SDR monitors (interpreted as gamma). PQ does not display on SDR (appears black).

- **Tone Mapping**: HDR → SDR or high-nit → low-nit conversion. Preserves appearance when display capability is insufficient.

- **APL (Average Picture Level)**: Frame average luminance (nits). OLED displays reduce brightness for high APL (burn-in protection).
