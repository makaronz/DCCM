# 6.2 HDR Standards and Grading Workflows

## Theory: HDR Ecosystem and Standards

### HDR10 (Static Metadata HDR)

**Specification**:
- **EOTF**: SMPTE ST-2084 (PQ)
- **Color Primaries**: Rec.2020 (UHDTV)
- **Bit Depth**: 10-bit (minimum)
- **Metadata**: Static (MaxCLL, MaxFALL) per title
- **Peak Luminance**: 600-10,000 nits (typical: 1000 nits)

**Metadata Structure** (HEVC/H.265):
```
Mastering Display Color Volume:
- Display Primaries: Rec.2020 (xy coordinates)
- White Point: D65
- Min Luminance: 0.005 nits (black)
- Max Luminance: 1000 nits (peak)

Content Light Level:
- MaxCLL: 1000 nits (example)
- MaxFALL: 400 nits (example)
```

**Advantages**:
- **Open Standard**: No licensing fees (unlike Dolby Vision)
- **Widely Supported**: Netflix, Amazon Prime, YouTube TV, physical media
- **Simpler Workflow**: Single-grade deliverable (no per-shot metadata)

**Limitations**:
- **Static Metadata**: Same MaxCLL/MaxFALL for entire title
- **No Creative Control**: Consumer display tone mapping (not artist-controlled)
- **Conservative Mastering**: Grade for baseline (600-1000 nits) to ensure compatibility

### HDR10+ (Dynamic Metadata HDR)

**Specification**:
- **EOTF**: SMPTE ST-2084 (PQ)
- **Color Primaries**: Rec.2020
- **Bit Depth**: 10-bit
- **Metadata**: Dynamic (per-shot or per-frame) via SMPTE ST-2094-10/40
- **Peak Luminance**: 600-4000 nits

**Dynamic Metadata Types**:
1. **ST-2094-10** (Samsung/Samsung HDR10+):
   - Tone mapping parameters per frame
   - Color volume mapping info
   - Roll-off curves

2. **ST-2094-40** (Philips/Technicolor HDR10+):
   - Alternative metadata structure
   - Compatible with ST-2094-10 decoding

**Metadata Examples** (per frame):
```
Frame 100:
- Targeted System Display Peak Brightness: 1000 nits
- Anchor Point: (0.5, 100 nits)
- Weight: 0.8
- Knee Point: 0.75
- Knee Strength: 1.5

Frame 101:
- Targeted System Display Peak Brightness: 800 nits
- Anchor Point: (0.6, 150 nits)
- Weight: 0.7
- Knee Point: 0.72
- Knee Strength: 1.3
```

**Advantages**:
- **Creative Control**: Artist controls tone mapping per shot
- **Better Adaptation**: Optimized for different consumer displays (600-4000 nits)
- **Open Standard**: Competitor to Dolby Vision (no licensing)

**Limitations**:
- **Complex Workflow**: Requires HDR10+ authoring tools (Panther, Cobble)
- **Smaller Ecosystem**: Limited adoption vs. Dolby Vision
- **Hardware Support**: Samsung, Panasonic, Philips (limited vs. Dolby)

### Dolby Vision (Proprietary HDR)

**Specification** (Dolby Vision 8.1/9.0):
- **EOTF**: SMPTE ST-2084 (PQ) or proprietary (Dolby Vision ICC)
- **Color Primaries**: Rec.2020 (or P3 for cinema)
- **Bit Depth**: 12-bit (Dolby Vision 8.1), 10-bit (Dolby Vision 9.0)
- **Metadata**: Dynamic (per-frame) via proprietary XML
- **Peak Luminance**: Up to 10,000 nits (typical: 4000 nits for cinema)

**Dolby Vision Versions**:
- **Dolby Vision Profile 5**: 4000-nit mastering, 12-bit, dual-layer (base + enhancement)
- **Dolby Vision Profile 8.1**: 1000-nit mastering, 12-bit, single-layer (streaming)
- **Dolby Vision Profile 9.0**: 1000-nit mastering, 10-bit, single-layer (broadcast)

**Metadata Structure** (per frame):
```
Dolby Vision XML (simplified):
Frame 001:
- RpuDataVersion: 1.0
- YccToRgbCoef: [matrix coefficients]
- ExtendingBlock:
  - Level1: [brightness mapping for 600-nit display]
  - Level2: [brightness mapping for 1000-nit display]
  - Level3: [brightness mapping for 4000-nit display]
  - ReshapeData: [color volume mapping]
  - NitReshaping: [brightness redistribution]
```

**Advantages**:
- **Best Quality**: Per-frame metadata optimizes tone mapping
- **Cinema Support**: Dolby Cinema (4000-nit dual-layer modulator)
- **Ecosystem**: Major studios, streaming services, physical media

**Limitations**:
- **Proprietary**: Licensing fees ($5,000-20,000 per title)
- **Complex Workflow**: Requires Dolby Vision mastering tools (CMU)
- **Limited Distribution**: Dolby-enabled displays/players required

### Hybrid Log-Gamma (HLG) Standard

**Specification**:
- **OOTF**: ARIB STD-B67 (HLG)
- **Color Primaries**: Rec.2020
- **Bit Depth**: 10-bit
- **Metadata**: Optional (HLG Phase 2 adds dynamic metadata)
- **Peak Luminance**: 1000 nits (system peak)

**Backward Compatibility**:
- **SDR Display**: HLG interpreted as gamma (similar to Rec.709)
- **HDR Display**: HLG detected, system gamma applied (auto adaptation)

**HLG Phase 2** (emerging, 2024+):
- Adds dynamic metadata to HLG (similar to HDR10+/Dolby Vision)
- Improves tone mapping for consumer displays
- Backward compatible with HLG Phase 1 (fallback to OOTF)

**Advantages**:
- **Broadcast-Ready**: Designed for live production (no metadata generation)
- **Backward Compatible**: Same signal works for SDR/HDR
- **Simple Workflow**: Grade once, deliver to both

**Limitations**:
- **Lower Peak**: 1000-nit limit (vs. 4000+ for Dolby)
- **Limited Ecosystem**: Mostly broadcast (BBC, NHK), limited streaming
- **Less Creative Control**: No per-frame metadata (Phase 1)

### ITU-R BT.2100 and BT.2408 Standards

**ITU-R BT.2100** (HDR Parameter Values):
- Defines HDR parameters for production (PQ, HLG, Rec.2020)
- Standardizes EOTF/OOTF functions (ST-2084, B67)
- Specifies color volume mapping guidelines

**ITU-R BT.2408** (HDR Grading Guidelines):
- HDR grading best practices
- Display management recommendations
- SDR→HDR→SDR workflow guidelines

**Key Recommendations**:
- **Mastering Display**: 1000 nits (baseline), 4000 nits (cinema)
- **Color Volume**: Rec.2020 for HDR10, P3 for Dolby Cinema
- **Grading Environment**: Dim surround (5 nits ambient), D65 white point
- **Target Displays**: Grade for multiple displays (600, 1000, 4000 nits)

## Practice: HDR Grading Workflows

### HDR10 Grading Workflow

**Setup** (DaVinci Resolve):
1. **Project Settings**:
   - **Color Space**: Rec.2020
   - **Gamma**: ST-2084 (PQ)
   - **Timeline Color Space**: Rec.2020 + ST-2084

2. **Monitor Setup**:
   - **HDR Mode**: On (PQ)
   - **Peak Luminance**: 1000 nits
   - **Color Primaries**: Rec.2020 (or P3 if monitor limited)

3. **Grading Strategy**:
   - **Middle Gray**: 10 nits (code value ~0.58)
   - **Peak Highlights**: 600-1000 nits (code value 0.75-0.95)
   - **Black Level**: 0.005 nits (code value 0.0)

4. **Grading Steps**:
   ```
   a. Set contrast/exposure: Middle gray at 10 nits
   b. Set highlights: Preserve up to 1000 nits (no clipping)
   c. Set shadows: Lift black level (0.005 nits target)
   d. Color grading: Saturation in Rec.2020 (wider gamut than P3)
   e. Validate: Check MaxCLL/MaxFALL (use HDR analyzer)
   ```

5. **Export**:
   - **Format**: HEVC/H.265 (10-bit)
   - **Metadata**: Embed MaxCLL/MaxFALL (auto-detected or manual)
   - **Color Space**: Rec.2020 + ST-2084

**HDR10 Deliverable**:
- **Streaming**: Netflix (4K HDR), Amazon Prime (4K HDR)
- **Physical Media**: Ultra HD Blu-ray (HDR10)
- **Gaming**: PlayStation 5, Xbox Series X (HDR10)

### Dolby Vision Grading Workflow

**Setup** (Dolby Vision CMU + Resolve):
1. **Dolby Vision Project**:
   - **Profile**: 8.1 (4000-nit) or 9.0 (1000-nit)
   - **Mastering Display**: 4000-nit Dolby Cinema or 1000-nit reference
   - **Color Primaries**: Rec.2020

2. **Dolby Vision CMU** (Content Mastering Unit):
   - **Trim Passes**: Create trim passes for 600, 1000, 4000 nit displays
   - **Metadata Generation**: Auto-generate per-frame metadata
   - **Validation**: Check metadata quality (Dolby Vision Tools)

3. **Grading Strategy**:
   - **Base Layer**: Grade for 1000-nit reference (baseline)
   - **Trim Pass 1**: Optimize for 600-nit display (consumer)
   - **Trim Pass 2**: Optimize for 4000-nit display (cinema)

4. **Grading Steps**:
   ```
   a. Base Layer (1000-nit reference):
      - Middle gray: 10 nits
      - Highlights: Up to 1000 nits
      - Color grading: Rec.2020 gamut

   b. Trim Pass 1 (600-nit display):
      - Tone map highlights: 1000 → 600 nits
      - Adjust contrast: Preserve mid-tone separation
      - Validate: Compare to base layer

   c. Trim Pass 2 (4000-nit display):
      - Extend highlights: 1000 → 4000 nits (if desired)
      - Add highlight detail: Recover clipped areas
      - Validate: Check 4000-nit monitor (if available)

   d. Metadata Review:
      - Check metadata: Per-frame tone mapping curves
      - Validate: Trim passes match creative intent
   ```

5. **Export**:
   - **Format**: HEVC/H.265 with Dolby Vision XML (profile 8.1/9.0)
   - **Metadata**: Embed Dolby Vision metadata (XML)
   - **Validation**: Dolby Vision Tools (conformance check)

**Dolby Vision Deliverable**:
- **Streaming**: Netflix (Dolby Vision), Disney+, Apple TV+
- **Cinema**: Dolby Cinema (4000-nit dual-layer)
- **Physical Media**: Ultra HD Blu-ray (Dolby Vision)

### HDR10+ Grading Workflow

**Setup** (Samsung HDR10+ Tools):
1. **HDR10+ Project**:
   - **Base HDR10**: Grade base HDR10 (1000-nit reference)
   - **Metadata**: Generate ST-2094-10/40 per-frame metadata
   - **Target Displays**: 600, 1000, 4000 nit

2. **HDR10+ Authoring Tools**:
   - **Panther**: Samsung's HDR10+ authoring tool
   - **Cobble**: Alternative HDR10+ tool

3. **Grading Strategy**:
   - **Base Layer**: HDR10 grade (same as HDR10 workflow)
   - **Metadata Layers**: Add tone mapping metadata per shot

4. **Grading Steps**:
   ```
   a. Base HDR10 Grade:
      - Same as HDR10 workflow (middle gray 10 nits)
      - Highlights up to 1000 nits
      - Color grading in Rec.2020

   b. Metadata Creation:
      - Define anchor points: (code value, luminance) pairs
      - Set knee points: Highlight rolloff position
      - Adjust weights: Priority of tone mapping

   c. Trim Passes (optional):
      - 600-nit display: Tone map highlights
      - 4000-nit display: Extend highlights
      - Validate: Compare to base HDR10

   d. Metadata Validation:
      - Check metadata: Per-frame continuity
      - Test playback: Samsung HDR10+ display
   ```

5. **Export**:
   - **Format**: HEVC/H.265 with HDR10+ metadata (ST-2094-10/40)
   - **Metadata**: Embed dynamic metadata
   - **Validation**: HDR10+ conformance tool

**HDR10+ Deliverable**:
- **Streaming**: Amazon Prime Video (select titles)
- **Hardware**: Samsung, Panasonic, Philips TVs

### HLG Grading Workflow

**Setup** (DaVinci Resolve):
1. **Project Settings**:
   - **Color Space**: Rec.2020
   - **Gamma**: HLG (ARIB STD-B67)
   - **Timeline Color Space**: Rec.2020 + HLG

2. **Monitor Setup**:
   - **HLG Mode**: On (auto-detect HLG signal)
   - **Peak Luminance**: 1000 nits (system peak)
   - **System Gamma**: Auto (adapts to display)

3. **Grading Strategy**:
   - **Middle Gray**: 25% signal (code value 0.25)
   - **Peak Highlights**: 100% signal (code value 1.0 = 1000 nits)
   - **Scene-Referred**: Preserve scene contrast (relative grading)

4. **Grading Steps**:
   ```
   a. Set contrast/exposure: Middle gray at 0.25
   b. Set highlights: Preserve up to 1000 nits (0.75-1.0)
   c. Set shadows: Lift black level (0.0-0.05)
   d. Color grading: Saturation in Rec.2020
   e. Validate: Check on HLG monitor (auto system gamma)
   ```

5. **Export**:
   - **Format**: HEVC/H.265 (10-bit) or H.264/AVC (broadcast)
   - **Color Space**: Rec.2020 + HLG
   - **Metadata**: Optional (HLG Phase 2)

**HLG Deliverable**:
- **Broadcast**: BBC, NHK, Freeview (UK)
- **Streaming**: Limited (YouTube accepts HLG)
- **Hardware**: Most HDR TVs support HLG

### Display Management for Multiple Deliverables

**Challenge**: Grade once for HDR10, HDR10+, Dolby Vision, HLG

**Solution**: Display-managed workflow with ACES

**ACES HDR Workflow**:
```
1. Grade in ACEScg (scene-linear, AP1 primaries)
2. Create LMT (Look Modification Transform)
3. Export via ODTs:
   - ODT HDR10 (PQ 1000-nit)
   - ODT HDR10+ (PQ + dynamic metadata)
   - ODT Dolby Vision (PQ + Dolby XML)
   - ODT HLG (B67 1000-nit)
```

**Advantages**:
- **Single Grade**: Grade once in ACES, deliver to all HDR formats
- **Consistency**: Same creative look across all deliverables
- **Future-Proof**: Add new HDR formats via new ODTs

**Implementation**:
- Use OCIO-ACES v2.0+ (includes HDR ODTs)
- Generate HDR ODTs for each format
- Validate on reference displays (600/1000/4000 nits)

## Failure Modes: Common HDR Grading Issues

### Wrong HDR Flavor

**Symptom**: Color mismatch, playback issues, metadata ignored

**Common Mistakes**:
1. **Grading HDR10, Delivering Dolby Vision**:
   - Example: Grade HDR10, attempt to export as Dolby Vision
   - Result: Missing metadata (Dolby Vision not created)

2. **Grading HLG, Delivering HDR10**:
   - Example: HLG grade interpreted as PQ (wrong EOTF)
   - Result: Incorrect contrast/tonality (HLG 0.5 ≠ PQ 0.5)

3. **Dolby Vision Profile Mismatch**:
   - Example: Graded Profile 8.1, exported Profile 9.0
   - Result: Bit depth mismatch (12 vs 10-bit)

**Solution**:
- **Choose Target**: Decide HDR format before grading (HDR10/HDR10+/Dolby/HLG)
- **Use Correct Project Settings**: Match EOTF/Color Space to target
- **Test Deliverable**: Validate exported file on reference display

### Metadata Mismatch

**Symptom**: Tone mapping artifacts, playback failures, display incompatibility

**Common Issues**:
1. **Missing MaxCLL/MaxFALL**: HDR10 file lacks metadata
   - Example: Export HDR10 without analyzing MaxCLL/MaxFALL
   - Result: Consumer display defaults (may clip or over-tone map)

2. **Incorrect MaxCLL**: MaxCLL set too high/low
   - Example: MaxCLL 4000 nits for 1000-nit grade
   - Result: Consumer display tone mapping (wrong expectation)

3. **Dolby Vision Metadata Errors**: XML corrupted or missing frames
   - Example: Dolby Vision XML missing per-frame data
   - Result: Playback fails (metadata parsing error)

**Solution**:
- **Analyze Metadata**: Use HDR analyzer tools (Resolve, Dolby Tools)
- **Validate Deliverable**: Test on consumer displays (Sony, LG, Samsung)
- **Check XML**: Validate Dolby Vision XML (Dolby Tools)

### Display Incompatibility

**Symptom**: Grade looks different on consumer displays, clipping, banding

**Common Issues**:
1. **Mastering Display Mismatch**:
   - Example: Grade on 1000-nit P3 monitor, deliver Rec.2020 HDR10
   - Result: Out-of-gamut colors (cyan/magenta issues)

2. **EOTF Confusion**:
   - Example: Monitor set to HLG, grading HDR10 (PQ)
   - Result: Wrong contrast (HLG OOTF vs. PQ EOTF)

3. **Display Calibration Drift**:
   - Example: Monitor not calibrated (1000 nits → 600 nits)
   - Result: Grade too bright (overestimated peak)

**Solution**:
- **Match Mastering Display**: Use display matching deliverable (Rec.2020 for HDR10)
- **Verify EOTF**: Check monitor EOTF settings (PQ vs. HLG)
- **Regular Calibration**: Calibrate monthly (Calman, LightSpace)

## Mini Glossary: HDR Standards Terminology

- **HDR10**: Open HDR standard (static metadata). Uses PQ EOTF, Rec.2020 primaries, 10-bit. No licensing fees. Widely supported (Netflix, Amazon, physical media).

- **HDR10+**: Dynamic metadata HDR standard (ST-2094-10/40). Per-frame tone mapping. Competitor to Dolby Vision. Open standard, limited ecosystem (Samsung, Panasonic).

- **Dolby Vision**: Proprietary HDR standard (dynamic metadata). Per-frame XML metadata, 12-bit (Profile 8.1) or 10-bit (Profile 9.0). Licensing required. Best quality, wide ecosystem.

- **HLG (Hybrid Log-Gamma)**: Broadcast HDR standard (scene-referred OOTF). Backward compatible with SDR. No metadata required (Phase 1). Used for live production (BBC, NHK).

- **ST-2094-10/40**: SMPTE standards for HDR10+ dynamic metadata. Define tone mapping parameters per frame (knee point, anchor points, weights).

- **Dolby Vision CMU**: Content Mastering Unit. Dolby's HDR grading and metadata authoring tool. Creates trim passes for different displays.

- **Dolby Vision Profiles**: Specific Dolby Vision configurations. Profile 5 (4000-nit, 12-bit, dual-layer), Profile 8.1 (1000-nit, 12-bit, streaming), Profile 9.0 (1000-nit, 10-bit, broadcast).

- **Dynamic Metadata**: Per-frame or per-shot HDR metadata (tone mapping, color volume). Enables creative control across different consumer displays (Dolby Vision, HDR10+).

- **Static Metadata**: Single set of HDR metadata for entire title (MaxCLL, MaxFALL). Used in HDR10. Less flexible than dynamic metadata.

- **Rec.2020**: ITU-R BT.2020 color primaries (UHDTV). Wider gamut than P3, covers 75.8% of Pointer's gamut. Used for HDR10, HDR10+, Dolby Vision.

- **Display Management**: Tone mapping from high-nit mastering display to low-nit consumer display (4000 → 600 nits). Critical for HDR10 (static metadata).

- **Trim Passes**: Separate grades optimized for different peak luminances (600/1000/4000 nits). Used in Dolby Vision workflow.

- **Backward Compatibility**: HLG displays on SDR monitors (interpreted as gamma). HDR10 does not display on SDR (appears black).

- **Conformance Check**: Validation of HDR deliverable (metadata, EOTF, color space). Dolby Vision Tools, HDR10+ conformance tools.
