# 5.3 Integrating ACES into Production Pipelines

## Theory: ACES Ecosystem and Tools

### ACES Components and Architecture

**Core Components**:
1. **ACES2065-1**: Scene-linear interchange format (16-bit EXR, AP0 primaries)
2. **IDT (Input Device Transform)**: Camera → ACES2065-1 conversion
3. **LMT (Look Modification Transform)**: Creative look application
4. **RRT (Reference Rendering Transform)**: Scene → display rendering (ACES 2.0 flexible)
5. **ODT (Output Device Transform)**: Display-specific tone + gamut mapping

**Transform Chain**:
```
Capture → IDT → ACES2065-1 → ACEScg → [Grading] → LMT → ACESrender → ODT → Display
```

**Software Ecosystem**:
- **OCIO-ACES**: OpenColorIO configuration (v2.0+) with all ACES transforms
- **CTL (Color Transform Language)**: Transform programming language
- **ACEScentral**: Academy resource center (documentation, transforms, tools)
- **Vendor Implementations**: Resolve, Nuke, Baselight, Scratch, etc.

### CTL Transforms and Rendering

**CTL Language Features**:
- C-like syntax for color math (matrix transforms, tone curves, gamut mapping)
- GPU-accelerated rendering via CTLrender
- Platform-independent (Windows, macOS, Linux)

**Transform Categories**:
```
IDT Transforms:
- lib/CTL/ARRI.IDT.cpp (LogC4 → ACES)
- lib/CTL/RED.IDT.cpp (RWG/IPP2 → ACES)
- lib/CTL/Sony.IDT.cpp (S-Log3 → ACES)

LMT Transforms:
- lib/CTL/LMT.*.cpp (Creative looks, CDL conversion)

ODT Transforms:
- lib/CTL/ODT.Rec709.48nit.cpp (SDR)
- lib/CTL/ODT.PQ.1000nit.cpp (HDR10)
- lib/CTL/ODT.PQ.4000nit.cpp (Dolby Cinema)
```

**CTL Rendering**:
```bash
# Render IDT transform
ctlrender -ctl lib/CTL/ARRI.IDT.cpp \
         -format exr \
         -input scene_logc4.exr \
         -output aces2065-1.exr

# Render ODT transform with LMT
ctlrender -ctl lib/CTL/LMT.example.cpp \
         -ctl lib/CTL/ODT.Rec709.48nit.cpp \
         -format exr \
         -input graded_acescg.exr \
         -output output_rec709.exr
```

### ACES-Related Tools and Libraries

**OpenColorIO (OCIO)**:
- Industry-standard color management framework
- OCIO-ACES config provides ACES transform definitions
- Integrates with Resolve, Nuke, Silhouette, Katana, etc.

**CTL Rendering Tools**:
- **CTLrender**: Command-line CTL executor (included in CTL SDK)
- **OpenColorIO CTL**: OCIO's CTL renderer (faster, GPU-accelerated)

**LUT Generation Tools**:
```bash
# ociobakelut: Generate 3D LUT from OCIO transform
ociobakelut --input-space "ACES - ACES2065-1" \
            --output-space "Output - Rec.709 - 48 nits" \
            --format cubelut \
            --size 33 \
            --output odt_rec709.cube

# ociobakelut: Generate 1D LUT (tone curve only)
ociobakelut --input-space "ACES - ACEScg" \
            --output-space "ACES - ACES2065-1" \
            --format shaper \
            --output acescg_to_aces2065.spi1d
```

**ACES Metadata Tools**:
- **acescomposer**: Compose multi-part CTL transforms
- **acescvt**: Convert between ACES transforms
- **acesconvert**: Apply ACES transforms to images

**Vendor Tools**:
- **DaVinci Resolve**: Native ACES support (OCIO 2.0+)
- **Nuke**: ACES via OCIO config
- **Baselight**: ACES via FLUX Color Space Manager
- **Adobe Premiere/After Effects**: ACES via Lumetri Color (limited)

## Practice: ACES Implementation

### OCIO-ACES Configuration

**Installation**:
```bash
# Download OCIO-ACES v2.0
wget https://github.com/ampas/OCIO-ACES/releases/download/v2.0/config.ocio

# Set environment variable
export OCIO=/path/to/config.ocio

# Verify installation
ociocheck --profile config.ocio
```

**Config Structure**:
```
config.ocio
├── colorspaces/
│   ├── ACES - ACES2065-1
│   ├── ACES - ACEScg
│   ├── Input - ARRI - Wide Gamut 3 - LogC3
│   ├── Input - ARRI - Wide Gamut 4 - LogC4
│   ├── Input - RED - REDcolor4 - REDlog3G
│   ├── Input - Sony - S-Gamut3 - S-Log3
│   └── Output - Rec.709 - 48 nits
├── displays/
│   ├── sRGB
│   ├── Rec.709 (Gamma 2.4)
│   └── P3-D60
└── views/
    ├── Input Transforms
    └── Output Transforms
```

**Config Customization**:
```python
# Add custom LMT to config
colorspaces:
  - name: LMT - ProjectX Look
    family: LMT
    encoding: scene-linear
    to_reference: !<ColorSpaceTransform>
      src: LMT_ProjectX_Look
      dst: ACES - ACES2065-1

roles:
  color_picking: ACES - ACEScg
  color_timing: ACES - ACEScg
  compositing_log: Input - ARRI - Wide Gamut 4 - LogC4
```

### DaVinci Resolve ACES Setup

**Project Configuration**:
1. **Preferences** → **Color Management**
   - **Color Science**: ACES
   - **OCIO Config**: Custom → Browse to config.ocio
   - **Default Color Space**: ACES - ACES2065-1
   - **Timeline Color Space**: ACES - ACEScg

2. **Clip Settings** (per camera)
   - Right-click clip → **Clip Color Space**
   - **Input Color Space**: Input → Manufacturer → Model → Log Encoding
   - Example: ARRI → Alexa → Wide Gamut 4 - LogC4

3. **Monitoring Setup**
   - Right-click viewer → **Video Monitor**
   - **Video LUT**: Output → Rec.709 - 48 nits (for SDR grading)
   - Or: Output → PQ - 1000 nits (for HDR grading)

4. **Export Settings**
   - **Deliver** page → **Color Space** tab
   - **Output Color Space**: ACES - ACES2065-1 (for archival EXR)
   - Or: Output → Rec.709 (baked ODT for quick delivery)

**ACES Grading Workflow in Resolve**:
```
1. Import footage (auto IDT detection from metadata)
2. Set timeline to ACEScg
3. Apply viewing ODT (Rec.709 48 nits)
4. Grade in ACEScg (color wheels, curves, qualifiers)
5. Create LMT (grade stored as CTL or CDL)
6. Export via ODTs for each deliverable
```

### Baselight ACES Setup

**FLUX Color Space Manager**:
1. **Setup** → **Color Spaces** → **Add ACES**
   - Import OCIO-ACES config
   - Set base color space: ACES2065-1
   - Set working color space: ACEScg

2. **Scene Configuration**
   - **Input**: ACES IDT per shot (auto or manual)
   - **Working**: ACEScg (grading space)
   - **Output**: ODT per monitoring (Rec.709, P3, PQ)

3. **Grade Layer Setup**
   - Grade in ACEScg (Base layer)
   - Create LMT layer (CDL + grade)
   - Output layers with ODTs per deliverable

**Baselight Advantages**:
- Native ACES support via FLUX
- Multi-stream grading (grade SDR/HDR simultaneously)
- ACES LMT creation and management

### Nuke ACES Setup

**OCIO Configuration**:
```python
# Init.py or menu.py
import PyOpenColorIO as OCIO

# Set ACES config
config = OCIO.Config.CreateFromFile("/path/to/config.ocio")
OCIO.SetCurrentConfig(config)

# Default color spaces for nodes
nuke.knobDefault("Read.colorspace", "Input - ARRI - Wide Gamut 4 - LogC4")
nuke.knobDefault("Write.colorspace", "ACES - ACES2065-1")
```

**Nuke Script Setup**:
```python
# Read node: Input color space
Read.colorspace = "Input - Sony - S-Gamut3 - S-Log3"

# Write node: Output color space
Write.colorspace = "ACES - ACES2065-1"
Write.file = "/shots/SC001/plates/SC001_0100.####.exr"

# ColorCorrect node: Works in ACEScg (automatically)
ColorCorrect.colorspace = "ACES - ACEScg"

# Viewer: Apply ODT for monitoring
Viewer.process = "Output - Rec.709 - 48 nits"
```

**VFX Pipeline**:
```
Plate Shot → IDT → ACES2065-1 → CG Render (ACEScg) → Comp → ACES2065-1 → ODT → Review
```

**Livegrade Pro ACES Workflow**:

   - **OCIO Config**: Load config.ocio

2. **Shot Setup**
   - **Input**: Camera IDT (ARRI LogC4, Sony S-Log3)

```

```

### ACES LUT Generation

**Generate ODT LUTs for Monitoring**:
```bash
# Resolve: Project Settings → Color Management → ACES
# Monitor Output Device → Rec.709 48 nits
# Export: 3D LUT 33x33x33, .cube format

# Command line (ociobakelut)
ociobakelut --input-space "ACES - ACES2065-1" \
            --output-space "Output - Rec.709 - 48 nits" \
            --format cubelut \
            --size 33 \
            --shapersize 1024 \
            --output ACES_to_Rec709_48nit.cube
```

**Apply LUT in Non-OCIO Software**:
- **Premiere Pro**: Lumetri Color → Input LUT → Select .cube
- **Final Cut Pro**: Effects → Color Wheels → LUT
- **Photoshop**: Image → Mode → 32-bit → Apply LUT

**LUT Applications**:
- On-set monitoring (transmit to director's monitor)
- Dailies generation (quick viewing LUT)
- Software without ACES support (interim solution)

## Failure Modes: Common Integration Issues

### Wrong OCIO Configuration

**Symptom**: Color shifts, missing color spaces, transform errors

**Common Mistakes**:
1. **Outdated OCIO Config**: Using OCIO-ACES 1.x instead of 2.0
   - Missing ACES 2.0 transforms (HDR ODTs, new RRT)
   - Incompatibility with latest software versions

2. **Custom Config Conflicts**: Mixing vendor config with OCIO-ACES
   - Example: Using custom ARRI config + OCIO-ACES ODTs
   - Result: Color space mismatch, incorrect transforms

3. **Missing Environment Variable**: OCIO not set
   - Software falls back to default config
   - Missing ACES color spaces in dropdowns

**Solution**:
- **Use Official OCIO-ACES**: Download latest from GitHub (v2.0+)
- **Set OCIO Environment**: `export OCIO=/path/to/config.ocio`
- **Verify Config**: `ociocheck --profile config.ocio`
- **Document Config Version**: Include in project documentation

### Transform Chain Errors

**Symptom**: Double transforms, missing transforms, color grading not applying

**Common Issues**:
1. **Double IDT**: Applying IDT twice (in camera metadata + manually)
   - Example: Clip has ACES IDT metadata, manually apply IDT again
   - Result: Extreme color shifts, contrast issues

2. **Missing ODT**: Grading in ACES but viewing without ODT
   - Example: Monitoring ACEScg directly (scene-linear, 0-18 stops)
   - Result: Very dark image, crushed blacks

3. **Wrong Order**: Applying ODT before grade
   - Example: Add ODT node before color correction
   - Result: Grading applied to display-referred image (wrong color space)

**Solution**:
- **Transform Chain Order**: IDT → Grade → LMT → ODT
- **Monitor with ODT**: Always view through ODT (except technical checks)
- **Verify Chain**: Check node graph/grade stack for correct order
- **Test with Chart**: Verify with grayscale chart (neutral grays after IDT)

### Version Conflicts

**Symptom**: Different looks between software versions, broken references

**Scenarios**:
1. **Software Version Mismatch**:
   - Resolve 18.6 (ACES 2.0) vs. Resolve 17.x (ACES 1.x)
   - Different RRT implementations, different ODTs
   - Result: Look changes between versions

2. **Transform Version Mismatch**:
   - Using OCIO-ACES 1.0 IDT with 2.0 ODT
   - Legacy RRT with ACES 2.0 workflow
   - Result: Inconsistent rendering

3. **LMT Version Conflicts**:
   - Different LMT versions in different software
   - Example: Nuke uses LMT v1.0, Resolve uses v1.1
   - Result: Look diverges between VFX and color

**Solution**:
- **Version Locking**: Tag OCIO config version in project documentation
- **Software Sync**: Use consistent software versions across pipeline
- **Transform Validation**: Test transforms across all software before production
- **Archive Configs**: Store OCIO config with project for archival

### IDT Selection Errors

**Symptom**: Wrong color balance, incorrect contrast, saturation issues

**Common Mistakes**:
1. **Generic IDT**: Using generic camera IDT instead of specific model
   - Example: "Sony IDT" instead of "Sony VENICE 2 IDT"
   - Result: Color shifts, incorrect white balance

2. **Log Encoding Mismatch**: Using IDT for wrong log format
   - Example: ARRI LogC3 IDT on LogC4 footage
   - Result: Contrast/gamma mismatch

3. **Custom Settings**: Camera using custom settings (EI, white balance)
   - IDT designed for standard settings
   - Result: Exposure/color shift

**Solution**:
- **Check Metadata**: Verify camera model and log encoding from clip metadata
- **Use Latest IDTs**: Download latest manufacturer IDTs from ACEScentral
- **Test with Chart**: Shoot grayscale + color chart, verify neutral after IDT
- **Custom IDTs**: Use manufacturer IDT calculator for non-standard setups

## Mini Glossary: ACES Integration Terms

- **CTL (Color Transform Language)**: ACES transform programming language (C-like syntax). Used for IDT, ODT, LMT definitions. Rendered via CTLrender or OpenColorIO.

- **OCIO-ACES**: OpenColorIO configuration for ACES transforms. Provides color space definitions, roles, and display/view mappings for ACES workflow. Current version: v2.0 (2024).

- **ACEScentral**: Academy's official ACES resource center (https://acescentral.com). Hosts documentation, transforms, tools, tutorials, and community forum.

- **ACES Metadata**: Embedded data in media files describing IDT, white balance, exposure, timecode, and camera model. Enables automated ACES workflow.

- **Transform Version**: Specific iteration of ACES transform (IDT v1.2, ODT v2.0, RRT a1.0.3). Version changes indicate bug fixes, new features, or improved color science.

- **IDT (Input Device Transform)**: Camera log encoding to ACES2065-1 conversion. Manufacturer-specific (ARRI, RED, Sony), firmware-specific, and designed for specific camera model.

- **ODT (Output Device Transform)**: ACES2065-1 to display-specific conversion. Includes tone mapping (scene → display) and gamut mapping (AP0/AP1 → Rec.709/P3/Rec.2020).

- **LMT (Look Modification Transform)**: Creative look transform applied in ACES workflow. Replaces CDL, stores contrast/saturation/color decisions. Can be CTL, 3D LUT, or CDL format.

- **RRT (Reference Rendering Transform)**: Scene-to-display rendering transform. ACES 1.x: Fixed "Academy look" (deprecated). ACES 2.0: Flexible rendering pipeline (ACESrender).

- **ACEScg**: Working color space (AP1 primaries, linear gamma). Used for grading, VFX rendering, compositing. Default working space in OCIO-ACES config.

- **ACES2065-1**: Archival interchange format (AP0 primaries, scene-linear). 16-bit EXR format, largest gamut, future-proof archival master.

- **OCIO (OpenColorIO)**: Industry-standard color management framework. Provides consistent color space definitions and transforms across software applications.

- **CTLrender**: Command-line tool for rendering CTL transforms. Applies IDT/ODT/LMT to images, used for batch processing and LUT generation.

- **3D LUT**: 3D lookup table (RGB → RGB'). Used for applying ODTs/LMTs in software without ACES support. Generated via ociobakelut or CTLrender.

- **Display Management**: Process of mapping scene-referred ACES image to display-referred output (ODT). Includes tone mapping, gamut mapping, and display-specific rendering.

- **Look Creation**: Designing creative appearance (contrast, color, saturation) in ACES workflow. Implemented via LMT, CDL, or grade stored in ACEScg.

- **Color Space Roles**: OCIO concept defining default color spaces for specific tasks (color_picking: ACEScg, scene_linear: ACES2065-1).
