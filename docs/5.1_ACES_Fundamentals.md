# 5.1 ACES Fundamentals

## Theory: ACES Architecture and Color Science

### ACES System Architecture

The **Academy Color Encoding System (ACES)** represents a comprehensive color management architecture designed for motion picture, television, and streaming media. At its core, ACES provides:

- **Device Independence**: Separation of capture (Input Device Transform - IDT) from display (Output Device Transform - ODT)
- **Archival Stability**: ACES2065-1 (ACES Scene Linear) uses 16-bit half-float (EXR) encoding with industry-standard primaries
- **Interchange Format**: Universal color space for VFX, color grading, and archival mastering
- **Future-Proofing**: Gamut larger than any current camera or display technology

### Color Primaries and White Point

**AP0 (ACES Primaries 0)**: Original ACES2065-1 encoding primaries
- Defined by spectral integration over visible spectrum (380-780nm)
- CIE xy coordinates:
  - Red: (0.7347, 0.2653)
  - Green: (0.0000, 1.0000)
  - Blue: (0.0001, -0.0770)
  - White: D65 (0.32168, 0.33767)

**AP1 (ACES Primaries 1)**: Working color space for ACEScg (OCIO)
- Optimized for computational efficiency and color volume
- 17% larger than P3, matches typical cinema projector gamuts
- CIE xy coordinates:
  - Red: (0.6130, 0.3400)
  - Green: (0.2940, 0.6140)
  - Blue: (0.1550, 0.0430)
  - White: D60 (0.32168, 0.33767)

**Why AP1 over AP0 for grading?**
- Minimizes negative RGB values during color operations
- Better suited for GPU operations (ACEScg in OCIO)
- Reduces precision errors in color transformations
- Maintains visual fidelity for practical color volumes

### ACES 2.0 Architecture (2024 Release)

**Key Changes from ACES 1.x:**

1. **Next-Generation RRT (Reference Rendering Transform)**
   - Deprecated original RRT+ODT architecture
   - New **ACESrender** node-based rendering framework
   - Improved highlight rendering with film-like rolloff
   - Separation of tone mapping from creative look

2. **Transform Architecture**
   - **IDT → LMT (Look Modification Transform) → RRT → ODT**
   - LMTs now integrated into OCIO workflow
   - ACES 2.0 OCIO configs include legacy RRT for compatibility

3. **ACES 2.0 Primaries**
   - Maintains AP0 for interchange (ACES2065-1)
   - AP1 for working space (ACEScg)
   - New rendering primaries under consideration (AP2 proposals)

4. **HDR Support**
   - Native HDR support up to 10,000 nits
   - PQ and HLG ODTs included in standard transforms
   - Display-managed rendering for SDR/HDR hybrid workflows

### Mathematical Definitions

**ACES2065-1 Encoding** (Scene Linear):
```
C_aces = 3 × ∫ S(λ) × C_cam(λ) dλ / ∫ S(λ) × Y_cam(λ) dλ
```
Where:
- C_aces = ACES RGB value (linear)
- S(λ) = Spectral sensitivity of camera
- C_cam(λ) = Camera spectral sensitivities
- Y_cam(λ) = Luminance sensitivity

**ACEScg Conversion** (AP1 primaries):
```
[ACEScg_R]                     [ACES_R]
[ACEScg_G] = CMatrix_AP1_AP0 × [ACES_G]
[ACEScg_B]                     [ACES_B]
```

Where CMatrix_AP1_AP0 is the 3×3 conversion matrix from AP0 to AP1 primaries.

### RRT+ODT Workflow (Legacy vs. ACES 2.0)

**Legacy ACES 1.x Flow:**
```
Camera → IDT → ACES2065-1 → ACEScg → [Grading] → ACES2065-1 → RRT → ODT → Display
```

**ACES 2.0 Flow:**
```
Camera → IDT → ACES2065-1 → ACEScg → [Grading] → ACESrender → ODT → Display
                                                    ↓
                                              (Look + Tone Mapping)
```

**Key Differences:**
- **ACES 1.x**: Fixed RRT applies "Academy look" (slight desaturation in highlights)
- **ACES 2.0**: Flexible rendering pipeline, creative looks via LMTs
- **ACES 1.x**: SDR-biased RRT limited to 48 nits reference
- **ACES 2.0**: HDR-aware rendering with proper highlight handling

## Practice: ACES Implementation

### Input Device Transform (IDT) Selection

**Manufacturer-Specific IDTs:**

| Camera | Recommended IDT | File Format | Notes |
|--------|----------------|-------------|-------|
| ARRI Alexa | ARRI IDT v1 | .ctl | Apply LogC4 → ACES for Mini LF, ALEV 4 |
| RED | RED IDT (IPP2) | .ctl | Use REDcolor4/REDgamut4 RWG → ACES |
| Sony VENICE | Sony IDT v2 | .ctl | Apply S-Log3/S-Gamut3.Cine → ACES |
| Blackmagic | BRAW IDT | .ctl | Use Film Gen5 for color science v4 |
| Panasonic | Panasonic IDT | .ctl | Apply V-Log/V-Gamut → ACES |

**IDT Application Methods:**

1. **In-Camera Metadata**: Modern cameras embed ACES IDT metadata in clips
   ```
   Resolve: Color Space → ACES → IDT: Auto (from clip metadata)
   ```

2. **OCIO Config**: Built-in IDTs in OCIO-ACES config
   ```
   OCIO Display: ACES 1.3 / Studio - ACEScg
   OCIO View: Input Transforms → Camera Manufacturer → Model
   ```

3. **LUT-Based**: Generate IDT LUT from CTL (for non-OCIO apps)
   ```bash
   # Render IDT LUT using CTL
   ctlrender -ctl lib/CTL/ARRI.IDT.cpp \
             -format exr \
             -input camera_logc4.exr \
             -output aces_idt.exr
   ```

### Output Device Transform (ODT) Selection

**SDR ODTs** (48 nits, D65):
- **ODT for ACES 1.0 - Rec.709**: Standard SDR broadcast
- **ODT for ACES 1.0 - Rec.2020**: Wide gamut SDR (rare)
- **ODT for ACES 1.0 - P3-DCI (D60)**: Digital cinema

**HDR ODTs** (ACES 2.0):
- **ODT 1000 nits (PQ, D65)**: HDR10 standard
- **ODT 4000 nits (PQ, D65)**: Dolby Cinema reference
- **ODT 203 nits (HLG, D65)**: HLG broadcast

**3D LUT Output**: Generate ODT LUT for monitoring
```bash
# Resolve: Project Settings → Color Management → ACES
# Generate LUT: Monitor Output Device → Rec.709 ODT 48nit
# Export: 3D LUT 33x33x33, Cube LUT
```


### ACES Workflow Integration

**VFX Pipeline (OpenEXR I/O)**:
```
Plate Shot → IDT → ACES2065-1 → CG Render (ACEScg) → Comp → ACES2065-1 → ODT → Review
```

**Color Grading Pipeline**:
```
RAW → IDT → ACES2065-1 → Grade in ACEScg → Look LMT → ACES2065-1 → ODT → Deliverable
```

**Hybrid SDR/HDR Pipeline**:
```
ACES Master → ODT SDR (Rec.709) → SDR Deliverable
           → ODT HDR (PQ 1000) → HDR Deliverable
           → ODT HDR (PQ 4000) → Cinema Deliverable
```

## Failure Modes: Common ACES Issues

### Wrong IDT Selection

**Symptom**: Color shifts, incorrect saturation, wrong contrast
- Using ARRI IDT on RED footage → magenta/green color bias
- Using Sony S-Log3 IDT on LogC footage → crushed blacks

**Root Cause**: Mismatch between camera log encoding and IDT expectations

**Solution**:
1. Verify camera metadata for correct transform
2. Test IDT with grayscale chart (should be neutral)
3. Use manufacturer IDT calculator for custom settings

**Prevention**:
- Create "IDT preset" per camera in project
- Document camera settings in shot log
- Use OCIO config with enforced IDT per camera type

### AP0 vs AP1 Confusion

**Symptom**: Color differences between ACES2065-1 and ACEScg, clipping issues

**Common Mistakes**:
1. Grading directly in ACES2065-1 (AP0) → negative RGB values → color shifts
2. Exporting ACEScg (AP1) as archival master → gamut loss
3. Using AP1 primaries for EXR interchange → color space mismatch

**Color Volume Differences**:
- AP0 gamut is 17% larger than AP1
- AP1 excludes some extreme spectral colors (rare in practice)
- Converting AP1 → AP0 → AP1 causes precision loss

**Best Practice**:
- **Working**: Always grade in ACEScg (AP1)
- **Interchange**: Use ACES2065-1 (AP0) for EXR I/O
- **Archival**: Store in ACES2065-1 (AP0) only

**OCIO Config Enforcement**:
```python
# roles section in config.ocio
roles:
  color_picking: ACES - ACEScg
  color_timing: ACES - ACEScg
  rendering: ACES - ACEScg
  scene_linear: ACES - ACES2065-1  # Interchange only
```

### Legacy RRT Issues

**Symptom**: Highlight desaturation, limited HDR range, "flat" appearance

**Legacy ACES 1.x RRT Problems**:
- Fixed highlight rolloff (not adjustable)
- 48-nit limit baked into transform
- "Academy look" forced on all content (desaturated highlights)
- No HDR support (post-factum HDR ODTs are kludges)

**ACES 2.0 Solutions**:
1. **Bypass RRT**: Use `RRT.a1.0.0 - Original` (legacy) vs `RRT.a1.0.3` (ACES 2.0)
2. **Custom LMT**: Apply creative look before RRT
3. **HDR ODTs**: Use native ACES 2.0 HDR ODTs (no SDR RRT kludge)

**Migration Path**:
```
Old: IDT → ACES → RRT (fixed) → ODT
New: IDT → ACES → LMT (custom look) → ACESrender (flexible) → ODT
```

### Transform Version Conflicts

**Symptom**: Color changes between software versions, inconsistent looks

**Common Issues**:
- Mixing ACES 1.0 and ACES 2.0 transforms in same pipeline
- Using old IDT (v1) with new ODT (v2)
- OCIO config outdated vs. installed software

**Solution**:
1. **Version Control**: Tag OCIO config in Git per project
2. **Transform Locking**: Bake IDT/ODT versions into shot metadata
3. **Testing**: Render test frames with each config version

**OCIO Config Versioning**:
```yaml
# config.ocio header
ocio_config_version: 2.0
description: "Project X ACES Config - v2.0.1 (2024-06)"
environment: {OCIO: "$(OCIO)"}

# version history
strictparse: true
```

## Mini Glossary: ACES Terminology

- **ACES**: Academy Color Encoding System. Industry-standard color architecture developed by AMPAS (Academy of Motion Picture Arts and Sciences) for device-independent color management.

- **AP0 (ACES Primaries 0)**: Original ACES2065-1 color primaries defined by spectral integration. Largest practical color gamut, used for archival interchange and reference.

- **AP1 (ACES Primaries 1)**: Optimized color primaries for ACEScg working space. Smaller than AP0 but larger than P3, designed for grading efficiency and GPU operations.

- **ACES2065-1**: Scene-linear color encoding using AP0 primaries. Half-float EXR format with 16-bit precision. Archival master format and interchange standard.

- **ACEScg**: Working color space (AP1 primaries, linear gamma). Used for color grading, VFX rendering, and compositing. Default in OCIO-ACES config.

- **ACES 2.0**: Next-generation ACES architecture (released 2024) with flexible rendering pipeline, native HDR support, and improved highlight handling. Replaces fixed RRT+ODT workflow.

- **IDT (Input Device Transform)**: Converts camera-native colorimetry (LogC, S-Log3, etc.) to ACES2065-1 scene linear. Manufacturer-provided CTL transforms.

- **ODT (Output Device Transform)**: Maps ACES2065-1 to display colorimetry (Rec.709, P3, HDR10). Includes tone mapping and gamut mapping.

- **RRT (Reference Rendering Transform)**: Scene-to-display rendering transform. In ACES 1.x, fixed "Academy look" with highlight desaturation. In ACES 2.0, flexible rendering pipeline (ACESrender).

- **LMT (Look Modification Transform)**: Creative look transform applied between ACES working space and ODT. Replaces CDL/grade in modern ACES 2.0 workflow.

- **CTL (Color Transform Language)**: ACES transform language (similar to C). Used for IDT/ODT/LMT definitions.

- **OCIO-ACES**: OpenColorIO configuration for ACES transforms. Provides standardized color space definitions and roles for ACES workflow.

- **ACEScentral**: Academy's online resource for ACES documentation, transforms, and tools: https://acescentral.com
