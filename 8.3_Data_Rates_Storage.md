# 8.3 Data Rates and Storage

## Theory

### Data Rate Calculations

[Data rate] (or bitrate) is the amount of data used per second of video, measured in megabits per second (Mbps) or megabytes per second (MB/s):

**Uncompressed Video Calculation:**

```
Data Rate (Mbps) = Horizontal Res × Vertical Res × Frame Rate × Bit Depth × Color Channels

Example: 1080p/24/10-bit/4:2:2
Data Rate = 1920 × 1080 × 24 × 10 × 2.5 (for 4:2:2)
         = 1,244,160,000 bits per second
         = 1,244 Mbps ≈ 155 MB/s
```

**Chroma Subsampling Impact:**
- 4:4:4: Full data rate (all color information)
- 4:2:2: ~67% of full rate (horizontal subsampling)
- 4:2:0: ~50% of full rate (horizontal and vertical subsampling)

**Compression Impact:**
- RAW codecs: Variable compression (3:1 to 18:1)
- Intermediate codecs: Fixed compression ratios (5:1 to 10:1)
- Distribution codecs: Variable compression (20:1 to 200:1)

### Storage Requirements

[Storage] capacity needs depend on data rate and recording time:

**Basic Formula:**
```
Storage (GB) = Data Rate (Mbps) × Recording Time (seconds) ÷ 8 (bits to bytes)
```

**Practical Example:**
- 1 hour of ProRes 422 (147 Mbps):
  - Storage = 147 × 3600 ÷ 8 = 66,150 MB ≈ 66 GB

**With Overhead:**
- Always add 15-20% for file system overhead, metadata, and safety margin
- Actual storage needed = Calculated storage × 1.2

**Multiple Copies:**
- Follow 3-2-1 rule: 3 copies, 2 different media types, 1 off-site
- Minimum storage requirement × 3 for basic redundancy
- Enterprise productions may use more copies

### Bandwidth Requirements

[Bandwidth] refers to data transfer speed required for operations:

**Real-Time Playback:**
- Storage must sustain data rate for smooth playback
- ProRes 422 HQ (220 Mbps) ≈ 27.5 MB/s sustained read speed
- 4K ProRes 422 requires ~110 MB/s sustained speed

**Offloading Speed:**
- Faster offload = faster turnaround
- Minimum: 2× real-time speed
- Recommended: 4-6× real-time speed
- Example: 1 hour of footage should offload in 10-15 minutes

**Network Transfer:**
- 1GbE network: ~125 MB/s theoretical, ~100 MB/s practical
- 10GbE network: ~1.25 GB/s theoretical, ~1 GB/s practical
- SSD direct attach: 500 MB/s to 7 GB/s (NVMe)

## Practice

### Storage Planning

**Pre-Production Planning Steps:**

1. **Calculate Daily Footage**
   - Estimate shooting ratio (3:1 to 10:1 typical)
   - Example: 4 pages of script = ~4 minutes of footage
   - At 5:1 ratio = 20 minutes of footage per day
   - Add coverage, takes, B-roll = ~1 hour total

2. **Calculate Storage per Day**
   - ProRes 422: 66 GB per hour × 1 hour = 66 GB/day
   - 4K ProRes 422: ~250 GB per hour × 1 hour = 250 GB/day
   - RAW formats: 500 GB to 1 TB per hour

3. **Plan Total Storage**
   - Multi-day shoot: Daily storage × number of days
   - Add 30% buffer for unexpected coverage
   - Multiply by 3 for 3-2-1 backup rule

4. **Choose Storage Media**
   - On-set: Fast SSDs for active footage
   - Near-set: RAID arrays for backup and processing
   - Off-site: HDDs or LTO for archival
   - Cloud: Optional for remote backup

### Card Selection

**Camera Media Considerations:**

*CFexpress Type A:*
- Sony cameras (FX3, FX6)
- Up to 900 MB/s read speed
- Expensive but fast
- Good for high-bitrate 4K

*CFexpress Type B:*
- Canon, Nikon, RED
- Up to 1,700 MB/s read speed
- More common than Type A
- Good for 6K+ and high frame rates

*SDXC UHS-II:*
- Widely supported
- Up to 300 MB/s read speed
- More affordable
- Sufficient for most 4K formats

*XQD:*
- Older standard, being phased out
- Similar performance to CFexpress B
- Still used by some cameras

*SSD via USB-C:*
- Increasingly common (Ninja V, external recording)
- Fast, affordable, reusable
- Good for ProRes RAW recording

**Card Capacity Planning:**
- Minimum: 2-3 hours of recording per card
- Consider data offload time between cards
- More smaller cards vs fewer larger cards
- Cost vs convenience trade-off

### Backup Strategies

**3-2-1 Backup Rule:**
- **3 copies** of all footage
- **2 different types** of media (SSD + HDD, or Local + Cloud)
- **1 off-site** copy (different physical location)

**On-Set Backup Workflow:**

```
Camera Card
     ↓
  Primary Backup (SSD RAID, checksum verified)
     ↓
  Secondary Backup (HDD, checksum verified)
     ↓
    Tertiary Backup (off-site or cloud)
```

**Checksum Verification:**
- Critical for data integrity
- MD5, xxHash, or SHA-256
- Verify after every copy
- Software: Silverstack, Hedge, ShotPut Pro

**Offload Best Practices:**
- Never erase camera card until backup verified
- Use multiple verification methods
- Maintain offload logs
- Test restore procedures periodically
- Keep cards until project complete

### Media Management

**Organization Strategies:**

*Directory Structure:*
```
Project_Name/
├── 2024-01-15_Day01/
│   ├── Camera_A/
│   │   ├── A001_012345_R2B.mov
│   │   └── A001_012346_R2B.mov
│   ├── Camera_B/
│   └── Audio/
├── 2024-01-16_Day02/
└── Documentation/
```

*Naming Conventions:*
- Include date, camera, scene, take
- Example: Project_YYYY-MM-DD_CameraID_Scene_Take
- Be consistent throughout production
- Avoid special characters

**Metadata Preservation:**
- Keep original camera metadata intact
- Don't re-wrap unless necessary
- Preserve sidecar files (.XML, .MXF)
- Document any metadata transformations

## Failure Modes

### Insufficient Storage

**Symptoms:**
- Run out of storage during shooting
- Cannot back up footage
- Forced to delete footage to make space
- Production delays or lost takes

**Causes:**
- Underestimated shooting ratio
- Didn't account for multiple cameras
- Wrong codec/file size calculations
- Inadequate backup planning

**Mitigation:**
- Calculate storage with 50% buffer
- Have backup storage ready
- Monitor usage throughout shoot day
- Plan for card offload and turnover
- Keep emergency spare storage available

### Data Loss

**Symptoms:**
- Files corrupted or unreadable
- Accidentally deleted footage
- Drive failure
- Lost or damaged media

**Causes:**
- Drive failure (HDD more prone than SSD)
- Human error (accidental deletion)
- Power loss during write
- Physical damage (drops, liquids)

**Mitigation:**
- 3-2-1 backup rule (non-negotiable)
- Checksum verification on all copies
- RAID for redundancy (RAID 5/6)
- Regular drive health monitoring
- Professional data recovery service contact
- Test restore procedures before critical work

### Backup Failures

**Symptoms:**
- Backup copy doesn't match source
- Checksum mismatch
- Incomplete copy
- Silent data corruption

**Causes:**
- Bad cables or connections
- Software errors
- Drive errors during copy
- Insufficient verification

**Mitigation:**
- Use professional offload software
- Verify with checksums every time
- Test backup copies periodically
- Maintain backup logs
- Use different cables/ports for primary/secondary
- Never skip verification step

## Mini Glossary

- **[Data rate]**: Amount of data used per second of video, typically measured in megabits per second (Mbps) or megabytes per second (MB/s).

- **[Storage]**: Physical media for retaining video data, includes SSDs, HDDs, camera cards, and archival systems.

- **[Bandwidth]**: Data transfer speed required for video operations (playback, offload, transfer), measured in MB/s or GB/s.

- **[Backup]**: Duplicate copy of data for redundancy in case of primary storage failure, critical following 3-2-1 rule.

- **[Redundancy]**: Duplication of critical systems or data to prevent single points of failure, essential for professional workflows.

- **[Media management]**: Systematic organization, naming, and tracking of video assets throughout production and post-production.

- **[Checksum]**: Mathematical verification of data integrity, ensures file copied exactly without corruption or errors.

- **[Shooting ratio]**: Ratio of footage shot to footage used in final cut, typically 3:1 to 10:1 for scripted, 50:1+ for documentary.

- **[Offload]**: Process of copying data from camera media to backup storage, includes verification and organization steps.

- **[RAID]**: Redundant Array of Independent Disks, combining multiple drives for performance, capacity, or redundancy (RAID 0, 1, 5, 6, 10).
