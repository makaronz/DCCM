# 2.3 RED Cameras (V-RAPTOR [X], KOMODO)

## Theory: RED Color Science

### IPP2 Architecture

**IPP2** [Image Processing Pipeline 2: RED's standardized color science architecture introduced in 2017 replacing the original pipeline] provides consistent behavior across all RED cameras.

**IPP2 goals**:
1. **Consistency**: Same color response across all RED cameras (DSMC2, V-RAPTOR, KOMODO)
2. **Accuracy**: Improved color fidelity vs original pipeline
3. **Flexibility**: Better highlight handling and shadow detail
4. **Workflow**: Simplified grading with standardized transforms

**IPP2 components**:
1. **Color space**: REDWideGamutRGB (native gamut)
2. **Gamma curve**: Log3G10 (logarithmic encoding)
3. **Tone mapping**: Highlight roll-off and shadow preservation
4. **Color matrix**: Transform to working space (Rec.709, P3, Rec.2020)

**IPP2 vs original pipeline** (pre-2017):
- **Better highlight handling**: Less color crosstalk at clip point
- **Improved shadow saturation**: No green shift in deep shadows
- **Consistent skin tones**: Across all RED cameras
- **Simpler workflow**: Single IDT for all cameras

**Critical**: Use IPP2 for all new projects. Original pipeline (Legacy) deprecated and no longer supported.

### REDWideGamutRGB

**REDWideGamutRGB** [RED's native color space, larger than Rec.2020, designed for maximum color capture with IPP2 workflow]:

**Primary chromaticities** (approximate, exact values proprietary):
- Red: (0.780, 0.220) - beyond Rec.2020
- Green: (0.210, 0.840) - beyond Rec.2020
- Blue: (0.110, -0.020) - beyond Rec.2020
- White: D65 (0.3127, 0.3290)

**Gamut coverage**:
- vs DCI-P3: ~115%
- vs Rec.2020: ~105%
- vs Pointer's gamut: ~100% of real surface colors

**Colorimetry**:
- Optimized for maximum color capture
- Requires tone mapping for deliverable gamuts
- Consistent across all RED cameras (DSMC2, V-RAPTOR, KOMODO)
- Compatible with ACES via IDT

### RED Log3G10

**Log3G10** [RED Logarithmic encoding with Gain parameter of 10, optimized for IPP2 workflow with 16+ stop dynamic range]:

$$
V = 255 \cdot \log_{10}(10^{(4.086 \cdot L + 1.0)} - 1) + 765
$$

**Key characteristics**:
- Base 10 logarithm
- G10 parameter = gain of 10 in formula
- Normalized linear $L=0.0$ maps to CV 128/1023
- 18% gray maps to CV 486/1023
- 100% reflectance maps to CV 681/1023
- Clip point depends on dynamic range setting

**Comparison to LogC4 and S-Log3**:
- **LogC4**: 18% gray at CV 599 (brightest)
- **S-Log3**: 18% gray at CV 388 (darkest)
- **RED Log3G10**: 18% gray at CV 486 (middle)
- **Implication**: Different exposure strategies required

**Dynamic range** (V-RAPTOR [X]):
- Claimed: 17+ stops
- Measured: ~16 stops (independent testing)
- Configurable: 13-17 stops via clip guides
- Trade-off: Highlight headroom vs shadow noise

### REDCODE RAW

**REDCODE RAW** [RED's proprietary compressed RAW format using wavelet compression with user-selectable compression ratios] introduced with RED ONE (2007) and enhanced in DSMC2/V-RAPTOR.

**Compression ratios**:
- **3:1**: Very low compression, near-lossless
- **5:1**: Low compression, high quality
- **8:1**: Medium compression, balanced quality/size
- **12:1**: High compression, longer record times
- **18:1+:** Maximum compression (not recommended)

**Bit depth**:
- 16-bit linear data (always)
- Preserves maximum color information
- Better grading flexibility than 12-bit ProRes

**Quality comparison**:
- **3:1-5:1**: Visually indistinguishable from uncompressed
- **8:1**: Acceptable for most productions
- **12:1+**: Compression artifacts possible in high-detail areas

**File size** (8K VV, 24fps):
- 3:1: ~1.2 TB/hour
- 5:1: ~800 GB/hour
- 8:1: ~500 GB/hour
- 12:1: ~350 GB/hour

**REDCODE vs X-OCN**:
- Similar wavelet compression algorithms
- Similar quality at similar ratios
- Different metadata structures (vendor-specific)

## Practice: REDcolor Selection, Gamma Workflows, Metadata Management

### REDcolor Selection

**REDcolor** [RED's color science versions evolving from original pipeline to IPP2, with multiple IPP2 variations available]:

**IPP2 REDcolor options** (2024):
- **REDcolor FW 4.0+**: Latest IPP2 color science (recommended)
- **REDcolor v3**: Earlier IPP2 version (deprecated)
- **REDcolor v2**: Original pipeline (deprecated, use only for legacy projects)

**Recommended**: Always use latest REDcolor FW 4.0+ for new projects.

**REDcolor FW 4.0+ features**:
- Improved skin tone accuracy
- Better highlight handling
- Enhanced shadow saturation
- Consistent across all RED cameras

**Backward compatibility**:
- Old footage (pre-2017) requires original pipeline
- New footage should use IPP2 REDcolor FW 4.0+
- Don't mix color science versions in same project

### Gamma Curve Selection

**Gamma options** in IPP2:
- **RED Log3G10**: Recommended for grading (scene-referred)
- **RedGamma**: Display-referred (not recommended for RAW workflow)
- **Hybrid Log-Gamma**: HLG broadcast (specific use case)

**RED Log3G10 workflow**:
1. **Shoot**: Record REDCODE RAW with RED Log3G10
2. **Edit**: Use Log3G10 monitoring LUT for editing
3. **Grade**: Apply RED Log3G10 IDT first
4. **Deliver**: Apply output transform (Rec.709, P3, HDR)

**Exposure targeting** (RED Log3G10):
- 18% gray at CV 486/1023
- Waveform monitor: 45-48% IRE with Log3G10 LUT
- Skin tones at CV 550-600
- Clip point: CV 1023 (17 stops above black)

### Metadata Management

**RED metadata** [camera settings embedded in R3D files used for RAW decoding and color management]:

**Critical metadata**:
- **ISO**: Sensor gain (affects noise floor)
- **Kelvin**: White balance color temperature
- **Tint**: White balance green-magenta offset
- **REDcode**: Color science version (IPP2 vs legacy)
- **Gamma**: Log curve (Log3G10 vs RedGamma)
- **Color Space**: Native gamut (REDWideGamutRGB)
- **Clip**: Unique identifier for each shot

**Metadata preservation**:
- Always preserved in R3D files
- Lost if transcoded to non-RAW format
- Required for accurate RAW decoding

**Common metadata loss scenarios**:
1. **Transcoding**: Wrong settings strip metadata
2. **XML export**: Incorrect export settings
3. **Archiving**: Sidecar files separated from R3D media
4. **CDN transfer**: RMD files not uploaded

**Best practices**:
- Archive R3D files with metadata intact
- Keep RMD (RED Metadata) files with media
- Test transcoding workflow before production
- Use REDCINE-X PRO for metadata verification

### Komodo Link Workflow

**Komodo Link** [proprietary control protocol for KOMODO camera via USB-C, allowing remote camera control and monitoring]:

**Features**:
- Camera control (exposure, white balance, recording)
- Monitoring (live view, waveforms, false color)
- Media management (clip naming, metadata)
- Firmware updates

**Workflow**:
1. Connect KOMODO to computer via USB-C
2. Open REDCINE-X PRO or Komodo Link app
3. Control camera remotely
4. Monitor exposure with tools

**Use cases**:
- Gimbal operation (remote control)
- Tight spaces (physical access limited)
- Multi-camera setups (centralized control)

**V-RAPTOR [X] control**:
- Similar control via ethernet
- RED Control app (iOS/Android)
- Third-party control (FoMa, Pocket Control)

## Failure Modes

### Old REDcolor vs IPP2 Issues

**Symptom**:
- Inconsistent color across different RED cameras
- Skin tones look wrong (too magenta or too green)
- Color grading produces unexpected shifts

**Root cause**:
- Mixing original REDcolor (v2) with IPP2 REDcolor (v3, FW 4.0+)
- Wrong IDT applied in post
- Legacy footage graded with new pipeline (or vice versa)

**Detection**:
- Check metadata: "REDcolor v2" vs "REDcolor v3" vs "REDcolor FW 4.0+"
- Visual inspection: Skin tones look wrong
- Color vectorscope shows saturation mismatch

**Solution**:
1. Use correct IDT for color science version
2. Re-grade if mixed pipelines (painful, avoid)
3. Document color science version in camera report
4. Test workflow before principal photography

**Prevention**:
- Use IPP2 REDcolor FW 4.0+ for all new projects
- Document color science version in camera report
- Test grading workflow before shoot
- Avoid mixing color science versions in same project

### Clip vs Compressed RAW

**Symptom**:
- Highlight detail abruptly lost (hard clip)
- Color crosstalk at clip point
- Banding in highlight gradients

**Root cause**:
- Exposure exceeded sensor's dynamic range
- Wrong compression ratio (too high)
- Incorrect "dynamic range" setting in camera

**Detection**:
- False color shows uniform color at highlights (clipping)
- Waveform monitor shows flat line at top
- Histogram shows pile-up at right edge

**Solution**:
1. Reduce exposure (protect highlights)
2. Use lower compression ratio (3:1-5:1)
3. Enable "highlight preservation" features
4. Re-shoot if critical (not always possible)

**Prevention**:
- Expose for highlights (ETTR)
- Use false color to verify exposure
- Test compression ratios before shoot
- Use 3:1-5:1 for critical footage

**Compressed RAW** (REDCODE 5:1-8:1):
- **Soft clip**: Highlight detail preserved with reduced contrast
- Smooth roll-off at highlight boundary
- Recovery possible through contrast adjustment
- Recommended for most productions

**Clipped RAW** (overexposed):
- **Hard clip**: All highlight detail lost
- Abrupt transition at clip point
- Recovery impossible
- Avoid through proper exposure

## Best Practices (2024-2025)

### Exposure Strategy

1. **RED Log3G10 middle gray**:
   - 18% gray at CV 486/1023
   - Waveform monitor: 45-48% IRE with Log3G10 LUT
   - Skin tones at CV 550-600

2. **ISO selection**:
   - ISO 800 for most situations (optimal SNR)
   - ISO 400 for more highlight headroom
   - ISO 1600-3200 for low-light (more noise)

3. **Highlight protection**:
   - Reserve 2-3 stops above key face
   - Use false color to verify exposure
   - ETTR when possible

4. **Monitoring**:
   - Apply RED Log3G10 to Rec.709 LUT on set
   - Verify with waveform monitor
   - Check skin tones on calibrated display

### Color Management

1. **Scene-referred workflow**:
   - Apply RED Log3G10 IDT first (ACES or RED LUT)
   - Grade in scene-linear or log space
   - Apply display transform last (Rec.709, P3, HDR)

2. **Color space selection**:
   - REDWideGamutRGB for capture (always)
   - Rec.709/P3 for deliverable
   - Rec.2020 for HDR master

3. **Metadata preservation**:
   - Archive R3D files with metadata
   - Keep RMD files with media
   - Test transcoding workflow before production

### Codec Selection

**REDCODE 3:1-5:1** (use for):
- Feature films (high-budget)
- VFX-heavy shots (green screen, CGI)
- Archival projects (future-proofing)
- High-motion or high-detail scenes

**REDCODE 8:1** (use for):
- Television drama
- Documentary with budget constraints
- Most narrative work (balanced quality/size)
- Web series with high quality requirements

**REDCODE 12:1** (use for):
- B-roll footage
- Behind-the-scenes content
- Review copies
- Non-critical shots

**ProRes 4444 XQ** (use for):
- Faster turnaround than REDCODE
- Easier dailies workflow
- Broadcast deliverables
- Commercial work with tight schedules

## Mini Glossary

- **IPP2** [Image Processing Pipeline 2]: RED's standardized color science architecture introduced in 2017, provides consistent behavior across all RED cameras
- **REDCODE RAW**: RED's proprietary compressed RAW format using wavelet compression with user-selectable compression ratios (3:1-18:1)
- **REDcolor** [RED's color science versions]: Multiple versions (v2, v3, FW 4.0+) evolving from original pipeline to IPP2, use FW 4.0+ for new projects
- **REDWideGamutRGB**: RED's native color space, larger than Rec.2020, designed for maximum color capture with IPP2 workflow
- **RED Log3G10**: RED Logarithmic encoding with Gain parameter of 10, optimized for IPP2 workflow with 16+ stop dynamic range
- **Komodo link**: Proprietary control protocol for KOMODO camera via USB-C, allowing remote camera control and monitoring
- **Global shutter**: Sensor design capturing all pixels simultaneously, eliminating rolling shutter skew (V-RAPTOR [X], KOMODO, Monstro, Gemini)
- **Dynamic range**: Ratio between maximum signal and noise floor, RED claims 17+ stops for V-RAPTOR [X] (measured ~16 stops)
- **SNR** [Signal-to-Noise Ratio]: Ratio of signal power to noise power, ~54dB at 18% gray for V-RAPTOR at ISO 800
- **Photosite**: Individual light-sensitive element on sensor, 5.0µm for V-RAPTOR [X], 4.17µm for KOMODO
- **Base ISO**: Sensor's native sensitivity without gain applied, 800 for most RED cameras (configurable 400-3200)
- **VV** [Vista Vision]: Large format sensor size (46mm diagonal), larger than full-frame, same as IMAX digital frame
- **Clip**: Unique identifier for each shot in RED camera system, used for organization and metadata management
- **R3D**: RED's RAW file format containing sensor data before de-Bayering, requires metadata for decoding
- **RMD** [RED Metadata]: XML sidecar files containing camera settings, can be separated from R3D files (caution: metadata loss)
- **DSMC2** [Digital Still and Motion Camera 2nd generation]: RED's previous modular camera body design (2017-2021), succeeded by V-RAPTOR

### RED V-RAPTOR Firmware 2.2 (May 2026)

RED released **V-RAPTOR firmware 2.2** in May 2026, a significant update across the entire V-RAPTOR / XL / [X] platform. This firmware is NOT optional for productions requiring broadcast or live-streaming integration — it enables core features that were previously announced as "coming soon."

| Feature | Description | DIT/Post Impact |
|---------|-------------|-----------------|
| **Faster boot times** | Reduced startup sequence | Critical for live productions where camera must power cycle between segments |
| **Lower power consumption** | Optimized sensor readout and processing | Extends battery life for gimbal/drone work; reduces thermal issues on long takes |
| **Broadcast R3D in RED Connect** | Live streaming integration with R3D proxy | **Critical:** DITs must manage both on-camera recording AND live stream simultaneously |
| **Discrete Phantom Track control** | Separate audio track routing | Enables broadcast audio (mix-minus, comms) on separate tracks without affecting cinema delivery tracks |
| **Timecode-triggered recording** | External timecode starts/stops recording | Enables multi-camera sync from external timecode generator (e.g., Ambient MasterLock) |
| **External tally recording** | Tally signal embedded in metadata | Live switcher tally state recorded per-frame for post reference |
| **Improved ND iris tracking** | Smoother exposure compensation with internal ND | Reduces exposure stepping during iris pulls with ND engaged |
| **SmallHD OS 6.1.2** | Updated monitor operating system | Compatible with new SmallHD focus and false color features |

### V-RAPTOR XE — New Broadcast-Optimized Variant

The **V-RAPTOR XE** launched alongside firmware 2.2 as a dedicated broadcast and live production variant. It is NOT a sensor upgrade — the XE uses the same VV 8K sensor as the standard V-RAPTOR [X] — but adds hardware-level connectivity enhancements:

- **Enhanced ethernet**: 10GbE with SMPTE-2110 output (not just control ethernet)
- **Dual 12G-SDI**: Independent 12G-SDI outputs for program and monitoring feeds
- **GENLOCK**: Hardware genlock input with sub-frame accuracy (previously software-only)
- **Audio expansion**: 4-channel balanced XLR input (vs. 2-channel on standard V-RAPTOR)
- **Redundant recording**: Dual SSD slot recording with automatic failover (previously single-slot on standard V-RAPTOR)

**DIT workflow implications:**
- The V-RAPTOR XE can replace traditional broadcast cameras (Sony HDC, Grass Valley LDX) in live production while maintaining cinematic image quality.
- RED Connect with Broadcast R3D means the DIT must manage two data streams: the full-quality R3D files on the internal SSD AND the lower-bitrate broadcast proxy stream via ethernet.
- The proxy stream is NOT a simple transcode — it is a real-time wavelet-compressed R3D subset (typically 8:1-12:1) that can be decoded by REDCINE-X PRO or Resolve 21 for immediate dailies while the full-quality 3:1-5:1 files are still recording.

### KOMODO and KOMODO-X Firmware Updates (2026)

RED also shipped continuous firmware updates for the KOMODO and KOMODO-X platforms through early 2026:

| Feature | KOMODO | KOMODO-X | Notes |
|---------|--------|----------|-------|
| **On-board LCD user pages** | v1.8.x | v1.3.x | Customizable LCD layouts for different shooting modes |

Mixed firmware versions can cause metadata format differences that complicate dailies generation.
