# 8.1 Overview of Major Codecs

## Theory

### Codec Types and Compression Principles

A [codec] (coder-decoder) is software or hardware that encodes (compresses) and decodes (decompresses) digital video data. Understanding codec types is critical for choosing appropriate formats:

**DCT-Based Codecs (Discrete Cosine Transform):**
- Divide image into 8x8 pixel blocks
- Convert spatial information to frequency data
- Quantize (discard) high-frequency information
- Efficient but can produce blocking artifacts
- Examples: ProRes, DNxHR, H.264, H.265

**Wavelet-Based Codecs:**
- Analyze entire image at multiple scales
- Better preservation of fine detail
- No blocking artifacts
- Computationally more intensive
- Examples: REDCODE RAW, JPEG 2000 (DCP), CineForm

**Uncompressed/RAW:**
- No spatial compression
- Maximum image quality
- Enormous file sizes
- Examples: ARRIRAW, uncompressed 10-bit/12-bit

### Intra-Frame vs Inter-Frame Compression

**Intra-Frame (Spatial Compression):**
- Compresses each frame independently
- Similar to JPEG compression for still images
- Each frame contains complete image information
- Ideal for editing and post-production
- Lower compression efficiency
- Examples: ProRes, DNxHR, CineForm

**Inter-Frame (Temporal Compression):**
- Exploits redundancy between consecutive frames
- Stores only differences from reference frames (I-frames)
- Much higher compression efficiency
- Difficult to edit frame-accurately
- Examples: H.264, H.265, AV1

**GOP Structure (Group of Pictures):**
- I-frame: Complete image, reference point
- P-frame: Predicted from previous I/P frames
- B-frame: Bidirectional prediction (past and future)
- Long GOP: Fewer I-frames, higher compression
- Short GOP/Intra: All I-frames or short GOP, easier to edit

### Compression Trade-offs

**Quality vs File Size:**
- Higher compression = smaller files but potential quality loss
- Visually lossless: Quality loss imperceptible
- Lossy compression: Visible artifacts at high compression
- Lossless compression: No quality loss, larger files

**Performance vs Quality:**
- More complex compression = better quality
- Computational cost increases with complexity
- Encoding time vs decoding efficiency
- Hardware acceleration increasingly important

## Practice

### Codec Selection for Professional Workflows

**Production-Quality Intermediate Codecs:**

*Apple ProRes (2024-2025):*
- **ProRes 422 Proxy**: 45 Mbps (1080p), offline editing, 8-bit
- **ProRes 422 LT**: 102 Mbps (1080p), low-bandwidth online editing
- **ProRes 422**: 147 Mbps (1080p), standard quality, 10-bit 4:2:2
- **ProRes 422 HQ**: 220 Mbps (1080p), high quality, 10-bit 4:2:2
- **ProRes 4444**: 330 Mbps (1080p), 12-bit 4:4:4 with alpha
- **ProRes 4444 XQ**: 500 Mbps (1080p), extreme quality, 12-bit 4:4:4
- **ProRes RAW**: Proprietary RAW, 12-bit, variable compression

*Applications:* Editing, color grading, visual effects, mastering. Industry standard for post-production.

*Avid DNxHR:*
- **DNxHR LB**: Low bandwidth, similar to ProRes 422 Proxy
- **DNxHR SQ**: Standard quality, similar to ProRes 422
- **DNxHR HQ**: High quality, similar to ProRes 422 HQ
- **DNxHR HQX**: 10/12-bit, similar to ProRes 422 HQ
- **DNxHR 444**: 4:4:4 chroma, similar to ProRes 4444

*Applications:* Media Composer workflows, Avid ecosystems, cross-platform compatibility.

**Camera Codecs:**

*Sony XAVC (H.264-based):*
- **XAVC-I**: Intra-frame, 10-bit 4:2:2, high quality
- **XAVC-L**: Long GOP, 10-bit 4:2:0, smaller files
- **XAVC-S**: Consumer version, MP4 wrapper
- **XAVC-S-I**: Intra-frame consumer format

*Applications:* Sony camera ecosystems (Venice, FX series, Alpha cameras)

*REDCODE RAW:*
- Wavelet compression, variable compression ratios
- 3:1 to 18:1 compression options
- 16-bit depth, up to 8K resolution
- R3D container format

*Applications:* RED cameras (Komodo, V-Raptor, Ranger), high-end cinema

*ARRIRAW:*
- Uncompressed or lightly compressed
- 12-bit or 16-bit depth
- Up to 4.5K resolution
- ARRIRAW codec in .ari container

*Applications:* ARRI Alexa cameras, premium cinema production

**Distribution Codecs:**

*H.264/AVC:*
- Ubiquitous compatibility
- 8-bit typically, supports 10-bit
- 4:2:0 chroma subsampling
- Highly efficient compression
- Long GOP structure

*Applications:* Web video, Blu-ray, broadcast, mobile delivery

*H.265/HEVC:*
- Successor to H.264
- Significantly better compression efficiency
- Supports 8K resolution
- 10-bit and 12-bit support
- More computationally expensive

*Applications:* 4K/8K streaming, HDR content, modern delivery platforms

*AV1:*
- Open-source, royalty-free
- Similar efficiency to H.265
- Growing adoption
- Hardware decode support increasing

*Applications:* Future-proofing web delivery, Netflix/YouTube premium tiers

### Quality vs File Size Considerations

**Bitrate Comparison (1080p/24fps):**
- Uncompressed 10-bit 4:2:2: ~995 Mbps
- ProRes 422: 147 Mbps (6.8:1 compression)
- ProRes 422 HQ: 220 Mbps (4.5:1 compression)
- H.264 (high quality): 10-50 Mbps (20:1 to 100:1 compression)
- H.265 (high quality): 5-25 Mbps (40:1 to 200:1 compression)

**Practical Selection Guide:**

| Use Case | Recommended Codec | Rationale |
|----------|------------------|-----------|
| Offline editing | ProRes 422 Proxy, DNxHR LB | Small files, fast performance |
| Online editing | ProRes 422, DNxHR SQ | Good quality, reasonable size |
| Color grading | ProRes 422 HQ, DNxHR HQX | High quality, headroom for grading |
| VFX work | ProRes 4444, DNxHR 444 | Maximum quality, alpha support |
| Camera master | Camera RAW or high-quality Log | Maximum flexibility |
| Web delivery | H.265, AV1 | Best quality at low bitrates |
| Broadcast | H.264, H.265 | Industry standard compatibility |
| Cinema DCP | JPEG 2000 | DCI specification |

## Failure Modes

### Wrong Codec Choice

**Symptoms:**
- Insufficient quality for intended use
- Excessive file sizes for practical workflows
- Performance issues (slow editing/rendering)
- Compatibility problems with post-production tools

**Examples:**
- Using H.264 Long GOP for editing (slow, frame accuracy issues)
- Using ProRes 4444 for simple offline editing (wasted storage)
- Using 8-bit codec for HDR grading (banding, limited dynamic range)
- Using uncompressed when compressed codec would suffice (storage waste)

**Mitigation:**
- Consider entire workflow before choosing codec
- Test codec performance with your hardware/software
- Balance quality needs with practical constraints
- Plan delivery format requirements from start
- Keep camera masters (RAW/Log) separate from editing proxies

### Quality Loss

**Symptoms:**
- Visible compression artifacts (blocking, banding)
- Color fringing around edges
- Loss of fine detail in textures
- Poor performance in color grading

**Causes:**
- Excessive compression ratio
- Wrong codec for content type (high detail, motion)
- Multiple generations of compression
- 8-bit codecs for HDR or extensive grading

**Mitigation:**
- Use higher quality codec for critical work
- Avoid re-compression when possible
- Use appropriate codec for content (high motion needs higher bitrate)
- Test compression with worst-case footage
- Maintain camera masters at highest quality

### Compatibility Issues

**Symptoms:**
- Codec won't play on target system
- Software doesn't recognize codec
- Hardware can't decode in real-time
- Color space or metadata issues

**Causes:**
- Proprietary codec (R3D, ARRIRAW) without proper software
- Old software without modern codec support
- Hardware without hardware acceleration
- Codec wrapper/container mismatch

**Mitigation:**
- Check codec compatibility before starting project
- Use widely-supported codecs for collaboration
- Keep software up to date
- Have transcode options available
- Test delivery format on target platforms

## Mini Glossary

- **[Codec]** (coder-decoder): Software or hardware component that encodes (compresses) and decodes (decompresses) digital video data.

- **[DCT]** (Discrete Cosine Transform): Compression technique dividing images into frequency components, basis for JPEG and many video codecs.

- **[Wavelet]**: Compression technique analyzing images at multiple scales, preserves fine detail better than DCT, used in REDCODE and JPEG 2000.

- **[ProRes]**: Apple family of high-quality intermediate codecs using DCT compression, industry standard for post-production.

- **[DNxHR]**: Avid family of high-quality intermediate codecs, similar to ProRes, optimized for Media Composer workflows.

- **[H.265]**: High Efficiency Video Coding (HEVC), successor to H.264, significantly better compression efficiency, computationally expensive.

- **[AV1]**: Open-source, royalty-free codec with efficiency comparable to H.265, developed by Alliance for Open Media.

- **[Intra-frame]**: Compression method compressing each video frame independently, ideal for editing and post-production.

- **[Inter-frame]**: Compression method exploiting temporal redundancy between frames, more efficient but difficult to edit frame-accurately.

- **[GOP]**: Group of Pictures, structure of I-frames (complete), P-frames (predicted), and B-frames (bidirectional) in inter-frame compression.
